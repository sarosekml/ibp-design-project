## Назначение
Темы из JSON в tokens/. IBP Legacy совпадает с текущей ДС и не ставит data-theme;
IBP Neo строится из Brand #18A59E / Neutral #617179; Custom — сиреневая, её
тёмный профиль сохраняет прежнюю service. Service остаётся хромом панели.

## Инварианты
- Без выбранной темы нет data-theme и новых правил: текущие экраны сохраняются.
- Legacy и Neo не перезаписываются; конструктор сохраняет Custom или новую тему.
- Статусы и графики фиксированы; акцентные статусы следуют за Brand.
- Несохранённое существует только в памяти страницы; IndexedDB хранит handle папки.
- Имя старого токена меняется через роль; карта содержит все 119 имён.
- Основная кнопка — ровно brand 500 в обеих темах; наведение и нажатие — ступени 600 и 700 той же рампы. Заливку ради контраста не затемняем: текст на заливке — «белый / тёмный», провал виден в «Все цвета → Контраст» (решение человека 07.10.2026).
- Опорная ступень (`brandStep` / `neutralStep`, по умолчанию 500) — ровно заданный цвет; правка любой ступени в конструкторе сдвигает за ней всю растяжку. «Только эта ступень» — точечная правка.

## Ключевые правила (из разделов страницы)
- **Использование** — выбор в конструкторе и панели прототипа; плавающего окна нет. Страница — инструмент по образцу coolors.co/tailwind: шапка с темой и сохранением → палитра → 18 живых примеров на компонентах ДС; управление — в закреплённой нижней панели (полосы Brand и Neutral, «Настроить», отмена/повтор, «Сгенерировать», «Все цвета», «Экспорт»). Вкладка «Документация» — устройство тем.
- **Анатомия** — JSON: name, label, locked; light/dark: brand, neutral, brandStep, neutralStep, adjust, overrides, onFill.
- **Слои токенов** — палитра `--ramp-*` → токены темы (роли `--color-*`, назначение цвета) → токены UI-kit (119 имён, которые пишут компоненты; в новых темах — `var(роль)`) → токены компонентов (`--tip-bg`, в CSS компонента). Тема меняет первые два слоя.
- **Варианты** — Light/Dark, у Legacy только Light; aliases ibp-light/ibp-dark → Neo.
- **Размеры** — 19 × 11 рамп, 160 ролей, 119 имён. Тема не меняет геометрию компонентов.
- **Контент** — Brand и Neutral в #RRGGBB; имена файлов — латиница, цифры, дефис.
- **Поведение** — OKLCH, уменьшение хромы в sRGB, генерация восьмью методами (случайный только тон; светлота и насыщенность — как у ступени 500 IBP Legacy: brand #00AA9B, neutral #617C7C), история (шаг — законченная правка), ручные отклонения, файловое сохранение. Пробел генерирует только при нейтральном фокусе; ⌘Z / ⇧⌘Z — история. Смешанная роль (color-mix) правится по базовому цвету, доля сохраняется.
- **Состояния** — базовая, сохранена, не сохранено, ошибка записи; предупреждение beforeunload.
- **Доступность** — метки контролов, Slider и ColorPicker с клавиатурой, текстовое обозначение контраста и ручных правок.
- **Типографика** — шрифты ДС сохраняются.
- **Цвета** — 17 тонов базы; светлая из Colors.css (grey = mgrey, 950 = 900), тёмная из прежней ibp-dark. Генерируются только Brand/Neutral; обязательные пары текста корректируются сдвигом цвета текста, заливка brand — никогда; ручные отклонения остаются видимыми. Тёмная: ступень 500 = вход, края шкалы (50 и 950) фиксированы.

## Для разработчиков (выжимка)

### Источники и сборка
Ramp.tokens.js — математические преобразования. ThemeEngine.js — общий компилятор
для Node и браузера. Themes.tokens.js — роли, профили, карта, точечные правила
(источник, правится руками, читает Node); Themes.runtime.js — его генерат для
браузера: без правил страниц, «не перекрашивается» и сборочных пометок, из точечных
правил — только токены `:root` (68 КБ вместо 229 КБ, review-2 Р8); tokens/*.json — файлы тем и базы; tokens.data.js — зеркало для file://.
`node design-system/tools/theme-build.mjs` собирает CSS, рантайм-данные и зеркало. `--check`
сверяет JSON, 119 legacy-имён, базу, контраст, монотонность и генераты; `--selftest`
проверяет алгоритм и падающие мутации. Исторические исключения статусов,
service и соответствующего custom-dark выводятся как INFO, не скрываются.

### Статический CSS и CSS на лету
Источник истины — один компилятор `ThemeEngine.js`. `theme-build` пишет его
вывод в `Themes.css` (блоки файловых тем — запасной путь для страниц без JS)
и в зеркало `tokens.data.js`; `ThemeBoot.js` в `<head>` компилирует выбранную
тему из того же зеркала тем же кодом и ставит её `<style>` до первой отрисовки.
Поэтому в браузере действует CSS на лету, а `--check` стережёт, что зеркало и
`Themes.css` собраны из текущих JSON: расхождение одного с другим — дефект
сборки (решение review-2, Р9, 08.10.2026). Скрипты тем грузит только ThemeBoot;
`ds.js` второй раз их не подключает (Р8). Компилятор и данные нужны и в IBP
Legacy: панель прототипа строит меню тем из зеркала и переключает тему без
перезагрузки, поэтому ленивую загрузку по выбранной теме не вводили (Р8, п. 3).

### Файловое сохранение
ThemeFiles.js: connect/restore/attach/read/save/download. FSA подключает папку
tokens один раз; в каждом сеансе проверяется разрешение. Запись защищает имена
базовых тем, не перезаписывает существующее имя через Save As, проверяет
конфликт изменений файла и пишет JSON + зеркало. Сбой зеркала откатывает JSON.
Firefox/Safari скачивают JSON; зеркало пересобирается Node-инструментом.
attach(handle) проверяет ту же запись на OPFS во встроенном браузере.

### Список тем — всё, что лежит в папке (1.015, 08.10.2026)
- **Источник списка.** Подключённая папка `tokens` читается при открытии страницы
  (если браузер сохранил разрешение) и по пункту меню темы «Обновить список из
  папки»; без папки — пункт «Подключить папку tokens…». Страница с диска
  (`file://`) содержимое папки без подключения не видит: тогда список — из
  зеркала, а новый файл появится после подключения или `node tools/theme-build.mjs`.
- **Имя темы — имя файла** (`DS_THEME_ENGINE.fromFile`): копия, переименованная
  в Finder, открывается под своим именем, при совпадении названий в меню
  подписано имя файла. Сохранение пишет `name` = имя файла; theme-build о
  расхождении пишет INFO, а не FAIL.
- **Файл с ошибкой** (не JSON, недопустимое имя, неверное значение) не прячет
  остальные: он виден в меню неактивным пунктом, причина — в уведомлении.
- **Зеркало** `tokens.data.js` переписывается, если разошлось с папкой
  (`syncMirror`): тема видна на всех страницах ДС и в панели прототипа.
  Зеркало из папки побайтно совпадает с зеркалом theme-build.
- **Смена входа применяется сразу** во всех темах: правка полосы, ступени,
  «Настроить» и генерация снимают ручные значения ролей, которые строятся от
  растяжки этого тона (IBP Legacy, тёмная Custom), — тема следует за
  растяжкой. Роли статусов и графиков не трогаются; ручная правка роли того же
  тона из «Все цвета» при следующей смене входа тоже снимается.
- **«Сохранить как…»** всегда спрашивает имя и название. Без подключённой папки
  файл скачивается под введённым именем — `name` внутри то же.

### API
```js
DSTheme.get(); // id или legacy
DSTheme.set('custom', 'dark');
DSTheme.set('ibp-dark'); // ibp-neo-dark
DSTheme.list(); // [{id,name,mode,label}]
DSTheme.files(); // [{name,label,locked,modes}]
DSTheme.selection(); // {name,mode,id}
DSTheme.preview(file, 'light'); // только до перезагрузки
DSTheme.reload(data); // после сохранения зеркало
document.addEventListener('ds:themechange', function(e) { /* e.detail.theme/name/mode */ });
```

### Разметка · HTML
```html
<!-- Обычный синхронный тег head; загрузчик приложений ставит его сам. -->
<script src="foundations/Themes/ThemeBoot.js"></script>
<div data-theme="ibp-neo-light">Компоненты ДС</div>
```

### Точечные правила
В rules: файл, селектор, свойство, from и роль. Все правила под data-theme и
низкоспецифичным :where; вложенная legacy возвращает исходные токены. Проверка
селекторов и исходных объявлений сохраняется. Роли --color-*/рампы --ramp-*
живут только в foundations/Themes.
