# Шаблон локального компонента

Заготовка папки локального компонента — тайла, таблицы, модального окна, поповера,
контекстного меню. Правила, по которым она заполняется, — страница ДС «Локальные
компоненты» (`patterns/LocalComponents/LocalComponents.html`). Шаблон один для всех
проектов на этой ДС.

**Шаблон — источник канона.** Заголовки `##` в `Component.md` — набор и порядок разделов
паспорта и вкладки «Документация» страницы компонента. Генератор витрины проекта читает их
отсюда. Меняются они только вместе со страницей правил и её версией (`rulesVersion`).

## Состав

| Файл | Что | Когда нужен |
|---|---|---|
| `Component.md` | паспорт: шапка полей и 13 разделов канона | всегда |
| `Component.html` | фрагмент разметки с одним корнем, без обвязки страницы; в комментарии — корни окна, поповера, подчасти | всегда |
| `Component.css` | внутренняя раскладка; что видно по `data-state` и `data-mode` | когда есть своя раскладка или свои блоки |
| `fixtures.json` | демо-данные конструктора: по состояниям и `long` | когда демо работает на данных |
| `CHANGELOG.md` | журнал: версия, дата, что, почему, требование | всегда |

`<Имя>.js` — только если компоненту нужно поведение, которого нет в рантаймах ДС; заготовки
у него нет. Подчасть со своим паспортом — подпапка с тем же составом.

## Как начать

1. Скопировать папку туда, где проект держит свои компоненты, и назвать именем компонента:
   PascalCase, тип в конце — `DealTeamTile`, `DealTeamModal`. В IBP —
   `apps/<раздел>/<модуль>/widgets/<группа>/<Имя>/`, группы — `tiles`, `tables`, `modals`,
   `context-menus`, `popovers`.
2. Переименовать `Component.*` в `<Имя>.*`, префикс классов `lc-component` — в `lc-<имя>`.
3. Заполнить паспорт `<Имя>.md`: сначала шапку (обязательны `name`, `category`, `purpose`),
   потом разделы — по порядку, ничего не переименовывая. Неизвестное — `не решено
   (ДД.ММ.ГГГГ)`, неприменимое — «Не применимо: …».
4. Собрать разметку из компонентов ДС, корень — по типу. Не хватает элемента — сначала
   завести его в ДС.
5. Вшить компонент в страницу меткой `<ds-include>`: так у страницы витрины появятся данные и
   окна страницы-хозяина.
6. Собрать витрину генератором проекта и прогнать проверки проекта. В IBP —
   `node .agents/tools/kit-build.mjs` и `node .agents/tools/lessons-cli.mjs gate`.
7. Первая запись журнала — создание компонента.

## Версия правил

`rulesVersion` в шапке паспорта — версия страницы правил, по которой компонент заполнен. В
шаблоне стоит текущая. Меняется она только тогда, когда компонент действительно приведён к
новым правилам, — отдельной записью журнала. Компоненты с прежней версией — конечный список
работ, а не обязанность всё помнить.
