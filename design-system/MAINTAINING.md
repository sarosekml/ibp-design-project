# Дизайн-система — правила ведения

## Язык
Отвечать и рассуждать в проекте только на русском.

## Формат ДС (ВАЖНО — отличие от исходного проекта)
Ванильный HTML/CSS без React и без шага сборки — `AGENTS.md` §1 и §4. React-слой не заводится, потому что с файлами напрямую работает любой агент или харнес. Раздел «Для разработчиков» на страницах — framework-agnostic хендофф (redline + псевдокод), а не React-код.

## Жёсткие запреты (НИКОГДА)
Общие запреты ДС — `AGENTS.md` §4: чит-шит и страницы целиком не читать, SVG не инлайнить, значения не выдумывать, на `uploads/` не ссылаться, React-компоненты не писать. Здесь — то, что добавляет к ним ведение ДС.
- Не читать `icons-data.js` (671 KB, одна строка). Имена глифов — `foundations/Icons/Icons.md`. Один SVG и поиск по именам — утилитой `node tools/ds-icon.mjs <имя>` / `--list [подстрока]` (отдаёт ровно нужный глиф, файл в контекст не идёт).
- Не перечитывать файл после своей правки «для самопроверки». Проверка одна — в конце, гейтом `node tools/ds-check.mjs <страница>` (см. «Проверка: чем гонять»).
- Не перезаписывать файл целиком при точечной правке — только замена конкретного фрагмента. Однотипные правки во многих файлах — скриптом на Node, чтобы содержимое не шло через контекст.
- **Не переверстывать внутреннюю анатомию компонента.** Разметка слотов берётся из спеки/чит-шита дословно: где показан `<svg>` — там `<svg>`, размер и тег уже решены в CSS компонента. Правило «иконки только `<i data-icon>`» относится к иконкам в раскладке экрана, не к слотам компонентов (подмена в `.cb__mark` сломала галочки чекбокса, 12.08.2026).
- **Не выбирать иконку по имени, не посмотрев глиф.** Имя из 253 позиций о рисунке не говорит. Сначала отрендерить сетку `foundations/Icons/Icons.html`, выбрать глазами.
- **Не достраивать неизвестное догадкой.** Назначение иконки, поля, связи или термина предметной области, которого я не знаю, — вопрос пользователю, а не реконструкция по внешнему виду. Выведенная догадка неотличима от факта и оседает в документации ДС (12.08.2026: назначение глифа и связей в тайлах было выведено из вида и записано как факт). В документации не остаётся утверждений о предметной области, источник которых не назван.

## Назначение ДС
Точка истины по визуальному языку продукта — для нас (дизайнеров) и для разработчиков, которые собирают по ней компоненты (см. раздел «Для разработчиков»).

**Кто потребитель.** Целевой потребитель ДС — не экран напрямую, а промежуточный слой: локальные организмы под конкретный продукт (тайлы «КНР», «Финансовые метрики сделки», «Дерево продуктов ДИД»), собранные из общих компонентов и несущие собственные правила. Экраны собираются уже из них. Компонент общей ДС предметной области не знает; он обязан дать организму состояния, варианты, поведение при переполнении и точки расширения. Сборка экранов прямо из компонентов — способ проверки ДС, а не целевой сценарий: так видно, что компонент отдаёт наружу, а что молча оставляет на сборщике. В будущем контент страниц соберут в md для автоматического разбора агентом, поэтому текст должен быть точным и однозначным: чёткие заголовки, таблицы вместо сплошного текста, явные значения токенов.

## Версионирование
В шапке страницы (masthead `.meta`) — поля «Версия» и «Обновлено».
- **Формат версии — `М.ммм`, три знака после точки, без префикса `v`** (`1.000`, `1.009`, `2.004`). Единый стандарт для всей ДС и для локальных компонентов проектов (решение 20.08.2026; до этого было `v1.6` с шагом +0.1).
- Менялся сам компонент (стили/поведение/токены) → «Версия» **+0.001** И «Обновлено» = текущая дата.
- **Версия записана в трёх местах — шапка страницы, `version` спеки и строка манифеста `specs/_index.md` — и поднимается во всех трёх одним ходом.** Сверки трёх копий у линтера нет (C7 проверяет только формат). На 01.10.2026 они разошлись у четырёх компонентов, у ContextMenu — при переносе правок из другой копии репозитория. Перенос правок сверяет все три (урок Л164).
- Кардинальная переделка (решили поменять подход, сломали совместимость) → **+1 в мажорной части**, минорная обнуляется (`1.009` → `2.000`).
- Менялась только страница → только «Обновлено» = текущая дата.
- Формат даты ДД.ММ.ГГГГ. Новые компоненты — с `1.000`.
- Формат проверяет линтер (правило `C7`): `v1.6` или `1.6` в шапке — ошибка.
- **Журнал правок — `CHANGELOG.md` в корне.** Менял компонент (стили/поведение/токены) или создал новый → тем же ходом добавь строку в таблицу текущей даты (компонент · версия · что изменилось · почему); нет секции с сегодняшней датой — создай. Правка только текста страницы в журнал не пишется. Журнал начат 21.08.2026, историю до этой даты не восстанавливали.
- **Шапка главной (`index.html`) руками не правится.** Версия ДС, дата и счётчик «Компоненты» выводятся из данных. Дата — самый поздний раздел `CHANGELOG.md`. Версия — последняя метка `· ДС М.ммм` в заголовке раздела журнала (база — `## 27.08.2026 · ДС 1.000`) плюс 0.001 за каждый более поздний день журнала; мажорный шаг — такая же метка на разделе дня. Счётчик — страницы атомов, молекул и организмов (`components/`, вместе с полями группы `Inputs/`). После записи в журнал и после добавления или удаления страницы компонента запусти `node tools/ds-home.mjs`; расхождение ловит правило D9 линтера.

## Контракт CSS компонента

Корень компонента (класс без `__` и `--`), объявляющий `display`, **обязан рядом объявить** `.<корень>[hidden] { display: none; }`. Браузерное `[hidden] { display: none }` живёт в UA-стиле со специфичностью (0,0,0), правило класса — (0,1,0): класс побеждает, и атрибут `hidden` на компоненте молча перестаёт работать. Дефект чинили поштучно шесть раз (Modal, TableCell, Tab, EmptyState, InputText, Chip), после чего закрыли соглашением и правилом **B11** линтера — новый компонент без пары попадёт в отчёт сразу. Исключения заводятся в `HIDDEN_PAIR_OK` (`tools/ds-lint.js`) с причиной. Седьмой случай (строки AllocationBar, 25.09.2026) пришёлся на элемент (`__`), которого B11 не видит, и с 01.10.2026 класс закрыт структурно: `[hidden] { display: none !important }` в `foundations/Typography/Typography.css` (Typography 1.002) скрывает любой элемент. Пара у корня остаётся второй линией.

**Состояние не меняет габарит.** `:focus`, `:hover`, ошибка, выбор меняют цвет, тень, заливку — не толщину рамки и не отступы. У поля с высотой по содержимому лишний пиксель рамки сдвигает всё ниже, у поля фиксированной высоты — текст внутри (InputText 1.015, 25.09.2026: при фокусе соседние поля прыгали). «Толстая» рамка состояния — бордер того же размера плюс `inset`-тень (урок Л158).

Ряд, который несёт рейл (общую линию под табами, слева от вертикальных табов), **не принимает паддинг по оси этой линии** — ни в CSS компонента, ни в хроме страницы, ни инлайном на экране. Inset-тень рисуется по padding-box: паддинг не сдвигает линию вместе с содержимым, а удлиняет её до первого элемента ряда и после последнего. Отступ задаётся обёрткой без рейла. Охраняется правилом **B15** линтера; подавления — в `RAIL_PAD_OK` (`tools/ds-lint.js`) ключом «файл ось блок», с причиной.

Страница, подключившая рантайм, подключает и его CSS: рантаймы ДС стилей не догружают, а разметку строят. Пары с уровнем — в `JS_CSS_PAIRS` (правило **A1**); у `Tooltip.js` → `Tooltip.css` уровень BLOCKER: без стилей построенный `.tip` рисуется обычным текстом и дублирует подпись компонента.

## Контракт страницы компонента
Обязательные разделы в этом порядке; имена h2 — контракт для агентов, только эти слова (варианты «Когда использовать», «Текстовка» и т.п. запрещены):
1. Шапка (masthead) с «Версия» и «Обновлено»
2. Конструктор — первым после шапки
3. Использование (h3: когда использовать/не использовать, сравнения с соседями, примеры в интерфейсе)
4. Анатомия
5. Варианты — контейнер всех осей конфигурации (типы, тоны, формы, ориентация, режимы, «С бейджем»…), каждая ось — h3
6. Размеры
7. Контент (текст, переполнение, иконографика)
8. Поведение — контейнер: позиционирование, авто-разворот, анимации, тайминги, адаптивность; каждая тема — h3
9. Состояния
10. Доступность
11. Типографика
12. Цвета
13. Для разработчиков

Правила:
- Отсутствующий раздел — добавить. Неприменимый (например «Типографика» без текста) — оставить с одной строкой «Не применимо: …».
- Уникальные темы — h3 внутри канонических h2 («Варианты», «Поведение», «Использование», «Контент»); новые h2 не вводить.
- Бейджи («Новое», «Расширение») — отдельным элементом внутри h2, не в тексте заголовка.
- Интерактивные блоки (Конструктор/playground) — наверху, сразу после шапки.
- Сегмент-контролы не переносить в 2 ряда: не помещаются — `<select>`.
- Блок **«Бэклог»** — в самом конце, после «Для разработчиков». Заголовок ровно такой: `<h2>Бэклог</h2>`. Синонимы («Что предлагаем добавить», «Предложения», «Идеи») запрещены — имя раздела контракт для агентов, как и остальные h2. **Раздел обязателен и не удаляется никогда**, даже если предложений не осталось: тогда оставить его с одной строкой вида «Открытых предложений нет: … реализовано и описано в разделах …». Удалять можно только устаревшие пункты внутри, не сам раздел.

### Раздел «Для разработчиков»
Хендофф-пакет (не копипаст-код под стек), только два блока с copy-to-clipboard:
- **Точные размеры (redline)** — таблица высот/паддингов/радиусов/зазоров/типографики по размерам. Значения — через `getComputedStyle(...)` с реально отрендеренного экземпляра (НЕ `getBoundingClientRect()` — на скрытых off-screen вернёт 0), чтобы не расходились с CSS.
- **Поведение · псевдокод (framework-agnostic)** — сложная логика (позиционирование, измерения, клавнавигация) как алгоритм, не vanilla-JS сниппет.
- «Анатомию DOM», «Рекомендуемый API (React)», «Справочник классов» НЕ добавлять.

## file:// — страницы открываются двойным кликом

- Не полагаться на `@import` внутри CSS по `file://` — нужный CSS компонентов и
  основ подключать **явными `<link>`** на странице.
- `fetch`/XHR по `file://` с не-ASCII путём **не работает** — любые данные для
  рантайма (код во вкладке «Код» и т.п.) вставлять статично в страницу
  (`<script type="text/plain">`), не подгружать.
- Порядок скриптов на странице документации: рантаймы (`<Имя>.js`, `utils/ds-*.js`) → `page.js`
  страницы → `docs-split.js`. Инлайн-обработчик, читающий состояние рантайма
  в момент события, срабатывает раньше (регистрируется при парсинге) и читает
  устаревшее значение. Переключение табов — по `data-`-атрибуту кнопки,
  клавиатура — через `setTimeout(0)`.

## Страницы документации (`<Имя>.html` в папках ДС) — паттерн «docs-split»

- Страницы документации компонентов — отдельный сценарий, не экраны проекта.
  Реструктуризация под паттерн «сплиттер + табы» и любые правки страниц —
  только по явному поручению человека.
- **Служебный тег темы** `docs-kit/ds-theme-boot.js` (RE0005) — один на
  страницу, последним в `<head>` (после `<style>`): ставит `data-theme` на
  `<html>` до первой отрисовки (`?theme=` или сохранённый выбор) и подключает
  `foundations/Themes/Themes.css` + `Themes.pages.css`. Путь — как у
  `window.__DS_ROOT`. Новый компонент берёт тег из эталона
  `.agents/skills/docs-split/references/skeleton.md`; наличие проверяет `ДС20`
  (`docs-split.mjs check`).
- Общий слой паттерна: `docs-kit/docs-split.css` (все правила префиксованы
  `main.ds-split` — на страницы без класса не влияют) + `docs-kit/docs-split.js`
  (активируется только при наличии `main.ds-split`). Страница-хост ставит
  класс `ds-split` на `main.page`.
- Структура: `main.page.ds-split` > `.splitpane--h[data-splitter]` > (панель A:
  демо `#pg-stage`; `.spl--h`; панель B: `.tabs[data-tabs]` + `.tabs-body` >
  три `.tabpane`). **Документация / Конструктор / Код используют единый
  контейнер `.docs-layout`** (центрированный, контент ~1200px; у документации
  справа колонка TOC) — вёрстка под табами идентична, никаких параллельных
  `.constructor-panel`/`.code-panel-wrap` с другими отступами.
- **Конвенция конструктора — две колонки:** справа (`.toggles`) —
  свитчеры, чекбоксы, радиобаттоны и слайдеры; слева (`.ctl-col`) —
  ButtonGroup, выпадающие списки и прочие инпуты. Если в конструкторе только один тип
  контролов — он встаёт в левую колонку. Контролы, разбитые на группы
  (`.ctl-group`, как в TableCell: «Шапка колонки», «Ячейка», «Строка»),
  сохраняют группировку — правила действуют отдельно внутри каждой группы.
  Свитчеры — самодостаточная подпись **без отдельного лейбла сверху**
  (правило компонента Switch) и **статичная**: не меняется от положения
  свитча — свитч называет опцию действием в On-состоянии («Показывать
  проценты»), а не переименовывается при выключении («Скрыть проценты»).
  Словарь `window.DS_SPLIT_SWITCH_LABELS` = статичная строка
  (`'Тултип': 'Показывать тултип'`) или объект `{ label, on? }` — `on` для
  явного on-значения селекта, когда эвристика даёт неверное направление.
  **Выбор по числу вариантов (решение человека 21.09.2026):** да/нет —
  свитч; 2–3 равноправных варианта («Юрлицо / Физлицо», «Найдено /
  Выбрано») — ButtonGroup с сегментированным выбором; 4 и больше —
  выпадающий список. Страница пишет все выборы селектами, превращает их
  `docs-split.js`: свитчем становится селект из словаря
  `DS_SPLIT_SWITCH_LABELS` или с вариантом «выключено» (`no`/`off`/
  `none`/«Нет»), остальные на 2–3 варианта — ButtonGroup (outline,
  fullwidth, M) в левой колонке. **ButtonGroup — тоже без лейбла
  сверху** (правило компонента ButtonGroup, 21.09.2026): слой прячет
  `.lbl`, его текст уходит в `aria-label` группы, поэтому варианты
  селекта пишутся самодостаточными — «1 чип / 2 чипа / 3 чипа», «По
  левому краю / По правому краю», «Без легенды», а не «1 / 2 / 3»,
  «Слева / Справа», «Нет». Свитч, управляющий полем, стоит в `.ctl`
  первым и несёт имя опции («Prefix»), а поле под ним — свой `.lbl`
  по смыслу («Пример», «Вариант»): лейбл над свитчем — дефект (R9).
  **SegmentControl в конструкторе не используется.** Неактуальные контролы
  скрываются полностью (`.is-off`), а не блокируются и не затемняются. Пустая колонка не рисуется (`docs-split.css`) —
  единственная оставшаяся встаёт слева. Слайдер/range — обычная ячейка
  правой колонки, не на всю ширину (без `ctl--span`).
- **Запрет `.splitpane--app`** на панелях паттерна: его правило переводит
  панели в `display:block` и ломает flex-раскладку (скролл, центрирование,
  якоря). На панелях — `display:flex!important`.
- Вкладка «Код»: исходники статично в `<script type="text/plain" id="src-code-*">`
  (HTML — эталон из спеки, CSS — полный файл, JS — выжимка API из `page.js`);
  подсветка — общим скриптом.
- Локальный TOC (замена `ds-toc.js`) собирается `docs-split.js` из
  `section.section` внутри `#pane-docs`. `ds-toc.js`/`ds-toc.css`/`pg-kit.js`
  на страницах паттерна не подключаются.
- **Скомпилированные артефакты витрины в ДС не хранятся.** Бандл
  `_ds_bundle.js` и манифест `_ds_manifest.json` были производными внешнего
  инструмента: ни одна страница их не подключала, линтер и сенсоры их не
  читали, локального компилятора не существует. Удалены 04.09.2026. Не
  собирать, не воссоздавать, не сверять с ними `*.page.js`. Маркер
  `<!-- @dsCard … -->` первой строкой страницы остаётся — его требует
  линтер (C1).

## Таблицы в документации
Любая табличная разметка на странице компонента (редлайн, справочник токенов/классов, размеры, **справочник цветов**) собирается на компоненте ДС Table/TableCell (`.tbl`/`.tbl__row`/`.th`/`.tc`, см. `components/organisms/TableCell/TableCell.md` и блок TableCell в `specs/_cheatsheet.md`), не на нативном `<table>`/`.ref-table`/`.dev-table` и не на самодельной сетке `.color-ref`/`.cref-group`/`.cref-row` (устаревший паттерн, отовсюду убран). Образец блока «Цвета» — `components/molecules/DropdownList/DropdownList.html`: `.panel` → `.tbl` со столбцами Раздел/Роль/Токен/Образец (`<span>` 22×22, `border-radius:var(--radius-xs)`, `background:var(--токен)`)/Hex. ## Сборка экранов и организмов
1. **Контекст = один файл, но точечно.** `specs/_cheatsheet.md` — все компоненты: css, deps, назначение, DOM-сниппет. Файл большой, **целиком не читать**: оглавление `grep -n "^## "`, блок компонента `sed -n '/^## <Имя>$/,/^## /p'`. Полную спеку — только для 1–2 компонентов со сложным поведением. CSS компонентов не читать.
2. **Один линк стилей** — только `ds.css` (импортирует всю ДС), не CSS компонентов поштучно. Новый компонент → добавить его @import в `ds.css`.
3. **Шаблон** — копия `templates/screen/Screen.html`, не с нуля.
4. **Иконки** — только `<i data-icon="имя"></i>`; рантайм иконок (`icons-data.js` + `Icons.js`) подключает `ds.js` (п.10) и сам вставляет SVG в currentColor; размер — width/height, дефолт 24px. Инлайн-SVG запрещён.
5. **Стили экрана** — токены и классы ДС; свой CSS только раскладка (grid/flex/gap).
6. **Нет нужного компонента в ДС** (Input, Table, Modal, Card…) — не выдумывать на ходу. Остановись, назови недостающее, сначала создаём его как компонент ДС, потом экран.
7. **Экран статичен** (мокап): состояния показывать вёрсткой (открытый дропдаун — отрисован открытым). JS — только если явно попросили кликабельный прототип.
8. **Чит-шит актуален**: новый/изменённый компонент → обнови его блок в `specs/_cheatsheet.md` тем же ходом.
9. **Тайлы в одном ряду равны по высоте** — высота строки определяется тайлом с максимальным контентом (`Tile.md`, «Размеры»). Выравнивает CSS тайла (`align-self: stretch` у `.tile`, `components/organisms/Tile/Tile.css`) — руками на ряду ничего не ставить.
10. **Рантаймы — через единую точку входа `ds.js`.** Один тег `<script src="ds.js"></script>` в конце body догружает все рантаймы ДС (список и порядок — `FILES` в `ds.js`: icons-data, Icons, Tab, Tile, ContextMenu, Popover, Tooltip, Modal, Table, Pagination, ds-notify, DatePicker, InputKit, NavPanel, Splitter, Illustrations и другие) в правильном порядке; каждый молча ничего не делает без своей разметки на странице, поэтому список одинаков для любого экрана. Экранный скрипт с данными конкретного экрана — отдельным тегом сразу после `ds.js`. Подключать перечисленные файлы напрямую не нужно и ловится линтером (`A7`). Закрыто 12.08.2026 — до этого недоподключено на всех 12 экранах.
11. **Компонент-композиция собирается целиком.** RiskMetric = Chip + Popover: без слоя `.pop` это не компонент. Так же Split-кнопка (ButtonGroup + меню), Select (+ DropdownList), переполнение табов (обёртка + меню «Ещё»). Половина композиции не диагностируется — выглядит нормально, не работает.
12. **Метод рантайма зовут по имени из экспорта, а не по памяти.** Идиома `window.DSX && DSX.method(...)` при опечатке в имени метода не падает и ничего не пишет в консоль: guard просто ложный, и функциональность тихо отсутствует. Так на Kanban не появлялся индикатор сегмент-контрола (`DSTabs.bindAll` вместо `wireAll`), не закрывалась модалка подтверждения (`DSModal.close` вместо `closeTop`), не рисовались иллюстрации пустого состояния (`DSIllustrations.apply` вместо `render`). Ловится линтером (`A9`) — правило репозиторного уровня: сверяет обращения `DSX.method(` во всех скриптах и страницах с ключами `window.DSX = {…}` соответствующего рантайма. Заведено 10.09.2026 после трёх таких промахов в одном заходе.
13. **Разметка, перерисованная скриптом, обязана быть связана заново.** Рантаймы ДС связывают свою разметку один раз, на `DOMContentLoaded`. Экран или витрина, пересобравшая блок через `innerHTML`, зовёт `DSMenu.bindAll(scope)`, `DSModal.bindAll(scope)`, `DSDrawer.bindAll(scope)`, `DSTabs.wireAll(scope)`, `dsIcons.apply(scope)` — иначе кнопки и меню остаются мёртвыми, причём молча.
14. **Скроллпорт и ряд одинаковой высоты — разные элементы.** Горизонтальный flex-контейнер, который сам является скроллпортом (`overflow: auto`), растягивает своих детей по высоте ВИДИМОЙ ОБЛАСТИ (`align-items: stretch` — дефолт), а не по высоте самого длинного из них. Если внутри ребёнка есть `position: sticky`, он держится только до конца этой коробки — то есть до конца одного экрана прокрутки, а контент, не влезший в коробку, торчит за её пределами и теряет hover/dropzone. Решение — развести роли: контейнер с `overflow` (скроллпорт) и вложенный в него ряд с высотой `auto` (растягивание по контенту). Пример — `.kanban__viewport` / `.kanban__track`. Ловится линтером (`B13`, WARN): срабатывает только если в том же CSS-файле объявлен `position: sticky`.

### Сверка с макетом
Соответствие картинке-референсу автоматика не проверяет: ни линтер, ни `layout-check.mjs` с макетом не сверяют. Скиллы сборки по скриншоту и гейт `FIDELITY-GATE` (правило линтера G1) сняты 13.09.2026: гейт требовал снимок отрендеренного экрана, а браузер по скрипту запрещён, так что он был невыполним и краснил каждый экран. Метрики макета (ширина, плотность, типошкала) по-прежнему переносятся в ТЗ текстом.

## Темы: новая тема и точечное правило
Темы — наложение поверх ДС (RE0005, MS0013). Файлы тем и фиксированные растяжки — `foundations/Themes/tokens/*.json`; роли, профили и точечные правила — `Themes.tokens.js`. Генераты `Themes.css`, `Themes.pages.css`, рантайм-данные для браузера `Themes.runtime.js` и зеркало `tokens.data.js` собирает `node tools/theme-build.mjs` (`--check` сверяет источники, legacy, контраст и свежесть, `--selftest` проверяет алгоритм). `node tools/theme-files-selftest.mjs` проверяет защиту записи, конфликт и откат при сбое зеркала. Руками генераты не правятся.

**Добавить тему.** Файл `foundations/Themes/tokens/<имя>.json`: `name`, `label`, `locked:false`; профили `light`/`dark` с `brand`, `neutral` (#RRGGBB), `adjust`, `overrides`, `onFill`. Legacy и Neo защищены; новый файл создают в конструкторе через «Сохранить как…» или агентом. Базовые 17 тонов фиксированы: светлая из Colors.css (серый = mgrey, 950 = 900), тёмная из прежней ibp-dark. `Ramp.tokens.js` строит Brand/Neutral, `ThemeEngine.js` применяет профили и карту. `theme-build.mjs` читает JSON, собирает Themes.css и зеркало tokens.data.js. После ручного добавления — сборка и --check. Конструктор пишет JSON и зеркало тем же компилятором через FSA; Firefox/Safari скачивают JSON для ручной установки. IndexedDB хранит только handle папки, несохранённое существует только в памяти. `DSTheme.set(name,mode)` работает на всех страницах, ThemeBoot.js генерирует CSS своей темы до первого рендера. Старые ibp-light/ibp-dark ведут на ibp-neo. Плавающего окна и Alt+Shift+T больше нет.

**Добавить точечное правило.** Место, где старого имени компонента не хватает: в `rules` источника — `file`, `selector`, `prop`, `from` (исходное объявление в CSS) и `value` (роль). Генератор пишет правило под `:where([data-theme]:not([data-theme="legacy"])…)`, сверяя **селектор и объявление** с файлом компонента.

**Генератор сообщает «пропал селектор» или «пропало объявление».** Значит, компонент изменили и место правила ушло. Правка в том же заходе: привести правило к новому месту компонента или убрать его. Оставлять нельзя — это красный `theme-build --check` в гейте.

**Контраст.** Пары «текст/фон» — в `contrast` источника: `required: true` роняет сборку; `false` — информационная (базовые тона legacy); `exempt: [тема]` — информационная для одной темы (фиксированные статусы сохраняют исторические исключения; у service/custom-dark сохраняется прежний контраст. Ссылки и границы генерируемых тем корректируются автоматически). Порог: текст 4,5:1, границы и элементы управления 3:1.

**Стерегут:** `theme-build --check` (генерат = источник; все роли и 119 имён; монотонность рамп; контраст; ibp-legacy = 119 значений Palette.css; base-light = Colors.css; JSON = зеркало) — шаг `ds-check --all` и гейта; `B16` — имена тем только в `foundations/Themes/`; `B17`/`ДС20` — служебный тег темы на страницах ДС.

| `node tools/spec-audit.mjs` | **Read-only аудит «правило объявлено — кода нет»** (Л42): проходы по репозиторию: обещания спек, чит-шита и манифеста против кода, CSS и каталога компонентов в `AGENTS.md` (состав проходов — в шапке скрипта, вручную не перечисляется). Ничего не пишет. Код выхода 1 — если есть не закрытое обещание «усечено → тултип» (корневой дефект CM) или манифест `specs/_index.md` расходится с каталогом §6 `AGENTS.md` (проход 8) | После правки спеки/рантайма, манифеста или каталога в `AGENTS.md` |

Коды выхода: 0 — чисто, 1 — есть BLOCKER/FAIL. Все пути — относительные от корня ДС.

Инструменты проекта, куда примонтирована ДС (журнал уроков, сенсор раскладки экрана), — в его харнесе; ДС их не требует.

## Целостность страниц (линтер ДС)
Тихие ошибки — забытый парный CSS, несуществующий токен, нарушенный контракт разделов, рассинхрон index / ds-nav / спек — ловит линтер `tools/ds-lint.js`. Сам по себе он не исполняемый (ждёт хелперы `readFile`/`ls`) и на страницах не подключается: запускать только через обёртку `tools/ds-lint-cli.mjs` или гейт `tools/ds-check.mjs`. Разбор правил и групп — `tools/ds-lint.md`. Прогон обязателен на любом новом или правленом компоненте и экране; страницу «глазами для перепроверки» не читать — источник истины один, отчёт линтера. Разобрал инцидент — тем же заходом допиши класс ошибки в линтер, иначе он повторится.

Класс дефекта «правило объявлено в спеке — реализации нет» (Л42) статический линтер не ловит — он проверяет связность/токены, а не «обещано поведение → есть код». Для него — read-only `tools/spec-audit.mjs` (см. «Проверка: чем гонять»): сверяет спек/манифест против рантаймов и выносит не закрытые обещания (например, «усечено → тултип»). Прогонять после правки спеки/рантайма, когда заявлено поведение.

## Тона состояний Button и Link
У Button и Link есть тоновые классы `.btn--<tone>` и `.link--<tone>` (info/warning/error/success).
