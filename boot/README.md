# boot — загрузчик дизайн-системы

Два маленьких файла, которыми экран подключает ДС. **Генерируются** из
манифеста проекта и руками не правятся:

```bash
node .agents/tools/boot-build.mjs           # собрать
node .agents/tools/boot-build.mjs --check   # сверить с манифестом (шаг гейта boot)
```

## Зачем

Путь до дизайн-системы записан **ровно в одном месте** — `project.json →
designSystem.mount` (решение владельца Р5). Раньше он стоял в каждом экране
четырьмя строками (корень рантайма, фавикон, `ds.css`, `ds.js`), и переезд ДС
означал массовую правку экранов. Теперь перенос ДС — это правка одного
значения в манифесте и пересборка загрузчика: ни один экран не трогается.
Литерал каталога ДС в экране — блокер сенсора Б34.

Почему не `.env` и не сборщик: страницы открываются двойным кликом
(`file://`), где нет ни процесса, ни `fetch`. Обычный `<script>` — всё, что
доступно браузеру в этом режиме.

## Как экран подключает ДС

```html
<head>
  <script src="../../../boot/ds-head.js"></script>   <!-- первым в <head> -->
  …
<body>
  …
  <script src="../../../boot/ds-body.js" data-ds="scripts/ibp-home.js"></script>
  <script> /* экранный скрипт */ </script>
```

| Файл | Что делает |
|---|---|
| `ds-head.js` | вычисляет корень проекта от собственного адреса (`document.currentScript.src`), ставит `window.__DS_ROOT`, пишет тегами фавикон и `ds.css`, задаёт переменную `--boot-bg-illustration` — фон стартовой страницы (экран пишет `var(--boot-bg-illustration, none)`) |
| `ds-body.js` | пишет тег `scripts/ds.js` (он сам догружает рантаймы ДС), а следом — дополнительные скрипты ДС из атрибута `data-ds` своего тега: пути внутри ДС через пробел |

Теги пишутся через `document.write` во время разбора страницы — то же место и
тот же порядок, что у прежних ручных тегов: собственный `<style>` экрана
по-прежнему идёт после `ds.css`, а `ds.js` успевает отработать до следующего
скрипта страницы.

**Ограничение честное:** загрузчик подключается обычным тегом, без `async` и
`defer` — иначе `document.write` не сработает.

## Что проверяет гейт

Шаг `boot` (`boot-build --check`) сверяет файлы с манифестом: коды БТ —
загрузчик не сгенерирован (БТ2) или разошёлся (БТ3) — правлен руками либо не
пересобран после смены `designSystem.mount`. Сам генератор доказан селфтестом
`boot-build --selftest`, включая разбор сгенерированного кода как JS.
