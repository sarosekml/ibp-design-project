Описание

Артефакт тайла «Сроки сделки». Не компонент: сам по себе не существует и в плоском списке кита его нет — он принадлежит своему тайлу и живёт под-пунктом его навигации. В ките и документации оно называется «Модальное окно сроков сделки», заголовок самого окна — «Сроки сделки».

Окно решает одну задачу: ввести дату первой выдачи. Её вводят вручную, когда в сделке есть инструмент НКЛ с баланса ПАО: его выдачи хранятся в стороннем сервисе, а не в системе. Дата заключения и дата окончания приходят из инструментов сделки и стоят в окне только для справки — по ним видно допустимый диапазон. У каждого поля информер: что это за поле и откуда данные.

Даты окно не хранит и сделку не знает: при каждом открытии берёт их у страницы, проверенную дату отдаёт странице (PostDealTermsModal.bind(scrim, { get, save }), DealPeriodModal.js). Страница сделки пишет дату в DealsStore и перерисовывает тайл.

Правила состава и проверки

  1. Правится только «Дата первой выдачи». Две другие даты — ReadOnlyField: их не правят и здесь, они приходят из инструментов.
  2. Пустая дата для справки — прочерк, поле с места не уходит.
  3. Дату первой выдачи можно стереть и сохранить пустой (решение человека 22.09.2026).
  4. Непустая дата проверяется по «Сохранить»:
    • не дата ДД.ММ.ГГГГ (в том числе несуществующий день) — «Введите дату в формате ДД.ММ.ГГГГ»;
    • раньше даты заключения — «Не раньше даты заключения — <дата>»;
    • позже даты окончания — «Не позже даты окончания — <дата>». Границы включительно. Если даты заключения или окончания нет, эта граница не проверяется.
  5. Ошибка — по правилу InputText: поле красное (inp--error, aria-invalid), текст — в тултипе на фокусе поля, не в хелпере. Окно с ошибкой не закрывается, фокус уходит в поле.
  6. Правка поля пересчитывает уже показанную ошибку и снимает её, как только ввод стал верным. Новая ошибка появляется только по «Сохранить» — пока дату набирают, поле не краснеет.
  7. Маска ДД.ММ.ГГГГ и календарь — из коробки ДС (InputDate, DatePicker).
