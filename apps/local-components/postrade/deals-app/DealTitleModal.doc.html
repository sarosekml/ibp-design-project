Описание (Purpose)

Артефакт шапки страницы сделки. Карандаш справа от заголовка «<номер>. <наименование>» открывает это окно; в нём правятся номер и наименование сделки. Заголовок окна — «Редактирование сделки».

Окно повторяет окно «Новая сделка» реестра портфеля (pages/Portfolio.html, #new-deal-scrim): те же два поля, тот же хелпер, те же правила и тексты проверок, — только поля заполнены значениями сделки (просьба человека 01.10.2026). У фронтенда это два окна, DealCreateModal и DealTitleModal, поэтому и здесь отдельный фрагмент, а не режим окна реестра.

Сделку окно не знает: значения берёт, сверяет с реестром и сохраняет через функции, которые передала страница (PostDealTitleModal.bind(scrim, { get, exists, save })).

Правила проверки

  1. Оба поля проверяются по «Сохранить»; при правке поле перепроверяется сразу, и ошибка снимается, как только ввод стал корректным (как в окне реестра).
  2. Номер: пусто — «Укажите номер сделки»; не только цифры — «Номер сделки — только цифры»; занят другой сделкой — «Сделка с таким номером уже есть в реестре».
  3. Наименование: пусто — «Укажите наименование сделки»; занято другой сделкой — «Сделка с таким наименованием уже есть в реестре».
  4. Сверка — регистронезависимая и по обрезанным пробелам (DealsStore.exists). Значение самой сделки дублем не считается: страница исключает её (except), и окно не сверяет значение, равное текущему.
  5. Ошибка — по правилу InputText: поле красное (inp--error, aria-invalid), текст — в тултипе на фокусе поля, не в хелпере. Окно с ошибкой не закрывается, фокус уходит в первое поле с ошибкой.
  6. Ничего не поменялось — «Сохранить» просто закрывает окно. Иначе странице уходит только изменённое: { id?, name? }.

Открытые вопросы (Open questions)

  1. Владелец — не назначен (01.10.2026).
  2. Хранение. Правка уходит в DealsStore — память страницы, как всё в нём: до реестра портфеля и до перезагрузки она не доходит. Постоянное хранение не решено (01.10.2026).
  3. Номер — ключ сделки. В прототипе номер и есть id записи. После смены номера адрес страницы (?id=) остаётся со старым, а состав КНР и дерево продуктов хранятся под старым номером (DealsStore помнит его как псевдоним). Как у бэкенда: меняется ключ или отдельное поле «номер» — не решено (01.10.2026).
  4. Две копии разметки. Окно реестра (Portfolio.html) и это окно повторяют одни поля и тексты. Пока реестр — не модульная страница, правки окна надо вносить в оба места; вынести общую часть — не решено (01.10.2026).
  5. Кто может менять номер. Права на смену номера и наименования отдельно от прочей правки сделки — не решено (01.10.2026).
