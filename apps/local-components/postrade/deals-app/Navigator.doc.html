Описание

Тайл ведёт сделку от черновика до мониторинга. Статус у сделки не один: свой статус у самой сделки, у ЦУП, у Operations и у мониторинга. Тайл показывает их вкладками (Сделка · ЦУП · Operations · Мониторинг): на каждой — путь дорожки степпером и действия, которые доступны в её текущем статусе.

Всё, что тайл рисует и делает, берётся из статусной модели сделки (data/deal-status-model.js): вкладки — её дорожки, шаги — её степперы, кнопки и пункты меню — её ручные переходы, последствия действия — её автопереходы. Модель — единственный источник; её схема, таблицы и несостыковки макетов — генерат data/deal-status-model.md (раздел «Несостыковки» там же, здесь не копируется).

Действие тайла меняет статусы записи сделки в DealsStore, поэтому вместе с тайлом меняются чипы статусов в шапке страницы и режим правки страницы (статус сильнее роли).

Вкладка «Сделка» — не путь статусов, а чек-лист заполнения: Общая информация · Продукты ДИД · Финансовые инструменты · Расчёт метрик · Согласование. Шаг «Согласование» нажимается и включает «Передать на сопровождение».

Место тайла на странице и ширину задаёт страница сделки (apps/postrade/deals-app/pages/Deal.html): правая колонка 320px, минимальная высота 400px — из ТЗ.

Обязательность заполнения

  • Компонент обязателен к заполнению целиком: не применимо — тайл не форма, значения ставит процесс.
  • Обязательные поля внутри: см. «Поля».
  • Что показывает, когда обязательное не заполнено: чек-лист «Сделки» — незаполненный раздел без галочки. Минимум для передачи на сопровождение по пояснению к «Черновику» — дата заключения и один инструмент; прототип его не проверяет: дату заключения на странице не завести (окно «Сроки сделки» правит только первую выдачу) — допущение 10.10.2026, вопрос 7.
  • Что отдаёт наружу: patch статусов записи сделки (страница пишет его в DealsStore).

Поведение

Переход статуса

Клик по кнопке подвала или пункту кебаба → переход модели → автопереходы модели в цикле (after.any — сработал любой из переходов, after.all — собраны все отметки, requires — запись стоит во всех статусах списка) → patch статусов → страница пишет его в DealsStore → тайл, чипы шапки и режим страницы перерисовываются по событию стора. Пример: «Утвердить» ЦУП при подтверждённой Operations → ЦУП «Утверждена», сделка «Активная», мониторинг «Утверждена».

Кнопки и меню

  • Кнопки вкладки — ручные переходы модели с via: 'button' из текущего статуса её дорожки, в порядке модели; первая — Accent, остальные — Outline (на области один Accent, Button ДС).
  • Пункты кебаба — переходы с via: 'menu' из текущих статусов всех дорожек: ввести изменения, погасить, вернуть в действующие, на мониторинг (ГК СБИ), передать изменения на мониторинг, удалить.
  • Переход без via (технический, «Ожидает передачи» → ПАО) не показывается.
  • «Список изменений» — кнопка из extraButtons степпера; куда ведёт — не решено (вопрос 3).

Скрипт Navigator.js (window.PostNavigator)

  • laneStatus(deal, lane), actions(deal), apply(deal, transitionId, extra) — движок модели без DOM; apply возвращает { patch, fired } и запись не меняет.
  • markOf(transition) — чью отметку ставит переход на себя (rm · pm · pmz); по нему окно NavigatorApprovalModal выбирает вариант.
  • render(tile, deal, opts) — вкладки, панели, кебаб; bind(tile, { get, save, progress, openModal }) → { paint, off }.
  • Клик без bind — событие navaction (TRANSITION, RETRY) на корне тайла.
