Описание

Тайл страницы сделки: из каких финансовых инструментов (ФИ) состоит сделка. Каждый ФИ — карточка: номер и тип в сделке задаются при создании, параметры правят в окне изменения, а баланс, валюта, сумма, дата подписания и список инструментов приходят из дерева продуктов — из инструментов и траншей, прикреплённых к карточке (решение человека 02.10.2026). Прикрепляют их в соседнем тайле «Продукты сделки», окном «Изменить связь с ФИ».

Типы ФИ: Кредит, Акции, Доп. доходность, РЕПО, Дебиторская задолженность. От типа зависят подпись суммы (сумма лимита · стоимость покупки · цена исполнения), целевой IRR (у акций) и состав окна изменения.

Тайл — витрина ФИ и точка входа в их правку:

  • пустой тайл в правке — «Сгенерировать автоматически» (карточка на каждый тип узлов дерева без связи с ФИ, узлы сразу прикрепляются, решение человека 02.10.2026) и «Заполнить вручную» (окно создания);
  • «+ Фин. инструмент» в шапке и «+ Финансовый инструмент» под списком — окно создания;
  • пункт «Изменить» меню карточки — окно изменения (временный — состав меню не решён).

Вкладки «Все · Активные · Погашенные» фильтруют карточки. Погашена карточка, у которой прикреплённые узлы есть и все погашены (допущение агента 02.10.2026). Пустая вкладка выключена и без счётчика — как «Погашенные» на макете.

Правила живут в сторе ФИ FinInstrumentsStore (data/fin-instruments-store.js), тайл их не дублирует.

Точной пары во фронтенде нет: ближайшее — группа DealFinancialInstrumentsGroup (widgets/groups/) из карточек DealFinancialInstrumentTile (features/); имя тайла оставлено нашим (README модуля, «Имена фронтенда»). Окна — пары фронтенда DealFinancialInstrumentCreateModal и DealFinancialInstrumentEditModal. Место на странице, ширину и минимальную высоту (200px) задаёт экран (apps/postrade/deals-app/pages/Deal.html), не компонент.

Откуда данные. Во фрагменте FinInstrumentsTile.html список — пример с макетов (сделка 1027: кредит с траншем развёрнут, акции с PE и кредит с ошибкой свёрнуты). На странице сделки его заменяет FinInstrumentsTile.js: PostTileFinInstruments.bind рисует FinInstrumentsStore.view() своей сделки и перерисовывает тайл после сохранения в окнах ФИ и в окне связи с ФИ у дерева. Карточки сохраняются между перезагрузками (PostApi, data/API.md).

Обязательность заполнения

  • Компонент обязателен к заполнению целиком: не решено (19.09.2026).
  • Обязательные поля внутри: тип, тип отчётности (окно создания) и наименование (окно изменения).
  • Что показывает, когда обязательное не заполнено: окна не сохраняют без них; в тайле таких карточек не бывает.
  • Что отдаёт наружу: карточки ФИ сделки — их читает окно связи с ФИ у дерева продуктов (ProductTreeStore.fiCards).

Функция
Что делает
cardHTML(card, opts)
разметка карточки из FinInstrumentCardView; opts.mode — edit / view, opts.open — развёрнута
counts(cards)
{ all, active, repaid } — счётчики вкладок
stateOf(cards)
empty — карточек нет; partial — у какой-то нет контрагента, FV/AC или узлов; иначе data
render(tile, cards, opts)
перерисовать список и вкладки, поставить data-state; opts.state — loading / updating, opts.canGenerate — доступность «Сгенерировать». После перерисовки связывает иконки, меню, окна, тултипы, риск-метрики и аккордеоны
bind(tile, store)
связать тайл со стором ФИ и стором дерева: перерисовка на use и после сохранения; «Сгенерировать» — store.generate(). Возвращает функцию отвязки
watchTabs(tile)
фильтр по вкладке — после клика или клавиши читает выбранную вкладку микрозадачей, когда рантайм Tab уже отработал (он мог привязать группу раньше скрипта тайла, поэтому не onChange)

Действия с исполнителем тайл отдаёт событием fiaction на своём корне, detail = { action, id }: CREATE слушает окно создания, EDIT — окно изменения. Пункты меню живут в общем слое DSFloat, их владельца тайл находит по кнопке-триггеру (урок Л88).
