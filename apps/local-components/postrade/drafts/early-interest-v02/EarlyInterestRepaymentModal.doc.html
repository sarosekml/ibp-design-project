Описание

Артефакт тайла «Досрочное погашение процентов». Заголовок окна — «Новый платеж» при внесении и «Изменение платежа» при изменении, форма одна.

Досрочный платёж — сумма, которая начиная с «Даты платежа» гасит процентную задолженность по видам в порядке приоритета погашения (окно «Приоритет погашения»). Кнопка «Рассчитать платежи» берёт задолженность процентного периода, в который попала дата, и раскладывает по ней сумму: первый вид гасится целиком, остаток идёт в следующий. Результат — таблица «Задолженность на дату»; «Досрочную сумму» любой строки можно поправить руками, но не больше её «Начисленной суммы». «Добавить» проходит, только когда сумма строк равна сумме платежа.

Страницу и таблицу платежей окно не знает: задолженность по периодам, валюту и приоритет берёт у страницы, проверенную запись отдаёт ей же (PostModalEarlyInterest.bind(scrim, { options, save }), EarlyInterestRepaymentModal.js). Страница ставит платёж «В обработке» и показывает уведомления.

Обязательность заполнения

  • Компонент обязателен к заполнению целиком: не применимо — окно.
  • Обязательные поля: «Дата платежа», «Сумма платежа»; расчёт обязателен перед «Добавить».
  • Что показывает, когда обязательное не заполнено: подсветка inp--error без текста.
  • Что отдаёт наружу: запись { paymentDate, paymentAmount, comment, allocations } через save.

Открытые вопросы

  1. Пары во фронтенде нет — имя наше (16.10.2026).
  2. Владелец компонента — не решено (16.10.2026).
  3. Сброс расчёта при смене даты или суммы — решено человеком 16.10.2026: таблица не сбрасывается, пересчитывает только «Рассчитать платежи».
  4. Платёж «Не обработан» можно править и сохранять повторно — решено человеком 16.10.2026 (причины ошибок обработки пока неизвестны; возможно, сервис недоступен).
  5. После ошибки «Сумма платежа превышает общую сумму задолженности» добавить платёж нельзя — решено человеком 16.10.2026: пользователь уменьшает сумму или рассчитывает на более позднюю дату.
  6. Маска даты на макете — «ММ.ДД.ГГГГ», в ДС и во всём проекте — «ДД.ММ.ГГГГ»; сделано по ДС (несостыковка макета, 16.10.2026).
  7. Валидация пустых полей на макете — только красные рамки, без текста; ошибка нулевой суммы на макете не показана — «Сумма платежа должна быть больше нуля» добавлена агентом.
  8. Заголовок ошибки «Сумма платежа превышает общую сумму задолженности» и «На указанную дату начисления отсутствуют» на макете — одна строка без заголовка; сделано так же.
  9. Макет показывает «Тип платежа» в одном ряду с датой и суммой — три колонки; «Комментарий» — на всю ширину.
  10. Сумма без верхнего предела, валюта — валюта инструмента (ответ человека 12.10.2026).
  11. «Досрочная сумма» — поле в каждой строке (правка человека 16.10.2026: по клику поле не появлялось); подсветка активной строки — допущение агента.
  12. Блок итогов под таблицей — серая подложка --tertiary-bg со скруглением --radius-m (8px) по образцу блоков метрик deals-app (правка человека 16.10.2026); готового компонента «подложка» в ДС нет.
  13. Рост задолженности с датой — упрощение прототипа (решение человека 16.10.2026): в жизни на графике платежей есть и погашения, после которых задолженность падает; с реальными моковыми данными логика заменится.
