# Карта экранов

Майндмап страниц проекта от главной: клик по карточке открывает страницу в
состоянии по умолчанию, с живыми демо-данными. Зачем (решение человека
11.10.2026) — открыть любую страницу быстрее, чем через весь пользовательский
сценарий: глубокие экраны зависят от адреса (`Tranche.preview.html?id=&tr=`),
без цепочки «Главная → … → Транш» до них не дойти. Состояния (окна, статусы,
варианты по параметрам) — опционально: переключатель «Состояния», по умолчанию
выключен. Концептов на карте нет — только модули раздела. Постановка —
задача [RE0015](../../docs/tasks/RE0015-screen-map.md).

## Как открыть

- Хаб [`index.html`](../../index.html) → колонка «Проекты» → «Карта Post» (сразу
  под «Post — ДИД»).
- На любой странице модуля Post: `Alt+Shift+P` → кнопка рельса «Screen map» —
  дерево страниц, текущая подсвечена, под ней — её состояния чипами.

## Как устроено

```
apps/screen-map/
├── README.md         этот файл
└── <раздел>/
    ├── map.yaml      источник: узлы, связи, состояния — руками
    ├── map-data.js   window.ScreenMaps[<раздел>] — генерат, руками не править
    └── index.html    страница карты — руками (оболочка, переключатель «Состояния»)
```

Отрисовщик один на оба входа — `.agents/proto-panel/map-view.js` (страница —
майндмап, шторка панели — дерево). Записи карт — `project.json → screenMap`
(`dir`, `maps`).

## Как править

1. Править `<раздел>/map.yaml`. Формат, поля и коды КЭ1–КЭ8 — шапка
   [`screen-map.mjs`](../../.agents/tools/screen-map.mjs); здесь не пересказываются.
2. `node .agents/tools/screen-map.mjs` — собрать `map-data.js` и проверить
   (`--check` — только сверка, `--selftest` — самопроверка). Последняя строка —
   `ВЕРДИКТ: OK | FAIL`.

**Покрытие.** Каждая страница модуля раздела (`pages/*.html`; собранная
`.preview.html` — тот же экран) стоит на карте. Новый экран без узла — КЭ6 с
именем страницы. Шага в гейте нет (решение 11.10.2026): карту проверяет запуск
генератора — после нового экрана модуля его запускают.

**Точка входа одна** — главная проекта (узел без `parent`); остальные узлы
подвешены к странице, с которой на них приходят.

Состояние описывается так:
- другими параметрами адреса (`page`) — обычная ссылка;
- действиями `do` на языке сценариев панели — адрес `#ppmap=<узел>/<состояние>`,
  действия проигрывает панель;
- ссылкой `flow:` на сценарий `flows.yaml` модуля — адрес `#pp=NN`. Если
  состояние уже есть в сценарии, ссылка лучше: селекторы не дублируются.

## Карта другого проекта

1. Запись в `project.json → screenMap.maps`: `id`, `section`, `title`, `desc`,
   `icon`, `after` (id приложения, под чьей записью хаба встанет пункт).
2. `apps/screen-map/<раздел>/map.yaml` и копия `postrade/index.html` с заменой
   раздела и заголовков.
3. `node .agents/tools/screen-map.mjs`, `node .agents/tools/hub-build.mjs`,
   `node .agents/tools/proto-panel.mjs` (включатель узнаёт раздел с картой),
   затем `node .agents/tools/lessons-cli.mjs gate`.

## Проверки

Сторожа экранов (сенсор, линтер, сборщик, README модулей) папку не обходят —
исключение по `screenMap.dir`. Страницу карты проверяет сторож хаба
`registry-check` (П4, П5, П7): запись хаба держит root на папке карты,
`app.json` ей не нужен. Саму карту — `screen-map.mjs`.

## Проверка человеком

Статический сервер из корня проекта: `python3 -m http.server 8765`.

1. `http://localhost:8765/index.html` — в «Проектах» под «Post — ДИД» пункт
   «Карта Post».
2. `http://localhost:8765/apps/screen-map/postrade/index.html` — 8 страниц от
   Главной, каждая открывается с данными. «Состояния» → «Новая сделка» открывает
   окно на портфеле, хардсы транша переключаются, «Сформирован» открывает расчет
   FV `id=16`.
3. `http://localhost:8765/apps/postrade/deals-app/pages/Tranche.preview.html?id=1024&tr=1024.d1.p1.i1.t1`
   → `Alt+Shift+P` → «Screen map»: транш подсвечен, его состояния под ним, клик
   по «Расчет FV» уводит в `post-reports-app`.

## Правила

- `map-data.js` руками не правится; `index.html` и `map.yaml` — руками.
- В папке нет `app.json`, `pages/`, спек — это не приложение.
- Экраны модулей и ДС ради карты не правятся.
