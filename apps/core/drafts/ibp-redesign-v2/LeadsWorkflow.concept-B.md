# LeadsWorkflow — концепт B (Сбалансированный)

## Суть
Единица работы — лид; «Мои проекты» — название рабочего пространства.
Подборка разбирается перед доской, а текущий шаг всегда доступен в компактном плавающем пути.

## Отличия от соседних концептов
| Решение | B | Обоснование |
|---|---|---|
| Единица доски | Лид без новой сущности Проект | Один ID связывает доску, реестр, встречи, задачи и будущую сделку; окончательное решение — человек |
| Рассмотрение | Полоса над рабочими стадиями | Решение о принятии отличается от продвижения взятой работы; это изменение исходного образа, требует выбора |
| Путь | Закреплённая композиция существующих компонентов | Минимальный вариант Popover; без свободного перемещения, ассистента и нового визуального языка |
| Финалы | Свёрнутые колонки | Исходы видны рядом с процессом, подробности — таблица Архива |
| Сегодня | Ссылка на встречи и задачи, без отдельной большой панели | Сохраняет высоту доски; полноценная рабочая лента — вариант C |
| Основания | Текстовые Chip в тонах семейств | Не вводит новые иконки, не меняет внутренности Card |
| Автодвижение | Только после ответа на вопрос 11 | Доменная гипотеза не утверждается выбором визуального концепта |

## Геометрия и приоритет
| Условие | Решение |
|---|---|
| 6 × 288 + 2 × 48 | Трек 1824 px; гарантии «без скролла на FHD» нет: рабочая область около 1816 px или меньше |
| Закреплённое меню / меньшая ширина | Горизонтальный скролл штатного Kanban; ширину карточек не переопределять |
| Подборка | Показывать максимум три карточки одновременно; Показать все ведёт к вкладке Подборка реестра; после разбора полоса сворачивается |
| Высота | `.screen--app`, хост `flex:1; min-height:0`; доска занимает остаток, viewport владеет обоими скроллами |
| Плавающий путь | Ширина ограничена токенами и viewport; ниже FHD по умолчанию свёрнут, на узком окне открывается штатным Drawer |
| Слои | Путь ниже Modal и Drawer, выше контента, отступает от SnackBar; не перекрывает главное действие шапки |
| Детальная страница | По сравнению с таблицей §6.2 ТЗ длинные списки встреч / задач вынесены на 12 колонок; избегаем узких таблиц и пяти рядов одинаково важных тайлов |

## Интеграция и границы
| Область | Решение |
|---|---|
| Источники | Все подтверждённые основания MS0015 §3.1, ссылки на локальные страницы v2 с актуальными именами MS0014a |
| КФЮЛ | Нет объекта в MS0014 — запросить объём, не добавлять фиктивный источник |
| Данные | `leads-store.js` адаптирует данные v2, сохраняет ссылки на оригиналы; стадия / история / чек-листы — одна матрица |
| Несколько оснований | Модель `basis[]` допустима; автоматическое объединение по клиенту и продукту не включать без ответа на вопрос 9 |
| Выход в Pipeline | Проверка §6.3, один объект сделки на лид, связь в обе стороны, повторная передача не плодит сделку |
| Сохранение | Отдельное состояние v2; UI пути — предпочтение интерфейса, не стадия лида |
| Проверка гипотез | Было / стало на данных одной версии; счётчики переходов измерять по сценариям, не выдавать сокращение за доказанный эффект |

## Открытые вопросы
1. Лид или отдельный Проект; несколько оснований — только у одного лида или у группы?
2. Подтвердить стадии и критерии §4, две проведённые встречи или одна колонка, как учитывать третью?
3. Разные исходы «Не беру» / «Клиент отказался», возврат и обязательные причины?
4. Вопросы 4–14 исходной задачи остаются открытыми; выбор B не утверждает автодвижение, критерии передачи или механизм рекомендаций.

## Рекомендация для первого демо
B без добавлений C: единый лид, ручное продвижение, объяснимые причины без
числового скоринга. Стадии и исходы — только после ответа человека.
Для сборки требуется выбрать B и принять либо скорректировать B1–B4.
