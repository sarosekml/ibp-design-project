## 3. Раскладка (Layout)

Layout screen--app → PageHeader (календарь перед неделей, «+ Новый проект») → управление доской (фильтр, Доска / Таблица) → Kanban B2 (5 рабочих + 2 свёрнутых исхода) / Table. Сводка, строка плана квартала и подборка недели закомментированы в HTML и скрипте по решению пользователя; место в раскладке не занимают. Код сохранён для дальнейшей проработки. Компактного режима нет.

Доска — flex:1,min-height:0; прокрутка принадлежит viewport, у колонок её нет. По просьбе пользователя viewport доходит до правой и нижней кромки экрана: отрицательные margin-right / margin-bottom компенсируют только соответствующие токены Layout; поля шапки сохранены. Трек занимает 100% доступной ширины. Открытые колонки делят её поровну через flex:1 1 var(--kb-col-w), свёрнутые сохраняют штатные 48 px. Раскрытие Pipeline или отказа сужает остальные открытые колонки, свёртка расширяет их. Это локальное изменение фиксированной геометрии Kanban ДС по прямому решению пользователя; высота и растяжение по вертикали остаются штатными. Для O открытых и C свёрнутых колонок ширина открытой — (ширина трека − C × 48) / O.

Под каждой колонкой — sticky-итог объёма в млн RUB: паттерн `.pm-colsum` из `apps/pretrade/drafts/pipelineManager-v02/pages/PipelineManagement.html`, локально `.lead-colsum`. Цвета, типографика, отступы — токены ДС. В свёрнутой колонке итог скрыт. Суммируются только отображаемые по фильтру лиды; неизвестные объёмы не оцениваются, их количество показано отдельно.

## 6. Поведение (Behavior)

| Триггер | Результат |
|---|---|
| Беру (из раздела Лиды / карточки лида) | REVIEW → IDEA; отменяемое изменение, лид появляется на доске |
| Перенос | Проверка текущей стадии и критериев; запрещённый перенос отменяется, нужная форма открывается |
| Меню колонки → Свернуть / Развернуть | Штатные DSMenu + DSKanban; открытые колонки сразу перераспределяют ширину трека, состояние сохраняется при фильтре и смене представления в текущей странице |
| Фильтр / изменение лида / перенос | Итог объёма каждой колонки пересчитывается вместе с карточками |
| + Новый проект | Форма создания единого лида; «Проект» — название в главной, дополнительная сущность не вводится |
| Повторная встреча | Действие внутри «Встреча проведена», отдельной колонки нет; незавершённая повторная встреча блокирует переход к документам |
| Назначить / Зафиксировать итоги | Встреча создаётся / завершается; согласованное действие переводит лид, внешнее событие без команды не двигает стадию |
| Клиент отказался / Не беру | Разные исходы, причина, история; возврат доступен |
| Передать | Проверка документов и полей; одна сделка в локальном Pipeline; повторное действие не создаёт дубль |
| Отменить | Восстанавливает данные, стадию и создание сделки одной операцией |
| Путь лида | Свёрнут / раскрыт / скрыт; критерии живые, Esc сворачивает; предпочтение отдельно от данных |

## 8. Состояния (States)

### Загрузка (Loading)
Нет асинхронного запроса: локальные скрипты загружаются последовательно.
### Данных нет (Empty)
EmptyState: в колонке нет лидов, лиды по фильтру не найдены.
### Ошибка (Error)
Неизвестный ID — EmptyState; ошибка формы — пояснение, запрещённый переход — SnackBar.
### Недоступно (Disabled)
Переход / передача disabled при невыполненных критериях; финалы — только возврат или открыть сделку.

При загрузке старого демо состав подборки перераспределяется только среди нетронутых записей; отсутствующие типы добавляются в работу из нетронутого Рассмотрения. Рабочие решения, поля, комментарии, документы и встречи сохраняются; карточек в старом демо может стать больше четырнадцати. Если по типу нет нетронутых кандидатов, он не добавляется в подборку. Повторная загрузка ничего не добавляет. КФЮЛ не выдумывается: источника в адаптере нет.

Старая стадия `MEETING_AGAIN` мигрирует в `MEETING_DONE` при загрузке и восстановлении снимка; идентификаторы, поля, встречи и история сохраняются. Обновлённая последовательность: Рассмотрение → Идея → В проработке → Встреча назначена → Встреча проведена → Подготовка документов → Передано в Pipeline.

## 13. Открытые вопросы и допущения (Open questions)

Текущий объём главной уточнён пользователем: только канбан с управлением. Сводка, план и B1 сохранены в комментариях для дальнейшей проработки; возврат этих блоков требует нового решения о дизайне.

B1–B4 одобрены для прототипа. КФЮЛ и потенциалы РД отсутствуют в адаптере до решения вопроса 10; ссылки не выдуманы. Механизм ранжирования — демонстрационный отбор по плану и зоне ответственности, без бизнес-скоринга. Документы отмечаются флагами, загрузок нет. Возврат из Pipeline сохраняет связь с созданной сделкой. Автодвижение по внешним событиям выключено. Объединение дублей и новый Проект не входят в выбранный первый вариант. Приёмка: статический сенсор и JS-DOM со всеми рантаймами ДС. Фактический overflow, CSS и геометрия требуют ручного браузерного просмотра. Исторические архивы сделок источников сохраняются в режиме Было; Архив единого реестра содержит решения нового процесса. Группы продуктов и их объёмы берутся из источника; неизвестное распределение не выдумывается.
