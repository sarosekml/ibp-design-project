## 3. Раскладка (Layout)

Layout screen--app → PageHeader → Tab → один внешний dtable-toolbar → headless Table dtable--fill. Внутренней шапки «Лиды», счётчика и кнопки группировки по клиенту нет. В тулбаре слева TableFilter; справа выбор источника SegmentControl S, затем «Таблица / По холдингам» с иконками и IconButton M settings, как в Portfolio. TableFilter в общей flex-строке имеет width:auto по содержимому вместо полноширинного значения ДС; соседняя зона flex:1,min-width:0. Лента источников занимает естественную ширину max-content внутри ограниченной прокручиваемой области. Внешнего Tile вокруг таблицы нет. Зазор рабочей области — space-12. Узкая область прокручивает только ленту источников, переключатель вида не сжимается.

Общая матрица содержит пять рабочих стадий; повторные встречи проходят внутри «Встреча проведена».

SegmentControl вида: глиф layout-rows-01 / tree-view и подпись «Таблица / По холдингам» — прямые соседи внутри segctrl__item; внутри текстового слота иконки нет.

## 5. Таблицы (Tables)

| Колонки | Поведение |
|---|---|
| ID, Клиент, Основание, Идея, Объём, Стадия, Почему рекомендован, Приоритет квартала, Ответственный, Появился, Активность | Сортировка data-table/data-sort-rows, resize, предпросмотр; двойной клик — страница |
| История, встречи, задачи | Table с общей геометрией строк; задачи показаны в контексте клиента |

Реестр: 20 строк, Pagination; массовые действия доступны выбранным строкам; «Беру» и «Не беру» — только в Рассмотрении. Таблица / По холдингам — SegmentControl S с подписями и иконками layout-rows-01 / tree-view. По холдингам — родительская строка data-node, дочерние лиды data-parent, TableCell tree и штатный tc__twisty. Заголовок группы начинается после левого сепаратора и занимает сетку до колонки объёма; это расположение не зависит от колонки Клиент. Все ключевые ячейки строки сохраняются для штатных Settings / Resize / Reorder, пустые ячейки группы скрыты атрибутом hidden. После изменения видимых колонок сеточные слоты группы пересчитываются по текущей шапке; скрытие ID или объёма не удаляет название и раскрытие группы. Исходный глиф chevron-right смотрит вправо, при aria-expanded=true штатный CSS поворачивает его вниз. Родитель показывает количество лидов и объём на текущей странице. Пагинация считает лиды, не родительские строки; холдинг может продолжаться на следующей странице. Сортировка штатного Table перемещает корни вместе с потомками; в списке сортируются все строки текущей страницы. Состояние свёртки группы сохраняется при перерисовке и настройке колонок. Фильтры общие для доски и таблицы.

Хедер использует `IBPR_TABLE.headCell`, общий с Pipeline: IconButton S neutral внутри `.th__tools`, глиф `arrow-up-down`, числа вправо. Единица объёма указана в заголовке. После фильтрации/смены вкладки создаётся новый корень .tbl, состав строк обновляется через `rowsChanged()` и настройки восстанавливаются штатным `DSTableSettings.restore`. Кнопка `data-table-settings="#lead-table"`; ключ сохранения `ibp-v2-leads-registry`. Видимость, порядок, ширины, закрепление и сортировка сохраняются через рантайм ДС.

Основания показаны квадратным Chip S (`chip--fit`, без `chip--rounded`) с цветом через штатные слоты `--chip-fill`, `--chip-border`, `--chip-text`, `--chip-icon-color`. Обязательная сделка — красный; возможная сделка — синий; лид ДИД — primary; лид для КМ — зелёный; обязательный лид — оранжевый; возможный лид — розовый; проект CIB — dpurple; кампания продаж — indigo; из встречи — cyan. Только токены ДС. Статусы сохраняют отдельную круглую форму.

## 6. Поведение (Behavior)

| Триггер | Результат |
|---|---|
| Источник | SegmentControl выбирает одно основание; «Все основания» сбрасывает выбор; фокус и навигация стрелками сохраняются |
| Таблица / По холдингам | Те же лиды, плоская таблица либо раскрывающиеся группы холдингов |
| Настроить колонки | Штатное окно TableSettings, применение и восстановление после смены фильтра/режима |
| Беру | REVIEW → IDEA; отменяемое изменение |
| Перенос | Проверка текущей стадии и критериев; запрещённый перенос отменяется, нужная форма открывается |
| Назначить / Зафиксировать итоги | Встреча создаётся / завершается; согласованное действие переводит лид, внешнее событие без команды не двигает стадию |
| Клиент отказался / Не беру | Разные исходы, причина, история; возврат доступен |
| Передать | Проверка документов и полей; одна сделка в локальном Pipeline; повторное действие не создаёт дубль |
| Отменить | Восстанавливает данные, стадию и создание сделки одной операцией |
| Путь лида | Свёрнут / раскрыт / скрыт; критерии живые, Esc сворачивает; предпочтение отдельно от данных |

## 8. Состояния (States)

### Загрузка (Loading)
Нет асинхронного запроса: локальные скрипты загружаются последовательно.
### Данных нет (Empty)
EmptyState: подборка разобрана, лиды по фильтру не найдены, встречи / события отсутствуют.
### Ошибка (Error)
Неизвестный ID — EmptyState; ошибка формы — пояснение, запрещённый переход — SnackBar.
### Недоступно (Disabled)
Переход / передача disabled при невыполненных критериях; финалы — только возврат или открыть сделку.

## 12. Доступность

Tab и три параметрических переключения через рантайм DSTabs (источник, список/холдинги, на главной доска/таблица); один активный tabindex, стрелки/Home/End, подписи иконок. Focus trap Drawer/Modal, сортировка кнопками, текстовые подписи состояний, aria-live стадии. Перенос не требует указателя. Путь можно свернуть / скрыть / вернуть; Esc возвращает фокус.

## 13. Открытые вопросы и допущения (Open questions)

По прямому запросу пользователя в SegmentControl источников десять сегментов (все + девять типов), хотя ДС рекомендует 2–6. Это сохранённое отклонение для сравнения всех оснований в одном ряду; при нехватке ширины есть прокрутка ленты.

B1–B4 одобрены для прототипа. КФЮЛ и потенциалы РД отсутствуют в адаптере до решения вопроса 10; ссылки не выдуманы. Механизм ранжирования — демонстрационный отбор по плану и зоне ответственности, без бизнес-скоринга. Документы отмечаются флагами, загрузок нет. Возврат из Pipeline сохраняет связь с созданной сделкой. Автодвижение по внешним событиям выключено. Объединение дублей и новый Проект не входят в выбранный первый вариант. Приёмка: статический сенсор и JS-DOM со всеми рантаймами ДС. Фактический overflow, CSS и геометрия требуют ручного браузерного просмотра. Исторические архивы сделок источников сохраняются в режиме Было; Архив единого реестра содержит решения нового процесса. Группы продуктов и их объёмы берутся из источника; неизвестное распределение не выдумывается.
