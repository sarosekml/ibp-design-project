# LeadsWorkflow — концепт C (Концептуальный)

## Суть
«Неделя аналитика» объединяет разбор новых возможностей, текущую работу и
ближайшие встречи. Группировка по проекту клиента — отдельная гипотеза для сравнения с единым лидом.

## Состав
| Экран / блок | Чем собран (компонент ДС) | Колонки из 12 | Что внутри |
|---|---|---|---|
| Главная / шапка | PageHeader, SegmentControl | 12 | Неделя, новый лид, Доска / Таблица |
| Главная / сводка | Tile, Entity, ProgressBar | 12 | Компактные показатели недели; показатели квартала подписаны отдельно |

| Главная / Сегодня | Entity, Tile, Chip [ПРЕДЛОЖЕНИЕ C2] | 4 | Ближайшие встречи и задачи, срок, связанный лид; после разбора блок сворачивается |

## Отличия от соседних концептов
| Решение | C | Цена / риск |
|---|---|---|
| Разбор | Один лид с причинами вместо полосы кандидатов | Лучше для сосредоточенного решения, хуже для быстрого сравнения всей десятки |
| Сегодня | Встречи и задачи на главной | Дополнительная высота; после разбора очередь сворачивается, доска остаётся главным блоком |
| Проект клиента | Новая группировка лидов | Нужна модель стадии проекта, участников и передачи; до ответов допустим только сравнительный текст |
| Проводник | Самостоятельный новый виджет | Больше свободы и больше обязательной проверки поведения, слоёв и доступности |
| Автодвижение | Показывается как гипотеза, с событием и отменой | Включается только после ответа на вопрос 11; выбор C сам по себе не разрешает автоматические переходы |
| Ассистент | Только явно обозначенная демонстрация подсказки | Не изображать работающий AI, бизнес-прогноз или интеграцию с сервисом |

## Геометрия и доступность
| Условие | Решение |
|---|---|
| Доска | Колонки по 288 px, исходы по 48 px; горизонтальный скролл при нехватке ширины, таблица доступна всегда |
| Разбор / Сегодня | 8 + 4; на меньшей ширине становятся последовательными, Сегодня сворачивается |
| Проводник | Не перекрывает SnackBar и главное действие; на узком окне открывается штатным Drawer |
| Клавиатура | Все решения доступны кнопками, без обязательного жеста; Esc сворачивает проводник, фокус возвращается |
| Автоматическое событие | Текст «что произошло / почему / как отменить», aria-live; никакого движения без объяснения |

## Предложения к расширению ДС
| Название | Что предлагается | Почему в ДС нет | Ближайший аналог в ДС | Что нужно, чтобы стало компонентом |
|---|---|---|---|---|
| C1 — Разбор кандидатов | [ПРЕДЛОЖЕНИЕ] Новый режим просмотра по одному, очередь и быстрые решения | Нет паттерна разбора подборки | Tile, Buttons, Popover | Поведение очереди, сравнение, отмена, EmptyState, a11y |
| C2 — Сегодня | [ПРЕДЛОЖЕНИЕ] Составной блок ближайших действий по лидам | Отдельные встречи и задачи не образуют такой блок | Entity, локальные MyDayTile / HomeTasksTile | Ссылки на реальные данные, сортировка, компактность и отдельный паспорт; без копирования рендера |
| C3 — Восемь колонок с исходами | [ПРЕДЛОЖЕНИЕ] 6 рабочих + 2 свёрнутые | Ограничение Kanban 3–7 этапов | Kanban `.kbcol--collapsed` | Проверка ширины, клавиатуры и переключения в таблицу |
| C4 — Карточка группы лидов | [ПРЕДЛОЖЕНИЕ] Новый вид карточки проекта клиента | У карточки доски сейчас один объект | Kanban, Tile, Drawer, Table | Сначала доменная модель проекта; потом анатомия и раскрытие группы |
| C5 — Сравнение дублей | [ПРЕДЛОЖЕНИЕ] Композиция сравнения перед объединением | Нет паттерна сравнения оснований | Modal, Entity, Table | Сначала критерии дубля от человека; затем сохранение истории и возможность отмены |
| C6 — Лента событий | [ПРЕДЛОЖЕНИЕ] Общая лента стадий, встреч и задач | Ленты нет | Entity, TaskHistoryTable | Словарь событий, причина / автор / время, группировка и длинные тексты |
| C7 — Проводник лида | [ПРЕДЛОЖЕНИЕ] Самостоятельная пристыкованная панель с пилюлей | Нет непривязанного немодального проводника | Popover, StepMarker, Tile | Анатомия, три состояния, persistence, слои, Esc, aria-live, один на страницу |
| C8 — Демо-подсказка | [ПРЕДЛОЖЕНИЕ] Подсказка со ссылкой на данные и подтверждением | Нет такого паттерна | Note, Buttons | Явная маркировка демо, никаких выдуманных данных или автоматических действий |

## Интеграция и границы
| Область | Условие |
|---|---|
| Источники | Все основания с реальными объектами из MS0014; КФЮЛ — только после решения вопроса 10 |
| Проект | Не создаётся как факт модели до ответа человека; альтернативой остаётся лид с несколькими основаниями |
| Передача | Один конкретный лид → одна сделка; запрет повторного создания при повторном клике |
| Было / стало | Все переходы внутри v2, исходная версия v1 не изменяется |
| Подборка | Факторы из исходных данных; числовой скоринг не выдумывается |

## Открытые вопросы
1. Нужен ли отдельный Проект; что определяет его стадию, если внутри несколько лидов на разных стадиях?
2. Финальный список стадий, встреч и критериев; может ли третья встреча вернуться в предыдущую стадию?
3. Различие «Не беру» / отказ клиента, возврат и причины?
4. Кто владеет проектом, встречами и задачами группы, что передаётся в Pipeline?
5. Допустимо ли автодвижение и как трактовать исправление / отмену встречи?
6. Критерии дубля и сохранение истории после склейки; остальные вопросы — MS0015 4–14.
