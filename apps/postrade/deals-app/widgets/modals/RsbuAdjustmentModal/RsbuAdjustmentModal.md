# Модальное окно внесения корректировки

## Описание (Purpose)

Артефакт тайла «Корректировки процентов РСБУ». Не компонент: сам по себе не существует и в плоском
списке кита его нет — он принадлежит своему тайлу и живёт под-пунктом его навигации. Заголовок окна —
«Новая корректировка» при внесении и «Редактирование корректировки» при правке, форма одна.

Корректировка — сумма, плюс или минус, которая прибавляется или вычитается начиная с «Исходной даты»;
«Целевая дата» после сохранения попадает в список дат начисления процентов. Данные влияют только на
отчёт РСБУ.

Транш и таблицу окно не знает: параметры списка берёт у страницы, проверенную запись отдаёт ей же
(`PostModalRsbuAdjustment.bind(scrim, { options, save })`, `RsbuAdjustmentModal.js`). Страница добавляет
или правит строку и показывает тост.

## Раскладка (Layout)

```
Modal w4 (заголовок «Новая корректировка» / «Редактирование корректировки», IconButton L «Закрыть»)
├── modal__alert — Alert error (скрыт, пока ошибки нет)
├── тело — форма в одну колонку
│   ├── ряд из двух колонок: «Исходная дата» (Select + DropdownList) · «Целевая дата» (InputDate)
│   ├── «Сумма корректировки» — InputAmount, постфикс — код валюты
│   └── «Комментарий» — InputText multiline
└── подвал: «Отменить» (transparent) · «Добавить» / «Сохранить» (accent)
```

Ширина — `modal--w4`. Раскладку формы (колонка и ряд из двух дат на токенах отступов) задаёт
`RsbuAdjustmentModal.css`, остальное — Modal.

## Поля (Fields)

| Поле | Чем собрано | Источник значений | Обязательное |
|---|---|---|---|
| Исходная дата | Select + DropdownList, крестик очистки | даты процентных платежей — из другого тайла; в прототипе статичный перечень (`startDateOptions`) | да |
| Целевая дата | InputDate, ручной ввод | любая дата `ДД.ММ.ГГГГ`, вводится руками | да |
| Сумма корректировки | InputAmount, постфикс — код валюты | любая сумма в валюте инструмента, со знаком «-» для вычитания | да |
| Комментарий | InputText multiline | свободный текст | нет |

Поле «Исходная дата» только для выбора; набранный руками текст принимается, если совпал с датой списка,
иначе откат к выбранной. Сумма форматируется при вводе: разряды неразрывным пробелом, запятая, не более двух знаков.

## Обязательность заполнения (Required)

- Окно обязательно к заполнению целиком: нет.
- Обязательные поля внутри: «Исходная дата», «Целевая дата», «Сумма корректировки»; комментарий необязателен.
- Что показывает, когда обязательное не заполнено: Alert «Выберите исходную дату, введите целевую дату в формате ДД.ММ.ГГГГ и сумму корректировки числом.» и красные поля.
- Что отдаёт наружу: запись `{ startDate, endDate, adjustmentAmount, comment }` (даты ISO) — странице (`save`).

## Переполнение (Overflow)

| Случай | Правило |
|---|---|
| Длинный текст в поле | Комментарий — многострочное поле; прочие значения короткие |
| Много строк или записей | Не встречается: одна корректировка |
| Узкая ширина | Не встречается: ширина окна фиксирована шагом ДС |
| Полная ширина | — |

## Поведение (Behavior)

1. «Добавить» / «Сохранить» проверяют форму:
   - не заполнены даты или сумма — «Выберите исходную дату, введите целевую дату в формате ДД.ММ.ГГГГ и сумму корректировки числом.»;
   - целевая дата раньше исходной — «Целевая дата не может быть раньше исходной.»;
   - сумма равна нулю — «Сумма корректировки не может быть равна нулю.»
2. С ошибкой окно остаётся открытым, ошибка — в Alert вверху окна, поля подсвечены; правка поля снимает подсветку.
3. Без ошибки запись уходит странице, окно закрывается, страница показывает тост «Корректировка добавлена» или «Корректировка изменена».
4. «Отменить», крестик и Esc закрывают окно без сохранения.
