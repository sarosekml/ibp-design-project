# Модальное окно сроков сделки

## Описание (Purpose)

Артефакт тайла «Сроки сделки». Не компонент: сам по себе не существует и в плоском списке кита
его нет — он принадлежит своему тайлу и живёт под-пунктом его навигации. В ките и документации
оно называется «Модальное окно сроков сделки», заголовок самого окна — «Сроки сделки».

Окно решает одну задачу: ввести дату первой выдачи. Её вводят вручную, когда в сделке есть
инструмент НКЛ с баланса ПАО: его выдачи хранятся в стороннем сервисе, а не в системе. Дата
заключения и дата окончания приходят из инструментов сделки и стоят в окне только для справки —
по ним видно допустимый диапазон. У каждого поля информер: что это за поле и откуда данные.

Даты окно не хранит и сделку не знает: при каждом открытии берёт их у страницы, проверенную
дату отдаёт странице (`PostDealTermsModal.bind(scrim, { get, save })`,
`DealPeriodModal.js`). Страница сделки пишет дату в `DealsStore` и перерисовывает тайл.

## Раскладка (Layout)

```
Modal (заголовок «Сроки сделки», IconButton L «Закрыть» в шапке)
└── тело
    ├── «Дата заключения» · «Дата окончания» — ReadOnlyField в один ряд, две колонки
    │   (штатная сетка ДС `.grid12`, ширина колонки `.col-6`, зазор 16px)
    └── «Дата первой выдачи» — InputDate M во всю ширину (прямой ребёнок `.modal__body`,
        в ДС это колонка с тем же зазором)
Подвал — `.modal__foot`: кнопка «Сохранить» accent (`data-terms-save`). Без
`data-modal-close`: окно закрывает скрипт, когда проверка прошла
```

Порядок полей — как в тайле; лейблы в колонках переносятся до двух строк
(`ds-label--wrap`). Ширина — `modal--w3`, 3 колонки (решение человека 22.09.2026).
Высота — по контенту. Своего CSS у окна нет.

## Поля (Fields)

| Поле | Чем собрано | Источник значений |
|---|---|---|
| Дата заключения | ReadOnlyField, информер `info-circle` справа | инструменты сделки — самая ранняя дата заключения договора |
| Дата окончания | ReadOnlyField, информер `info-circle` справа | инструменты сделки — самая поздняя дата, по последнему плановому платежу |
| Дата первой выдачи | InputDate M, действие-информер «Подсказка» | ручной ввод — при инструменте НКЛ с баланса ПАО |

Информеры: у ReadOnlyField — иконка `.rof__icon` `info-circle` с тултипом
(`data-tooltip`, `data-tooltip-multiline="yes"`, фокус с клавиатуры — `tabindex="0"`); у
InputDate — действие-информер `inp__act--static` «Подсказка» первым в ряду действий
(порядок ДС: информер → крестик → календарь). Цвет обоих — `--secondary`, его задают
компоненты ДС (ReadOnlyField 1.009).

Крестик очистки в разметке не пишется: он живёт по значению, и рисует его рантайм
`Inputs.js` — между информером и календарём, ровно когда в поле есть что стирать.
Нарисованный руками, он висел бы и на пустом поле. Значение окно ставит кодом, поэтому
после заполнения зовёт `DSInput.sync` (присваивание `.value` событий не шлёт — правило
InputText 1.014). С 23.09.2026; до этого крестик стоял в разметке.

Начальный фокус — поле «Дата первой выдачи»: рантайм окна ДС (Modal 1.009) ставит фокус
на первое поле ввода тела, а не на информер первого поля, — окно открывается без поднятой
подсказки.

Текст информера — одно предложение: что это за дата и откуда она. Процесс (когда
заполняется, от чего сдвигается) в подсказку не выносится — для этого есть документация
(решение человека 22.09.2026). Тексты информеров (черновик, согласовать на витрине):

| Поле | Текст |
|---|---|
| Дата заключения | Самая ранняя дата заключения договора среди инструментов сделки |
| Дата окончания | Самая поздняя дата среди инструментов сделки — по последнему плановому платежу |
| Дата первой выдачи | Заполняется вручную, если в сделке есть НКЛ с баланса ПАО (подробности в подсказке не нужны — решение человека 22.09.2026) |

## Обязательность заполнения (Required)

- Окно обязательно к заполнению целиком: нет — правится одна дата, две другие стоят для справки.
- Обязательные поля внутри: нет — дату первой выдачи можно стереть и сохранить пустой
  (решение человека 22.09.2026).
- Что показывает, когда обязательное не заполнено: не применимо — обязательных полей в окне нет.
- Что отдаёт наружу: дату первой выдачи — странице (`save`), она пишет её в `DealsStore` и
  перерисовывает тайл.

## Поведение (Behavior)

### Правила состава и проверки

1. Правится только «Дата первой выдачи». Две другие даты — ReadOnlyField: их не правят и здесь,
   они приходят из инструментов.
2. Пустая дата для справки — прочерк, поле с места не уходит.
3. Дату первой выдачи можно стереть и сохранить пустой (решение человека 22.09.2026).
4. Непустая дата проверяется по «Сохранить»:
   - не дата `ДД.ММ.ГГГГ` (в том числе несуществующий день) — «Введите дату в формате ДД.ММ.ГГГГ»;
   - раньше даты заключения — «Не раньше даты заключения — <дата>»;
   - позже даты окончания — «Не позже даты окончания — <дата>».
   Границы включительно. Если даты заключения или окончания нет, эта граница не проверяется.
5. Ошибка — по правилу InputText: поле красное (`inp--error`, `aria-invalid`), текст — в тултипе
   на фокусе поля, не в хелпере. Окно с ошибкой не закрывается, фокус уходит в поле.
6. Правка поля пересчитывает уже показанную ошибку и снимает её, как только ввод стал верным.
   Новая ошибка появляется только по «Сохранить» — пока дату набирают, поле не краснеет.
7. Маска `ДД.ММ.ГГГГ` и календарь — из коробки ДС (InputDate, DatePicker).
