# Окно «Продукты» (ProductsModal)

## Описание (Purpose)

Окно выбора продуктов одного продукта ДИД. Открывается кнопкой ⊕ «Добавить продукт» у
продукта ДИД в тайле «Продукты сделки». В заголовке — номер и название этого продукта ДИД:
«1. Кредитный мезонин».

Две колонки. «Доступные продукты» — каталог продуктов, которые можно добавить в этот
продукт ДИД, без номеров. «Выбрано» — продукты его ветки: у сохранённых — номер по месту в
дереве, у добавленных в окне номера нет, он появится после «Сохранить» (ответ человека
30.09.2026, 24). Строку переносят в соседнюю колонку кнопкой ⇄ или двойным кликом.

Перенос вправо добавляет продукт со всеми его обязательными инструментами (ответ 15).
Перенос влево убирает продукт из ветки вместе с инструментами: сохранённый — после
подтверждения «Подтвердите действие», добавленный в окне — сразу (ответы 20, 25).
Продукт можно выбрать повторно — левая колонка не убывает (ответ 14).

Обязательный продукт продукта ДИД выбран заранее. Пока он единственный в ветке, строка
выключена: убрать его нельзя. Когда в ветке появляется другой продукт, обязательный можно
убрать — так на макете: «убрать его можно только если добавить другой продукт вместо
первого». Выключена и строка продукта, у которого инструмент или транш прикреплён к ФИ.

Правки идут в черновик. «Сохранить» применяет их к дереву сделки и сохраняет, тайл
перерисовывается. Крестик, Esc и клик по подложке закрывают окно без сохранения, дерево
остаётся прежним.

В этом же файле — общий слой двух колонок `PostProductPicker`. На нём стоят и окна
«Продукты ДИД» (`DidProductsModal`) и «Инструменты» (`InstrumentsModal`): строки, номера,
перенос, подтверждение, черновик и состояния одни на три окна. Окна отличаются только
списками и тем, что делает перенос; во фронтенде это три отдельных виджета (решение
человека 30.09.2026).

Место на странице задаёт страница: скрим вшивается отдельной меткой `<ds-include>` в конце
`body`.

## Раскладка (Layout)

```
Modal modal--w7 (1053px на 1920 — ширина макета), высота 60vh
├── шапка: заголовок «N. <продукт ДИД>» + крестик
├── тело без полей (modal__body--flush)
│   ├── колонка «Доступные продукты»: заголовок H6 Strong + список ProductRow
│   ├── Divider вертикальный (от шапки до подвала)
│   └── колонка «Выбрано»: заголовок H6 Strong + подсказка пустой колонки + список ProductRow
└── подвал справа: Button accent M «Сохранить»
```

Строка в колонке — ProductRow в одну линию (48px): название, справа IconButton L ⓘ
«Описание продукта» (подсказка — описание продукта) и ⇄ «Переместить». Строки через 8px.
Колонки равной ширины, у каждой свой скролл с полосой ДС `.ds-scroll`; заголовки колонок
не прокручиваются.

| Состояние | Когда | Вид |

## Обязательность заполнения

- Окно обязательно к заполнению целиком: нет.
- Обязательный продукт продукта ДИД приходит с продуктом ДИД и выбран заранее. Убрать его
  можно, только когда в ветке есть другой продукт (правило стора, `canRemove`).
- Что отдаёт наружу: после «Сохранить» — производные поля записи сделки
  (`productsNames` и другие), стор переносит их в `DealsStore` и сохраняет дерево.

## Переполнение

| Случай | Правило |
|---|---|
| Длинное название | переносится по словам, не усекается (ProductRow); строка растёт по высоте |

| Узкая ширина | ширина окна фиксирована шкалой Modal (`modal--w7`); своих брейкпоинтов нет |

### Скрипт окна

`ProductsModal.js`:

| Глобал | Функция | Что делает |
|---|---|---|
| `PostProductPicker` | `rowHTML(item, cfg)` | разметка строки колонки: `item = { key, name, number, description, main, disabled }`; номер показывается, если ключ есть в `cfg.numbered` |
| | `bind(scrim, cfg)` | общий слой окна выбора: номера у сохранённых до открытия, перенос кнопкой и двойным кликом, подтверждение у сохранённых, черновик (`begin` при открытии, `commit` по «Сохранить», `rollback` при любом другом закрытии), `data-state`, классы сохранения, возврат фокуса после переноса. Возвращает `{ open, repaint, use, root }` |
| | `mirror(scrim)` | `data-state="updating"` → `.modal--saving` на окне и `btn--loading` на «Сохранить»; снято — классы убраны. Окно, связанное `bind`, зовёт это само по смене `data-state`; копии витрины — явно, так правило одно |
| `PostModalProducts` | `open(didId)` | открыть окно для продукта ДИД |
| | `use(didId)` | нарисовать окно без открытия — для витрины |

Окно слушает событие тайла `ptreeaction` на документе: action `ADD` у узла `kind: 'DID'`.
Правила («что доступно», «можно ли убрать», нумерация, обязательные инструменты) — в
`ProductTreeStore`, окно их не дублирует.
