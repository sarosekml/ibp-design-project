# Финансовые метрики сделки

## Описание

Тайл страницы сделки: во что вложена сделка и какой под неё резерв. Сверху —
**ВБС** сделки на дату в разрезе продуктов:
AllocationBar ДС — итог, полоса распределения и строки с долей и суммой. Под
ним — резерв, обесценение и RWA. У сделок с Private Equity внизу — итог
переоценки по PE.

Это сводка. ОСЗ, резервы по каждому ФИ и
переоценка по каждому ФИ — в окне «Финансовые метрики сделки»
(`DealFinancialMetricsModal`), оно открывается действием «Развернуть».

Метрики считает система — в тайле их не правят ни в каком режиме, ни одной
ролью (макет: «Редактирование недоступно»).

Место на странице и ширина в колонках задаются экраном
(`apps/postrade/deals-app/pages/Deal.html`), не компонентом. Значения приходят из
метрик сделки (`apps/postrade/deals-app/data/mock-financial-metrics.js`,
`DealFinancialMetricsRsDto`); рисует их `DealFinancialMetricsTile.js`
(`PostTileDealFinMetrics.render`).

## Поля

В порядке отображения. Источник у всех — метрики сделки: они складываются из
финансовых инструментов сделки (суммы ВБС по продуктам — по ФИ, резерв и
ставки — по ФИ, переоценка по PE — по ФИ с PE). В прототипе значения — демо
(`data/mock-financial-metrics.js`), с деревом ФИ сделки не связаны; привязка
к бэкенду и мок-данным ФИ — следующий шаг (решение человека 25.09.2026).

**Итог над баром ВБС — сумма значений его строк** (решение человека
25.09.2026): своего поля итога в данных нет, его считает
`DealFinancialMetricsTile.js`. Поэтому доли строк всегда дают 100%, и
состояний AllocationBar «сумма меньше / больше итога» у тайла не бывает.

| Поле | Смысл | Тип, единица | Источник | Обязательное |
|---|---|---|---|---|
| ВБС по сделке на {дата} | ВБС сделки на дату расчёта: разбивка по продуктам (доля, сумма) и итог — сумма строк | AllocationBar: итог и суммы — деньги, 2 знака; доли — %, 2 знака. Строка — колонки 50 / 20 / 30% (наименование · доля · сумма), значения друг под другом | `vbs.items` | да |
| Сумма резерва | Резерв по сделке | деньги, 2 знака, постфикс — код валюты | `reserves.reserveAmount` | нет, прочерк |
| Ставка резерва | Ставка резерва | %, без лишних нулей («62 %») | `reserves.reserveRate` | нет, прочерк |
| RWA | Взвешенные по риску активы | % | `reserves.rwa` | нет, прочерк |
| Ставка обесценения | Ставка обесценения | % | `reserves.impairmentRate` | нет, прочерк |
| Переоценка по PE | Итог переоценки по Private Equity на дату последней оценки и её изменение (Δ) | деньги, 2 знака; Δ — со знаком, зелёным (рост) или красным (падение) | `peRevaluation` | только у сделки с PE |

**Продукты ВБС и их цвета** — постоянные: цвет привязан к продукту, а не к
месту в списке, поэтому «Акции» в любой сделке одного цвета (макет «Привязанные
к легенде цветовые стили», доменный маппинг из спеки AllocationBar):

| Продукт | Код | Цвет |
|---|---|---|
| Кредит | `LOAN` | `--ch-indigo` |
| Фондирующий кредит | `LOAN_LIABILITY` | `--ch-pastel-green` |
| Внутригрупповой кредит | `INTRA_GROUP_LOAN` | `--ch-blue` |
| РЕПО | `REPO` | `--ch-light-blue` |
| Акции | `SHARES` | `--ch-shiny-green` |
| Облигации | `BONDS` | `--ch-turquoise` |
| Корп. контроль | `CORPORATE_CONTROL` | `--ch-red` |
| Доп. доходность | `ADD_INCOME` | `--ch-orange` |
| Комиссия | `COMMISSION` | `--ch-yellow` |
| Дебиторская задолженность | `ACCOUNTS_RECEIVABLE` | `--ch-purple` |

**Пояснения у подписей** — IconButton `info-circle` в подписи поля, тултип ДС в
несколько строк; тексты с макета «Текст тултипов»:

| Поле | Текст |
|---|---|
| Сумма резерва | Общая сумма по кредитным ФИ |
| Ставка резерва | Среднее значение по кредитным ФИ |
| RWA | Среднее значение по всем ФИ |
| Ставка обесценения | Общая сумма по всем кредитным ФИ для «Типа учета» = «FV» |

Валюта — кодом (`RUB`): в подписи бара «ВБС по сделке на 25.02.2026, RUB», в
постфиксе суммы резерва, в плашке PE. На макете в подписи бара «руб.» — см.
«Осознанные отклонения».

## Права

| Роль | Просмотр | Редактирование |
|---|---|---|
| Финансист ДИД | да | нет — метрики считает система |

Режим `data-mode` у тайла всегда `view`: действий правки у него нет ни при какой
роли и статусе. Действие шапки одно — «Развернуть» (окно на просмотр); это не
правка, поэтому оно есть и в просмотре.

### Свои состояния

| Состояние | Вид |
|---|---|
| ВБС рассчитывается (`vbs.calcStatus = CALCULATING`) | в месте бара — подпись без итога и плашка ДС «Данные рассчитываются / Это может занять несколько секунд» (макет «Состояния лайн чарта»). Поля и плашка PE показываются как обычно |
| Сделка с PE (`data-pe="yes"`) | внизу — плашка «Переоценка по PE, RUB», дата «на {дата последней оценки}», справа сумма и Δ. Без PE плашки нет совсем: пустая плашка читалась бы как «переоценки нет» |

## Обязательность заполнения

- Компонент обязателен к заполнению целиком: не применимо — значения считает
  система, пользователь их не вводит.
- Обязательные поля внутри: не применимо.

## Переполнение

| Случай | Правило |
|---|---|
| Длинный текст в поле | значения — числа ограниченной длины; при усечении ReadOnlyField показывает полное значение тултипом. Длинное имя продукта в баре усекает AllocationBar |
| Много строк или записей | в баре больше пяти продуктов — первые пять и кнопка ДС «Показать ещё N», по ней видны все (правило AllocationBar). Продуктов не больше десяти — их список постоянный |
| Узкая ширина | бар перестраивается по своим контейнерным брейкпоинтам ДС. Поля: уже 420px ширины тайла — две колонки, «Сумма резерва» на всю строку (`@container`) |
| Полная ширина | поля в три колонки 2 : 1 : 1, «Ставка обесценения» — вторым рядом. Бар растянут (`albar--stretch`): шапка, полоса и строки во всю ширину, суммы стоят под итогом (AllocationBar 1.003) |

## Осознанные отклонения

| Правило | Как сделано | Почему |
|---|---|---|
| Ошибка в компоненте — причина и повтор запроса (правила локальных компонентов; спека AllocationBar — Alert и кнопка «Повторить») | только Alert «Не удалось загрузить данные», без кнопки | как на макете «Состояния лайн чарта» (решение человека 25.09.2026). Повторить запрос можно перезагрузкой страницы |
| AllocationBar: медленная загрузка — скелетон итога и полосы плюс плашка «Данные рассчитываются» | подпись без итога и плашка, без скелетонов | как на макете «Состояния лайн чарта» |
| Валюта — кодом (сенсор Б26) | «RUB» в подписи бара | на макете «руб.»; код валюты — правило проекта |
| Пустота в компоненте шире четырёх колонок собирается EmptyState | строка «Нет данных» без иллюстрации | тайлы страницы сделки стоят в минимальной высоте 200px (решение человека 21.09.2026), EmptyState с иллюстрацией растянул бы ряд; на макете в этом состоянии тоже одна строка. Действия нет — метрики не заполняют руками |

## Открытые вопросы

1. Владелец компонента — `не решено (19.09.2026)`.
2. Состав ролей с правом видеть метрики — `не решено (25.09.2026)`.
3. Плашки «Переоценка по PE» в ДС нет — собрана на токенах (`--bg-page`,
   `--radius-control`, цвет Δ — `--success-dark` / `--error-dark`, как у
   ReadOnlyField).
4. Дата в плашке PE — дата последней оценки. На макете даты тайла
   (21.01.2026) и окна (21.12.2025) не совпадают; взята дата окна.
5. Состояние «Обновление» — `не решено (25.09.2026)`: метрики в прототипе не
   пересчитываются.
6. Расшифровки ВБС и ОСЗ для описания — `не решено (25.09.2026)`, у владельца
   продукта; на макетах только аббревиатуры.
7. Привязка к данным — следующий шаг (решение человека 25.09.2026): значения
   считать из финансовых инструментов сделки — бэкенд и мок-данные ФИ
   (`data/mock-deal-trees.js`), а не отдельный файл демо-метрик.

Закрыты 25.09.2026 правкой ДС: строки растянутого бара больше не ограничены
600px, у строки бара есть пара `[hidden]` (AllocationBar 1.003).
