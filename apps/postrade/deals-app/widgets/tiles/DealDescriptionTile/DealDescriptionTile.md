# Widget: DealDescriptionTile — Описание сделки

## Описание (Purpose)

Тайл страницы сделки: о чём сделка и по каким правилам её ведут. Сверху — суть
сделки свободным текстом и комментарий Operations, ниже — признаки сделки на
подложке и группа связанных заемщиков. Всё, что видно в тайле, правится в одном
окне; дополнительные доходы тайл не показывает — они видны только в окне (так на
макете).

Признаки — не поля ввода, а короткие строки «иконка + текст»: значение несёт
иконка (отмечено / нет, тон категории риска), текст подписывает признак. У двух
признаков текст несёт и значение: «Категория риска ЦУП: C», «Совместность: МБ».

Кроме правки у тайла два входа в соседние данные: «Документы ЭКД по сделке» в
шапке — документы участников сделки, ссылка «Связанные сделки» — список
связанных сделок клиента (строка есть, только когда связанные сделки есть).

Место на странице и ширина в колонках задаются экраном (`pages/Deal.html`), не
компонентом. Значения приходят из записи сделки (`data/deals-store.js`, typedef
`DealDescriptionFields` в `data/mock-deals.js`).

## Поля

Порядок строк — порядок отображения. Источник у всех один — запись сделки.

| Поле | Смысл | Тип, единица | Источник | Обязательное |
|---|---|---|---|---|
| Суть сделки | О чём сделка — свободный текст | строка | `deal.description` | нет |
| Комментарий Operations | Комментарий сопровождения | строка | `deal.operationsComment` | нет |
| Категория риска ЦУП | Категория риска по оценке ЦУП | код A · B · C · D · UNDEFINED; в тайле — «Категория риска ЦУП: C», «…: не определена», нет значения — «…: отсутствует»; в окне — «Категория A» … «Категория D», «Не определена» | `deal.riskCategory` (`DEALS_ENUMS.riskCategory`) | нет |
| Участие Деска ИФ | Участвует ли деск ИФ | да / нет | `deal.ifDeskParticipation` | нет |
| Участие ЦЭ | Участвует ли ЦЭ | да / нет | `deal.ceParticipation` | нет |
| Реструктуризация | Сделка реструктурирована | да / нет | `deal.restructured` | нет |
| Связанные сделки | Есть ли у сделки связанные сделки клиента | список; строка признака только у непустого списка | `deal.relatedDeals` — приходит из системы, в окне не правится | — |
| Совместность | С каким территориальным банком ведётся сделка | код банка: ЦА, ЦЧБ, УБ, МБ, ЮЗБ, СРБ, ВВБ, СБ, ПВБ, СЗБ, ДБ (полные имена — `DEALS_ENUMS.jointnessNames`, в окне хелпером); нет — «отсутствует» | `deal.jointness` (`DEALS_ENUMS.jointness`) | нет |
| Фин.расчеты в шаблоне | Сделка ручная: расчёты ведутся в Excel, а не в системе | «Да» / «Нет» | `deal.finTpl` | нет |
| Группа связанных заемщиков | ГСЗ, в которую входит клиент | строка из справочника | `deal.gsz` (`DEALS_ENUMS.gsz`) | нет |

`gsz`, `jointness` и `finTpl` — поля реестра «Текущий портфель ДИД»: их же
показывает таблица и фильтр портфеля (`refs/Текущий портфель.md`). Остальные
добавлены 24.09.2026 вместе с тайлом. Незаполненное текстовое поле — прочерк,
поле с места не уходит.

### Признаки

Значение признака — иконка (пояснения макета). Иконка по умолчанию —
`--secondary`; тон — только там, где он несёт смысл.

| Признак | Значение | Иконка | Тон |
|---|---|---|---|
| Категория риска ЦУП | A | `alert-triangle-filled` | `--error` |
| | B | `alert-triangle-filled` | `--warning` |
| | C | `alert-triangle-filled` | `--success` |
| | D | `alert-triangle-filled` | `--text-primary` (тёмный) |
| | отсутствует · не определена | `circle` | — |
| Участие Деска ИФ · Участие ЦЭ · Реструктуризация | да | `check-circle-filled` | — |
| | нет | `circle` | — |
| Совместность | банк | `link` | — |
| | отсутствует | `circle` | — |
| Фин.расчеты в шаблоне | да | `bar-chart-square` | `--warning` |
| | нет | `circle` | — |

Смысл категорий риска (пояснение макета): A — сделка с повышенным риском,
требуется регулярный анализ; B — потенциально рисковая, требуется экспертная
оценка; C — высоких рисков нет; D — венчурное финансирование или Residential RE,
дифференцированный подход к мониторингу. Пояснения видны в окне правки под
вариантами списка.

## Права (Permissions)

| Роль | Просмотр | Редактирование |
|---|---|---|
| Финансист ДИД | да | не решено (19.09.2026) |

Режим прав приходит на компонент атрибутом `data-mode` — его ставит страница
сделки:

| `data-mode` | Что в шапке |
|---|---|
| `edit` | «Документы ЭКД по сделке» и IconButton «Редактировать» — окно на правку |
| `view` | «Документы ЭКД по сделке» и IconButton «Развернуть» — то же окно на просмотр |

Статус сделки сильнее роли: в статусах «Активная», «Погашена», «Ожидает
подтверждения» и «Подтверждение изменений» страница ставит `view` при любой роли
(`DealsStore.isEditable`, решение человека 21.09.2026).

**Почему в просмотре действия остаются.** «Документы ЭКД» и «Развернуть» — не
правка. Документы смотрят при любом режиме, а окно в просмотре — единственное
место, где видны дополнительные доходы и полный текст длинного описания.

## Состояния (States)

| Состояние | Есть в продукте | Вид |
|---|---|---|
| Загрузка (Loading) | да | скелетоны в габаритах итогового содержимого: две строки описания, подпись и значение комментария, блок подложки признаков, подпись и значение ГСЗ; действий в шапке нет |
| Данные есть | да | суть, комментарий, признаки и ГСЗ заполнены (макет, «Заполнено») |
| Заполнено частично | да | та же раскладка; незаполненное текстовое поле — прочерк цветом обычного текста (ReadOnlyField 1.010), признак без значения — пустой круг |
| Данных нет (Empty) | да | в окне правки не заполнено ничего и не отмечен ни один признак. С правом правки — accent-кнопка «Заполнить» слева вверху тела; без права — строка «Не заполнено» серым Body M. «Документы ЭКД по сделке» в шапке есть в обоих случаях, карандаша и «Развернуть» нет (макет, «Не заполнено»). Без иллюстрации — «Осознанные отклонения» |
| Ошибка (Error) | не решено (24.09.2026) | |
| Обновление | не решено (24.09.2026) | |
| Редактирование доступно | да | карандаш в шапке и «Заполнить» в пустом тайле открывают окно на правку; после сохранения тайл показывает новые значения (перерисовка по событию стора) |
| Только просмотр | да | состав и порядок полей те же; вместо карандаша — «Развернуть», окно на просмотр |
| Правка временно запрещена (Disabled) | нет | запрет по статусу сделки — тот же «Только просмотр» (правило модуля, `widgets/README.md`) |
| Нет права видеть | не решено (19.09.2026) | |

Что считается пустым тайлом: пусты суть, комментарий, дополнительные доходы, ГСЗ,
совместность и категория риска, сняты все четыре галочки окна. Связанные сделки
на это не влияют — они приходят из системы, а не заполняются.

Демо на странице сделки: 1024 — данные есть, просмотр, три связанные сделки;
1027 — данные есть, правка, длинное описание, связанных сделок нет; 1025, 1026, 1029 — заполнено частично (категории D, B,
«не определена»); 1028 — пусто, правка; 1033 — пусто, просмотр.

## Обязательность заполнения

- Виджет обязателен к заполнению целиком: не решено (24.09.2026).
- Обязательных полей внутри нет: окно сохраняет любой набор, в том числе пустой.

## Переполнение

| Случай | Правило |
|---|---|
| Длинный текст в поле | суть сделки и комментарий — до четырёх строк, дальше многоточие и тултип с полным текстом (ReadOnlyField, `ds-readonlyfield.js`); целиком текст виден в окне. ГСЗ — одна строка с тем же тултипом |
| Много строк или записей | не бывает: признаков шесть или семь (строка «Связанные сделки» — только когда они есть). Длинный список связанных сделок живёт в поповере |
| Узкая ширина | подпись признака переносится внутри своей колонки, иконка остаётся на первой строке. Ниже 720px ширины тайла признаки встают в две колонки, ниже 380px — в одну (`@container`). На странице сделки: окно 1920 — тайл ≈ 732px, три колонки; 1366–1680 — тайл 610–660px, две; окно до 1296 — тайл на всю ширину, три (решение человека 25.09.2026) |
| Полная ширина | три колонки признаков, подложка тянется на всю ширину тела |
