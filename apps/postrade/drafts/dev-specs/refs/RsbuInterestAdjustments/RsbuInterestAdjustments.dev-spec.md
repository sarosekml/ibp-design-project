# Корректировки процентов РСБУ

## 1. Коротко

- **Что.** На странице транша — новый тайл «Корректировки процентов РСБУ»; он ведёт на новую
  страницу с таблицей корректировок, где их добавляют, правят и удаляют в модальном окне.
- **Зачем.** Корректировка — сумма (плюс или минус), которая прибавляется или вычитается начиная с
  «Исходной даты»; «Целевая дата» попадает в список дат начисления процентов. Данные влияют только
  на показатель «Начисленные проценты за период» в отчёте РСБУ по финансовому инструменту.
- **Кто.** Правят — Финансист ДИД и Финансист СБИ; видят — те же роли, что «Процентные схемы» и
  «Процентные периоды». Без права редактирования у тайла нет кнопки «Внести корректировку»; вид
  страницы только для просмотра не спроектирован (вопрос 6).
- **Где.** Карточка есть у траншей и у кредитоподобных опционов со «Структурой выплат по опциону» =
  «Процентные платежи». Меню: «Текущий портфель ДИД». Адрес страницы в продукте не решён.
- **Новое.** Страница `RsbuInterestAdjustments`; локальные компоненты `RsbuInterestAdjustmentsTile`
  (тайл) и `RsbuAdjustmentModal` (окно); окно подтверждения удаления — разметкой страницы.

## 2. Сценарий

1. Финансист открывает транш → в секции «Процентная задолженность» после «Процентных платежей» стоит
   тайл «Корректировки процентов РСБУ».
   <!-- snap: tranche-place -->
2. Вид тайла задают три признака. Условия: процентные платежи рассчитаны или нет. Данные:
   корректировки есть (с их числом) или нет. Права: редактирование доступно или нет. Пока условия не
   выполнены, тайл просит расчёт, а данные и права на его вид не влияют.
   <!-- snaps: tile-locked tile-none tile-filled tile-none-view tile-filled-view -->
3. Стрелка в шапке тайла → страница корректировок. Пока корректировок нет, у таблицы только шапка.
   Назад на транш — кнопка «В транш» в шапке страницы или крошка транша.
   <!-- snap: page-empty -->
4. «Внести корректировку» (в тайле или в шапке страницы) → окно «Новая корректировка». С тайла
   страница открывается сразу с поднятым окном (`?open=add` в прототипе).
   <!-- snap: modal-new -->
5. Финансист выбирает исходную дату из списка, вводит целевую дату, сумму (можно с минусом) и,
   если нужно, комментарий → «Добавить».
6. Проверка не прошла → Alert вверху окна, поля с ошибкой красные, окно остаётся открытым; правка
   поля снимает подсветку.
   <!-- snap: modal-error -->
7. Проверка прошла → окно закрывается, строка появляется в таблице, тост «Корректировка добавлена».
   <!-- snap: page-filled -->
8. Правка: карандаш в строке или двойной клик по строке → «Редактирование корректировки» с данными
   строки → «Сохранить» → тост «Корректировка изменена».
   <!-- snaps: modal-edit page-saved -->
9. Удаление: корзина в строке → подтверждение → «Удалить» → строка исчезает, тост «Корректировка
   удалена».
   <!-- snap: delete-confirm -->

Ветки:

- **Отмена** — «Отменить», крестик или Esc: окно закрывается без сохранения. Окно с формой кликом по
  затемнению не закрывается (правило ДС).
- **Условия не выполнены** (расчёт процентных платежей не сделан) — в тайле ни стрелки, ни кнопки, на
  страницу не попасть.
- **Нет права редактирования** — в тайле нет кнопки «Внести корректировку», стрелка на страницу
  корректировок остаётся.

## 3. Экраны

### Транш (`Tranche`) — изменение

Секция «Процентная задолженность»: после тайлов «Процентные схемы» · «Выдачи и погашения» · «Процентные
периоды» · «Процентные платежи» — новый тайл `RsbuInterestAdjustmentsTile` (раздел 4). Ширина в сетке — `col-3 colw-6`:
4 тайла в ряд на широкой рабочей области, 2 — на узкой.

### Корректировки процентов РСБУ (`RsbuInterestAdjustments`) — новая страница

- **Вход:** стрелка тайла — страница; «Внести корректировку» тайла — страница с открытым окном
  новой корректировки.
- **Выход:** «В транш» в шапке и крошка транша — на тот же транш.
- **Крошки:** Главная › Текущий портфель ДИД › 348. МКС › 1.1.1. Договор займа (НКЛ) › 1.1.1.1. Транш ›
  Корректировки процентов РСБУ. Уровни 3–5 — названия сделки, договора и транша из данных.

└── Table — корректировки, на всю свободную высоту

кнопки «Отменить» (`btn--transparent`) и «Удалить» (`btn--accent btn--danger`).

## 4. Новые локальные компоненты

### RsbuInterestAdjustmentsTile — тайл

- **Назначение:** показывает, внесены ли корректировки, и ведёт на страницу корректировок.
- **Где стоит:** страница транша, секция «Процентная задолженность»; `col-3 colw-6`. Место и ширину
  задаёт страница, не компонент. Размер в px — в подписи снимков.
- **Из чего собран (ДС):** Tile; IconButton `arrow-right` (`ibtn--neutral ibtn--m`, ссылка);
  Buttons `btn--outline btn--s` (ссылка).

**Состояния** — три признака на корне тайла:

| Признак | Атрибут | Значения | Что меняет |
|---|---|---|---|
| Условия | `data-calc` | `done` · `required` | `required` — процентные платежи не рассчитаны: только текст «Требуется расчёт процентных платежей», без стрелки и кнопки; данные и права на вид не влияют |
| Данные | `data-state` | `data` · `empty` | «Внесено корректировок: N» или «Корректировки отсутствуют» |
| Права | `data-mode` | `edit` · `view` | в `view` нет кнопки «Внести корректировку», стрелка остаётся |

| Вид | Текст | Стрелка | Кнопка «Внести корректировку» |
|---|---|---|---|
| условия не выполнены | «Требуется расчёт процентных платежей» | нет | нет |
| нет данных · редактирование доступно | «Корректировки отсутствуют» | да | да |
| есть данные · редактирование доступно | «Внесено корректировок: N» | да | да |
| нет данных · редактирование недоступно | «Корректировки отсутствуют» | да | нет |
| есть данные · редактирование недоступно | «Внесено корректировок: N» | да | нет |

<!-- snaps: tile-locked tile-none tile-filled tile-none-view tile-filled-view -->

Загрузка, ошибка, нет права видеть — не решено (вопрос 12). Длинного текста нет; на узкой ширине
текст переносится по словам.

**Поведение:** стрелка → страница корректировок; «Внести корректировку» → та же страница с открытым
окном новой корректировки. Сам тайл окно не открывает.

**Данные:** условия и данные — код `locked | none | filled` (`TrancheRsDto.rsbuInterestAdjustmentsState`):
`locked` — условия не выполнены, `none` и `filled` — нет данных и есть данные. N — число корректировок
(`RsbuInterestAdjustmentsRsDto.adjustments.length`). Признак права редактирования — `edit | view`;
откуда он приходит, не решено (вопрос 6).

### RsbuAdjustmentModal — модальное окно

- **Назначение:** внести или поправить одну корректировку. Одна форма на оба случая: «Новая
  корректировка» (кнопка «Добавить») и «Редактирование корректировки» (кнопка «Сохранить»).
- **Ширина:** `modal--w4`. Форма в одну колонку; обе даты — в одном ряду, по колонке.
- **Из чего собрано (ДС):** Modal, Alert (`alert--error alert--m alert--flush` в `modal__alert`),
  Select + DropdownList, InputDate, InputAmount, InputText multiline, Buttons, IconButton
  (крестик шапки `ibtn--neutral ibtn--l`).
- **Открывает:** страница — кнопкой «Внести корректировку», карандашом и двойным кликом по строке.
  Виден только тем, кто вносит корректировки.

<!-- snaps: modal-new modal-error modal-edit -->

**Поля**

| Поле | Компонент | Обязательное | Правило |
|---|---|---|---|
| Исходная дата | Select + DropdownList (`ddl--floating ddl--scroll`), крестик очистки | да | только из списка дат процентных платежей; набранное руками принимается, если совпало с датой списка, иначе откат к выбранной |
| Целевая дата | InputDate | да | любая дата `ДД.ММ.ГГГГ`, ручной ввод и календарь |
| Сумма корректировки | InputAmount, постфикс — код валюты (`RUB`) | да | плюс или минус; при вводе — разряды неразрывным пробелом, запятая, не больше двух знаков |
| Комментарий | InputText multiline | нет | свободный текст |

Все поля `inp--m`. Кнопки подвала: «Отменить» (`btn--transparent btn--m`) и «Добавить» / «Сохранить»
(`btn--accent btn--m`).

**Проверки** — по «Добавить» / «Сохранить»; ошибка — Alert вверху окна и красные поля:

| Условие | Текст |
|---|---|
| не заполнены даты или сумма | «Выберите исходную дату, введите целевую дату в формате ДД.ММ.ГГГГ и сумму корректировки числом.» |
| целевая дата раньше исходной | «Целевая дата не может быть раньше исходной.» (допущение, вопрос 3) |
| сумма равна нулю | «Сумма корректировки не может быть равна нулю.» (допущение, вопрос 4) |

**Контракт:** на входе — валюта и список дат процентных платежей (и запись — при правке); на выходе —
`{ startDate, endDate, adjustmentAmount, comment }`, даты ISO. Таблицу и тост ведёт страница.
Сохранение и ошибка сервиса не спроектированы (вопрос 13).

## 5. Данные и API

| Тип (DTO) | Поле | Тип | Смысл |
|---|---|---|---|
| `RsbuInterestAdjustmentRsDto` | `startDate` | string, ISO | исходная дата — одна из дат процентных платежей |
| | `endDate` | string, ISO | целевая дата, любая |
| | `adjustmentAmount` | number | сумма в валюте инструмента, может быть отрицательной |
| | `comment` | string | комментарий |
| `RsbuInterestAdjustmentsRsDto` | `currencyCode` | string, ISO 4217 | валюта сумм |
| | `startDateOptions` | string[] | даты для списка «Исходная дата» |
| | `adjustments` | `RsbuInterestAdjustmentRsDto[]` | внесённые корректировки |
| `TrancheRsDto` | `rsbuInterestAdjustmentsState` | `locked \| none \| filled` | вид тайла по условиям и данным |

Имена выдуманы 09.10.2026 (DTO нет). Имена полей дат (`startDate`, `endDate`) — имена API, подписи в
интерфейсе — «Исходная дата» и «Целевая дата». Нужно от бэкенда: список корректировок транша;
создание, изменение, удаление корректировки; даты процентных платежей и валюта инструмента; признак
«процентные платежи рассчитаны»; право пользователя вносить корректировки. Имена методов выбирает
разработка.

**Отчёт РСБУ (вне прототипа).** «Начисленные проценты за период» считаются с учётом «Целевой даты»
и «Суммы корректировки»; отчётные даты — даты начисления процентов плюс целевые даты корректировок;
суммы, на которые повлияли корректировки, в отчёте выделяются.

## 7. Открытые вопросы

1. **Бизнес-смысл корректировок** — требование пришло, комментарий К-1 панели прототипа открыт до
   решения человека (`RsbuInterestAdjustments.screen.md` §13, п. 1).
2. **Источник списка «Исходная дата»** — даты «Процентных периодов» (требование) или «Процентных
   платежей» (дизайнер); когда список становится доступен (§13, п. 2; паспорт окна, п. 3).
3. **Порядок дат** — «целевая не раньше исходной» — допущение, в требовании нет (§13, п. 3).
4. **Сумма ≠ 0** — допущение (§13, п. 4).
5. **Комментарий** необязательный (§13, п. 5).
6. **Права** — вид страницы для просмотра не спроектирован; права на внесение за пределами
   Финансиста ДИД и СБИ; откуда тайл берёт признак права редактирования (§13, п. 6; паспорта тайла
