# Окно «Новый платеж»

## Описание (Purpose)

Артефакт тайла «Досрочное погашение процентов». Заголовок окна — «Новый платеж» при внесении и
«Изменение платежа» при изменении, форма одна.

Досрочный платёж — сумма, которая начиная с «Даты платежа» гасит процентную задолженность по видам
в порядке приоритета погашения (окно «Приоритет погашения»). Кнопка «Рассчитать платежи» берёт
задолженность процентного периода, в который попала дата, и раскладывает по ней сумму: первый вид
гасится целиком, остаток идёт в следующий. Результат — таблица «Задолженность на дату»; «Досрочную
сумму» любой строки можно поправить руками, но не больше её «Начисленной суммы». «Добавить» проходит,
только когда сумма строк равна сумме платежа.

Страницу и таблицу платежей окно не знает: задолженность по периодам, валюту и приоритет берёт у
страницы, проверенную запись отдаёт ей же (`PostModalEarlyInterest.bind(scrim, { options, save })`,
`EarlyInterestRepaymentModal.js`). Страница ставит платёж «В обработке» и показывает уведомления.

```
Modal w7 (заголовок «Новый платеж» / «Изменение платежа», IconButton L «Закрыть»)
├── modal__alert — Alert error: заголовок + текст (скрыт, пока ошибки нет)
├── тело

│   │   ├── ряд из трёх колонок: «Дата платежа» (InputDate) · «Сумма платежа» (InputAmount) · «Тип платежа» (disabled)
│   │   ├── «Комментарий» — InputText multiline
│   │   └── «Рассчитать платежи» — btn--outline btn--s, глиф calc
│   └── «Задолженность на дату» — таблица: Дата начала ПП · Дата оконч. ПП · Вид задолженности ·
│       Валюта · Начисленная сумма · Досрочная сумма (поле в каждой строке); пусто — «Нет данных»
│       под таблицей после расчёта — серый блок итогов: «Общая сумма задолженности» · «Общая досрочная сумма»
└── подвал: «Отменить» (transparent) · «Добавить» / «Сохранить» (accent)
```

Ширина — `modal--w7` (на шаг шире прежней, правка человека 16.10.2026). Раскладку задаёт `EarlyInterestRepaymentModal.css`, остальное — Modal.

## Обязательность заполнения (Required)

- Компонент обязателен к заполнению целиком: не применимо — окно.
- Обязательные поля: «Дата платежа», «Сумма платежа»; расчёт обязателен перед «Добавить».
- Что показывает, когда обязательное не заполнено: подсветка `inp--error` без текста.
- Что отдаёт наружу: запись `{ paymentDate, paymentAmount, comment, allocations }` через `save`.

## Поведение (Behavior)

| Триггер | Результат |
|---|---|
| Ввод в «Сумму платежа» | разряды неразрывным пробелом, запятая, два знака; знак «-» не вводится |
| Смена даты или суммы после расчёта | таблица не сбрасывается — пересчитывает только «Рассчитать платежи» (решение человека 16.10.2026); «Добавить» сверяет строки с текущей суммой платежа |
| «Рассчитать платежи» | распределение по приоритету или ошибка из таблицы выше |
| Смена даты платежа | «Начисленная сумма» после «Рассчитать платежи» зависит от даты: чем позже дата, тем больше задолженность (моки: +0,03 % в день к уровню на 31.03.2025, назад — меньше) |
| Ввод в «Досрочную сумму» | поле стоит в каждой строке (`tc--input`, `inp--s`): в покое сливается со строкой, при наведении и фокусе проявляется; по уходу фокуса (или Enter) сумма принимается, «Общая досрочная сумма» пересчитывается; «Начисленную сумму» не правят |
| «Добавить» / «Сохранить» | проверки в порядке таблицы ошибок; без ошибок окно закрывается, страница ставит платёж «В обработке» |
| «Отменить», крестик, Esc | окно закрывается без изменений; клик по скриму окно не закрывает (форма) |

Две записи на одну дату допустимы (ответ человека 12.10.2026) — окно их не запрещает.

### Ошибки (Errors)

| Когда | Заголовок | Текст |
|---|---|---|
| «Рассчитать платежи» или «Добавить» с пустой датой или суммой | — | подсвечены поля, текста нет (макет) |
| Расчёт: на дату нет начислений | — | На указанную дату начисления отсутствуют (в прототипе — только сценарием панели: на обычной дате начисления есть) |
| Расчёт: сумма больше общей задолженности | — | Сумма платежа превышает общую сумму задолженности (таблица заполнена начисленными суммами) |
| «Добавить» с суммой платежа больше общей задолженности | — | Сумма платежа превышает общую сумму задолженности (пользователь уменьшает сумму или рассчитывает на более позднюю дату, когда накопится больше процентов) |
| «Добавить» без расчёта | Не рассчитаны платежи | Чтобы добавить платеж рассчитайте платежи по суммам задолженности |
| «Добавить»: строка больше начисленной | Досрочная сумма превышает начисленную сумму задолженности | Досрочная сумма по «[Вид задолженности]» должна быть равна или меньше начисленной суммы (вид — в кавычках, с большой буквы, без склонения; ответ человека 16.10.2026) |
| «Добавить»: сумма строк меньше суммы платежа | Сумма платежа распределена не полностью | Сумма всех досрочных платежей меньше суммы платежа на N [валюта], необходимо распределить всю сумму. |
| «Добавить»: сумма строк больше суммы платежа | — | Сумма досрочных платежей превышает сумму платежа (текст человека, 16.10.2026) |
| «Добавить» с суммой 0 | — | Сумма платежа должна быть больше нуля (допущение агента) |

## Открытые вопросы (Open questions)

1. Пары во фронтенде нет — имя наше (16.10.2026).
2. Владелец компонента — `не решено (16.10.2026)`.
3. Сброс расчёта при смене даты или суммы — решено человеком 16.10.2026: таблица не сбрасывается, пересчитывает только «Рассчитать платежи».
4. Платёж «Не обработан» можно править и сохранять повторно — решено человеком 16.10.2026 (причины ошибок обработки пока неизвестны; возможно, сервис недоступен).
5. После ошибки «Сумма платежа превышает общую сумму задолженности» добавить платёж нельзя — решено человеком 16.10.2026: пользователь уменьшает сумму или рассчитывает на более позднюю дату.
6. Маска даты на макете — «ММ.ДД.ГГГГ», в ДС и во всём проекте — «ДД.ММ.ГГГГ»; сделано по ДС (несостыковка макета, 16.10.2026).
7. Валидация пустых полей на макете — только красные рамки, без текста; ошибка нулевой суммы на макете не показана — «Сумма платежа должна быть больше нуля» добавлена агентом.
8. Заголовок ошибки «Сумма платежа превышает общую сумму задолженности» и «На указанную дату начисления отсутствуют» на макете — одна строка без заголовка; сделано так же.
9. Макет показывает «Тип платежа» в одном ряду с датой и суммой — три колонки; «Комментарий» — на всю ширину.
10. Сумма без верхнего предела, валюта — валюта инструмента (ответ человека 12.10.2026).
11. «Досрочная сумма» — поле в каждой строке (правка человека 16.10.2026: по клику поле не появлялось); подсветка активной строки — допущение агента.
12. Блок итогов под таблицей — серая подложка `--tertiary-bg` со скруглением `--radius-m` (8px) по образцу блоков метрик `deals-app` (правка человека 16.10.2026); готового компонента «подложка» в ДС нет.
13. Рост задолженности с датой — упрощение прототипа (решение человека 16.10.2026): в жизни на графике платежей есть и погашения, после которых задолженность падает; с реальными моковыми данными логика заменится.
