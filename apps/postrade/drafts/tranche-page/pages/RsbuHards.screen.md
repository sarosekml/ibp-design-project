# Page: RsbuHards — Харды в РСБУ

## 1. Назначение (Purpose)

Страница карточки «Харды в РСБУ» транша: финансист смотрит расчёт процентов as-is
(«Текущий расчёт»), при необходимости правит его копию («Хардовый расчёт») и
добавляет новые периоды. Данные хардового расчёта идут в отчёт РСБУ вместо
текущего (критерий 7).

**Роль пользователя:** финансист ДИД, финансист СБИ — редактирование; просмотр — те же роли, что у карточки «Процентные схемы».
**Права:** по ТЗ (критерий 3); в концепте не различаются — вопрос в разделе 13.

## 5. Таблицы (Tables)

Обе таблицы — прямо в разметке страницы, колонки одни и те же (критерии 5 и 6.b).

| Ключ | Заголовок | Тип | Выравн. |
|---|---|---|---|
| `periodNumber` | № | целое | слева |
| `periodStartDate` | Дата начала периода | дата | слева |
| `periodEndDate` | Дата окончания периода | дата | слева |
| `currentInterestOnLoan` | Текущие проценты, начисленные на Объём кредита | сумма | справа |
| `currentInterestOnPik` | Текущие проценты, начисленные на PIK проценты | сумма | справа |
| `capitalizedInterestOnLoan` | Капитализируемые проценты, начисленные на Объём кредита | сумма | справа |
| `capitalizedInterestOnPik` | Капитализируемые проценты, начисленные на PIK проценты | сумма | справа |
| `deferredInterestAccrued` | Отложенные проценты начисленные | сумма | справа |
| `repoPaymentsAmount` | Платежи по сделкам РЕПО | сумма | справа |
| `articleName` | Статья | текст | слева |

**Формат значений:** суммы — `1 250 000,00` с неразрывными разрядами, валюта
транша — кодом в модалке (`RUB`); даты — `ДД.ММ.ГГГГ`.

Колонки по умолчанию шириной 240px, колонка № — минимальная (80px: № и кнопка сортировки); сортировка — в каждой колонке (цикл «без сортировки →
по возрастанию → по убыванию»); ширину можно менять, остаток ширины уходит хвостовому
разделителю — линии строк доходят до правого края.

«Текущий расчёт» — только чтение. «Хардовый расчёт» изначально содержит те же данные; ячейки
только для чтения, строка правится в модалке (раздел 7). Ячейка, отличающаяся от текущего
расчёта, залита `--bg-table-accent` (`tc--accent`) и несёт угловой маркер правки (`tc--edited`);
при наведении — тултип «Расчётное значение: <значение из текущего расчёта>». Строка нового
периода (добавлена кнопкой) залита целиком — `tbl__row--accent`, включая разделители по краям, — и помечена маркерами, тултипа у неё нет. У акцентных ячеек и строки есть hover (токен `--bg-table-accent-hover`). Колонка «Статья» несёт
скрытые действия строки (карандаш и корзина, видны при наведении).

**Вариант «исходное значение в ячейке»** — `?variant=subtext` (переключается панелью прототипа): у изменённой ячейки вторая строка `tc__subtext` с расчётным значением, на ступень мельче (`--type-body-xs`), цветом `--text-inactive`; тултип «Расчётное значение» остаётся. У нового периода второй строки нет.

## 6. Поведение (Behavior)

| Триггер | Результат |
|---|---|
| «Рассчитать» | пересчитывает «Текущий расчёт»; дата и время в подзаголовке («Последний расчёт: ДД.ММ.ГГГГ ЧЧ:ММ», стоят с открытия страницы) обновляются на текущие (критерий 4.b) |
| Клик по табу | показывается панель выбранного таба; «Хардовый расчёт» — редактируемая |
| Двойной клик по строке «Хардового расчёта» или карандаш в строке | открывается модалка «Редактирование периода» с данными строки |
| «Новый период» | открывается модалка «Новый период» с пустой формой |
| «Добавить» / «Сохранить» в модалке | проверка (раздел 7); при успехе строка добавляется или обновляется, модалка закрывается |
| Расчёт, добавление, изменение и удаление периода | тост ДС (`DSToast`, фоновый, зелёный, исчезает сам): «Расчёт выполнен», «Период N добавлен», «Период N изменён», «Период N удалён» |
| Клик по затемнению | модалка с формой не закрывается (правило ДС); закрывают крестик, «Отменить», Esc |
| Заголовок колонки (кнопка сортировки) | сортирует строки таблицы |
| «Настроить колонки» (шестерёнка над таблицей) | модалка настройки колонок ДС: видимость, порядок, закрепление; «Применить» закрепляет колонки (`position: sticky` при горизонтальной прокрутке); у каждой таблицы настройка своя |
| Корзина в строке «Хардового расчёта» | открывается модалка подтверждения; «Удалить» убирает период из таблицы |
| Отчёт РСБУ по индикатору «XXX» (критерий 7) | берёт данные «Хардового расчёта», если таблица заполнена, иначе «Текущего» — на этой странице не показан |

## 7. Модальные окна (Modals)

| Окно | Триггер | Ширина | Содержимое |
|---|---|---|---|
| «Новый период» / «Редактирование периода» | кнопка «Новый период»; двойной клик по строке или карандаш | `modal--w5` | поля в два столбца, поля одного ряда выровнены по нижней границе (метки бывают в 1–2 строки): дата начала, дата окончания, шесть сумм (текущие ×2, капитализируемые ×2, отложенные, платежи по РЕПО; валюта — постфиксом); подвал — «Отменить», «Добавить» / «Сохранить» |

№ периода присваивается автоматически (следующий по порядку), «Статья» у нового периода — «Проценты по кредитам»; в форме этих полей нет. Суммы в полях разбиты на разряды. При правке под полем, значение которого отличается от текущего расчёта, виден помощник «Расчётное значение: …» (у нового периода его нет).

**Проверка при сохранении** (ошибка — `alert--error` над формой, поля дат с `inp--error`, модалка остаётся открытой): все поля заполнены; дата окончания не раньше даты начала; период не пересекается с другими периодами «Хардового расчёта» (при правке сама строка не учитывается).

**Подтверждение удаления** — модалка `modal--w3`, `role="alertdialog"`: «Удалить период N (ДД.ММ.ГГГГ — ДД.ММ.ГГГГ)? Действие нельзя отменить.»; подвал — «Отменить», «Удалить» (`btn--danger`).
