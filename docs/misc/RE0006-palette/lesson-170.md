### Л_. Гейт атрибута темы ставится на каждый селектор списка, а не на список целиком
- **Дата/зона:** 04.10.2026 | design-system/tools/theme-build.mjs (RE0005–RE0006), design-system/foundations/Themes/Themes.css, components/atoms/Switch/Switch.css
- **Симптом:** в legacy (страница без атрибута `data-theme`) у включённого свитча при наведении пропадал фон; выключенный вёл себя нормально; дефект воспроизводился и на странице компонента Switch. Дошёл до человека.
- **Причина:** генератор тем навешивал `:where([data-theme]…)` на всю строку селекторов целиком, поэтому у правил с запятой гейт доставался только первому селектору. Хвосты списка (`, .sw--hover.sw--on .sw__control`, `, .sw:hover:has(.sw__input:checked) .sw__control`) срабатывали без атрибута — и в legacy подставляли несуществующий токен темы (`--color-control-track-on-hover`). Свойство `background` становилось невалидным в момент вычисления (unset) — фон исчезал. `checkGated` проверял строку целиком и видел `data-theme` от первого селектора — дефект проходил.
- **Правило:** в генерате, который гейтит правила атрибутом темы, префикс `:where([data-theme]…)` навешивается на КАЖДЫЙ селектор списка по запятой; проверка гейта идёт по каждому селектору, а не по строке. Правило файла тем не действует в legacy ни одним своим селектором.
- **Закрепление:** исполняемое — `структурно:theme-build`: гейт на каждый селектор; `checkGated` проверяет каждый селектор списка; кейс `--selftest` с правилом `.a .b, .c .d`; регресс роняет `theme-build --check` (шаг `ds-check --all` и гейта).
- **Промоут:** не промоутить — закреплено кодом `theme-build --check`
