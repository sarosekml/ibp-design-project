## 2. Решения

### 2.1 Шапка (№ 1, 2)

Подзаголовок PageHeader — кастомный, из мета-элементов `.phead__meta` с иконкой
`.phead__meta-ico` (анатомия PageHeader ДС), считается из данных на каждом рендере:

| Мета | Иконка | Как считается |
|---|---|---|
| Неделя 42 · 12–18 октября | `calendar` | `WEEKLY_PICKS.title` |
| В подборке: N | `star` | лиды вкладки «Подборка недели» |
| В работе: N | `tasks` | лиды вкладки «Мои в работе» |
| Встречи на неделе: N | `calendar-check-01` | встречи моих лидов с датой 12–18.10.2026, кроме отменённых |
| В Pipeline за Q4: N · X млн RUB | `pipeline` | мои лиды «Передано в Pipeline», вход в стадию с 01.10.2026 |
| Без движения > 14 дн.: N | `clock-timer` | мои лиды в работе, на стадии больше 14 дней |

Сводка — текст, не фильтр: клик по мете — кандидат следующего шага (вопрос 1).

### 2.2 Ритм (№ 3, 4)

Одна строка экрана `.screen__content { gap: var(--space-12) }` — ритм экрана-реестра ДС.
Шапка → 12 → табы → 12 → тулбар → 12 → таблица.

### 2.3 Пагинация и итоги (№ 5, 6)

`DSPagination.row({ pager:{ total, page, pageSize, … }, info:{ items, warn:'' } })` — без
`footer`: собственная панель массовых действий `#lead-bulk` уже стоит в `.dtable__footer`.
Размер страницы по умолчанию 50 (как в остальных реестрах прототипа). Инфо-слот слева:
«Всего лидов: N», «На сумму: X млн RUB», «Без оценки: N» (если есть лиды без объёма).
Итоги считаются по всем строкам вкладки с учётом фильтра и основания, а не по текущей странице.

### 2.4 Демо-данные (№ 7, 10) — решение человека 13.10.2026

Человек: «Все лиды» — около 70; остальные вкладки фильтруют этот список; подборка 10, в работе 15,
в архиве около 10.

| Вкладка | Что | Сколько |
|---|---|---|
| Подборка недели | Рассмотрение, в подборке | 10 |
| Мои в работе | мои, рабочие стадии | 15 |
| Все лиды | все не финальные: подборка + мои в работе + Рассмотрение вне подборки + в работе у коллег | 70 |
| Архив | финалы: «Передано в Pipeline», «Клиент отказался», «Не беру» | 10 |

Лиды берутся из существующих записей источников (их 190) — ссылки «Основание» продолжают
вести на исходные страницы; записи вне 80 отобранных лидами не показываются. Отбор — по очереди
оснований (все девять типов на каждой вкладке, где хватает записей). Состояние демо получает
версию: старая сессия пересобирается один раз. «Все лиды» больше не показывает финалы —
они только в «Архиве».

### 2.5 Колонка «Статус клиента» — решение человека 13.10.2026

## 4. Открытые вопросы

1. Должны ли метрики шапки фильтровать таблицу по клику (как сводка доски в MS0015 §5.1)?
2. «Статус клиента» — атрибут клиента или лида? В прототипе — поле демо-лида, поэтому у одного
   клиента в разных лидах статусы бывают разными. Откуда он берётся в продукте?
3. «Отказался» в статусе клиента и стадия «Клиент отказался» — одно и то же событие или разные?
   В демо «Отказался» стоит только у лидов со стадией «Клиент отказался».

### 5.4 Резиновая колонка «Клиент» — только в этом прототипе

Просьба человека: колонка «Клиент» тянется до упора, пока нет горизонтального скролла,
и остаётся текущей ширины (224px), когда таблица по контенту шире области. Рантайм Table
ДС держит ширины в px (выравнивание, ресайз, настройки, перестановка), поэтому быстрый
вариант (решение человека 13.10.2026) — экранный `stretchClient` в `leads-ui.js`,
помечен `[ПРЕДЛОЖЕНИЕ]`. Проверено: 1920 — 224px и скролл, 2800 — 570px, таблица до
правого края без скролла. Пересчёт на живое изменение ширины окна в скрытой панели
браузера проверить нельзя (ResizeObserver и resize там не доставляются) — нужен взгляд
человека в обычном браузере.

Кандидат в ДС: свойство колонки «фиксированная / тянется до упора» (например,
`data-col-grow` на ячейке шапки) — правка `Table.js`, `TableResize.js`, `TableReorder.js`,
`TableSettings.js` по согласованному плану.

### 5.7 Зазор между IconButton — правило (14.10.2026)

Правило человека: подложки (`::before`) соседних IconButton **не наезжают** друг на друга; зазор между
подложками — 0 или любое чётное значение по ситуации. Подложка шире иконки (S 24/16 · M 32/20 · L 40/24),
поэтому расстояние между иконками соседей — не меньше S 8 · M 12 · L 16, плюс выбранный зазор.

- Правило записано в инварианты IconButton 1.012 (спека, чит-шит). Зазоры рядов компонентов ДС
  **не менялись**: первая попытка подняла их у Tile, Drawer, TableCell, Entity, ProductRow — откачено
  по решению человека.
- Макет: в шапке панели лида «Открыть страницу лида» в обёртке с отступом 12px к 4px шапки Drawer —
  между подложками 4px.
- Сторож — сенсор Б44 (замечание) и пункт K14 composition-review. Урок Л227.
