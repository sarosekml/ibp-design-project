# StepForm: пошаговая форма

## Коротко

- **Откуда.** Конструктор запроса в `RequestThread.html` v02 (`.bld`,
  `.bsec`, `.bld__foot`; стили ~354–380, 433–435, 443; разметка ~682–711).
  Скриншоты человека 05.10.2026 (2–5): секции «1 Объект анализа» и
  «2 Дополнительный фокус» — слева номер шага и подпись (колонка 184 px),
  справа контролы (поиск объекта, чипы); секции разделены пунктиром; когда
  в секции есть выбор — номер становится галочкой; внизу заметка про срок
  подготовки. На узком контейнере (≤ 960 px) колонки складываются в одну.
- **Чего нет в ДС.** Формы «шаг + подпись слева, поле справа» с состоянием
  готовности шага нет. Номер шага — MS0010d, заметка — MS0010e.
- **Задача.** Новая молекула **StepForm** — `components/molecules/StepForm/`,
  версия `1.000`. Внутри — StepMarker, Divider dashed, Note и любые поля ДС
  (InputText, Chip). Перевести конструктор прототипа, включая поиск
  объекта (`.bfind` → InputText).
- **Часть группы MS0010.** Правка ДС — после согласования вопросов §6.

## Objective

Пошаговая форма собирается из StepForm: шаги с маркером и подписью, контролы
справа, разделители, подвал-заметка, складывание в колонку на узком
контейнере. Конструктор v02 — без локальных `.bld*`, `.bsec*`, `.bfind*`.

## 1. Как сейчас

| Что | Класс | Вид |
|---|---|---|
| Контейнер | `.bld` | колонка, зазор `--space-12`, поля `--space-16`, граница сверху `--border-light`; появление `opacity/transform` + лесенка `bldIn` по `--i` |
| Секция | `.bsec` | грид `184px minmax(0,1fr)`, зазор `--space-8` `--space-16`, `align-items: start`, сверху `padding --space-12` + `1px dashed --border-light`; у первой — ни линии, ни отступа |
| Подпись | `.bsec__label` | `min-height: --space-40` (по высоте поля M), `body-s-strong`, зазор 8 до номера |
| Номер | `.bsec__num` | → StepMarker (MS0010d) |
| Готово | `.bsec.is-done` | номер → галочка; ставит скрипт по выбору в секции |
| Контролы | `.bsec__ctl` | колонка, зазор `--space-8`, `min-width: 0` |
| Блок на всю ширину | `.bprior` с `grid-column: 1 / -1` | → Tile Inset (MS0010g) |
| Подвал | `.bld__foot` | → Note (MS0010e) + пунктир сверху |
| Поиск объекта | `.bfind` | свой контейнер поля: высота 40, фон `--bg-page`, кольцо фокуса `--cmp-ring` |
| Узкий контейнер | `@container screen (max-width: 960px)` | одна колонка |

## 2. Решение

### 2.1. Анатомия

```html
<div class="stepform" role="group" aria-label="Конструктор запроса">
  <section class="stepform__step" aria-labelledby="stObject" data-state="todo">
    <div class="stepform__label" id="stObject">
      <span class="stepmark stepmark--m" aria-hidden="true"><span class="stepmark__num">1</span><i class="stepmark__icon" data-icon="check"></i></span>
      <span class="stepform__title">Объект анализа</span>
    </div>
    <div class="stepform__control">
      <!-- любые поля ДС: InputText M, .chiplist чипов, … -->
    </div>
    <div class="stepform__wide"><!-- на всю ширину шага: Tile Inset --></div>
  </section>
  <section class="stepform__step" …>…</section>
  <p class="note note--s stepform__foot">…</p>
</div>
```

- Шаги разделяет сам компонент (пунктир между `stepform__step` и перед
  `stepform__foot`) — `border-top` по правилам Divider dashed или вставкой
  `hr.dvd.dvd--h.dvd--dashed` (вопрос 6.2). Первый шаг без линии.
- `data-state` шага: `todo` / `done` / `error` / `disabled` — компонент
  красит StepMarker внутри (`.stepform__step[data-state="done"] .stepmark`
  = `stepmark--done`). Экран меняет только атрибут — данными, а не
  параллельным классом.
- Статус шага для скринридера: визуально-скрытый текст «выполнено» в
  `stepform__title` или `aria-describedby` (вопрос 6.4).

### 2.2. Раскладка

| Свойство | Значение |
|---|---|
| колонка подписи | вопрос 6.1 (в прототипе 184 px) |
| зазор колонок / строк | `--space-16` / `--space-8` |
| отступ шага сверху | `--space-12` |
| высота строки подписи | `--space-40` — центр подписи на уровне поля M |
| узкий контейнер | одна колонка; порог — container query компонента (вопрос 6.3) |
| `stepform__control` | колонка, зазор `--space-8`, `min-width: 0` |

Компонент **не** рисует фон, рамку и поля вокруг себя — это делает
контейнер (в прототипе — слот панели PromptInput).

### 2.3. Поиск объекта — InputText

`.bfind` → `div.inp.inp--m` + `.inp__field` + `.inp__lead` (`client-search`) +
`input.inp__control type="search"`. Отличия от прототипа: фон поля и фокус —
как у InputText (без `--bg-page` и внешнего кольца); крестик очистки ставит
`Inputs.js` (в прототипе Esc очищает — оставить обработчиком экрана). Метки
нет — `aria-label` на контроле; `.inp` без `ds-label` допустим? — проверить
по спеке InputText (вопрос 6.5).

### 2.4. Анимации

Лесенка появления шагов (`bldIn`, `--i`) и `bldPop` — не переносятся (нет
токенов движения). Смена номера на галочку — внутри StepMarker.

## 5. Риски

| Риск | Что делаем |
|---|---|
| `min-height: --space-40` у подписи не совпадёт с полем другого размера | правило в спеке: в StepForm — поля M; S — в бэклог |
| Пунктир рисуется дважды (у шага и у вложенного Divider) | один способ разделения (вопрос 6.2) |

## 6. Вопросы к человеку

1. **Ширина колонки подписи.** 184 px — не токен и не кратно сетке.
   Варианты: (а) `max-content` с ограничением — подписи разной длины
   выровняются по самой длинной; (б) 2 колонки сетки 12; (в) ближайший
   токен. Рекомендую (а) с минимумом `--space-160`/сопоставимым токеном —
   проверить шкалу Spacing.
2. **Разделитель** — `border-top: dashed` в CSS компонента (рекомендую,
   разметка чище) или явный `hr.dvd--dashed` между шагами?
3. **Порог складывания** 960 px — container query на самом `.stepform`
   (рекомендую: зависит от ширины формы, а не экрана) или класс-модификатор
   `.stepform--stacked`?
4. **Озвучка готовности шага** — скрытый текст «выполнено» (рекомендую) или
   не озвучивать?
5. **InputText без метки** в форме, где подпись шага уже есть, — допустимо?
   Рекомендую да, с `aria-labelledby` на подпись шага.

## Решения (06.10.2026)

1. **Колонка подписи — по самой длинной подписи** (ответ человека):
   `fit-content(33%)` у формы + `subgrid` у шагов, без литералов. Сейчас
   208px: «Дополнительный фокус» теперь в одну строку (в прототипе колонка
   184px и подпись переносилась). Моя оценка в вопросе «≈184px, вид не
   меняется» была неточной.
2. **Разделитель** — пунктир в CSS компонента (рекомендация §6.2).
3. **Порог складывания** (ответ человека: «стандартный, но как сейчас»):
   container query по ширине самой формы — уже **840px** (нижняя граница класса
   Expanded Material 3). В композере форма 846px — две колонки; переход в
   одну колонку при окне ≈ 978px (в прототипе — при экране ≤ 960, то есть окне
   ≤ 1016). Порог по форме работает и рядом с панелью просмотра.
4. **Озвучка готовности** — скрытый статус `.stepform__status--done` («выполнено»)
   / `--error`, компонент открывает его скринридеру только в своём состоянии.
5. **InputText без метки** — да: `aria-labelledby` на название шага;
   `.inp--fullwidth` (у InputText ширина по умолчанию 280px); `type="text"` +
   `role="searchbox"` — нативного крестика `search` в ДС нет, крестик даёт
   рантайм поля.
6. **Анимации** (принцип переноса): лесенка `bldIn` и проявление панели —
   опция `.stepform--appear`, срабатывает по снятию `inert` с панели; значения
   из прототипа.
7. **Состояния шага** — `data-state`: `pending` · `current` · `done` · `error` ·
   `disabled` (`pending` вместо `todo` — сенсор Б9).
