# ДС: уникальные id внутри SVG на каждую копию иконки

## Коротко

- **Что не так.** Глифы лежат в `icons-data.js` строками SVG, и каждая
  вставка на страницу — один и тот же текст. У 141 глифа из 247 внутри SVG
  есть элементы с `id` — маска обрезки `clipPath` и служебные прямоугольники —
  и ссылка на маску `clip-path="url(#…)"`. Две одинаковые иконки на странице
  дают повтор `id`, а ссылка `url(#…)` ищется по всему документу и попадает в
  первую копию глифа на странице, а не в свою.
- **Чем это плохо.** `id` в HTML-документе обязан быть уникальным.
  Отрисовка копии зависит от чужой копии — её скрытия, удаления, перерисовки.
  На повторах спотыкаются `getElementById`, валидаторы и проверки доступности
  (правило duplicate-id).
- **Видимого дефекта сейчас нет.** 25.09.2026 при проверке панели прототипа
  (задача 0005a) один раз не отрисовалась иконка «Comment on state» в меню
  узла. Повторить не удалось: в Chrome копия рисуется, даже когда первая копия
  глифа на странице скрыта (`display: none`). Задача — гигиена и снятие класса
  риска, а не починка наблюдаемой поломки.
- **Решение — в одном файле, рантайме иконок `ds-icons.js`.** Он даёт всем
  `id` внутри SVG суффикс копии и переписывает ссылки на них внутри той же
  копии — и при вставке `<i data-icon>`, и при чтении `DS_ICONS[имя]` другими
  рантаймами. Остальные скрипты ДС не меняются.

## Objective

На экране каждый вставленный глиф ДС самодостаточен: `id` внутри его SVG
уникальны в документе, ссылки `url(#…)` и `href="#…"` указывают на элементы
той же копии — через какой бы скрипт ДС глиф ни попал на страницу.

## 1. Как сейчас (замер 26.09.2026)

- `icons-data.js`: 247 глифов, у 141 есть `url(#…)`. Пример `message-text`:
  `id="b49_clip192_251"` (clipPath), `id="b49_message-text"` дважды (служебные
  rect), `id="b49_Icon"` (контур). Префикс `b49_` — один на глиф, не на копию.
  В меню узлов панели прототипа — 11 копий `message-text` с одним и тем же `id`.
- **Кто вставляет глифы:**
  - `ds-icons.js`, `apply()`: `el.innerHTML = DS_ICONS[имя]` — главный путь,
    все `<i data-icon>` экранов, организмов и панели прототипа;
  - рантаймы экрана читают `DS_ICONS` напрямую: `ds-notify.js` (снекбары и
    тосты), `ds-pagination.js`, `ds-actions-overflow.js`, `ds-datepicker.js`,
    `input-kit.js` — часть из них запоминает объект при загрузке
    (`const L = window.DS_ICONS`);
  - страницы документации ДС: `pg-kit.js`, скрипты `*.page.js`, встроенные
    скрипты в `pages/**`, `index.html`.
- На экране рантаймы грузит `ds.js` строго по порядку `icons-data.js →
  ds-icons.js → остальные` (`document.write`). Страницы документации
  подключают `icons-data.js` и нужные рантаймы поштучно, часто без
  `ds-icons.js`.
- Обращений к внутренним `id` глифов из CSS и скриптов нет (поиск по
  `design-system/`, `apps/`, `.agents/`).

## 2. Решение

Всё — в `design-system/scripts/ds-icons.js`:

- **Копия с уникальными `id`.** Каждой копии — порядковый номер N;
  `id="X"` → `id="X-iN"`; внутри той же копии `url(#X)` → `url(#X-iN)`,
  `href="#X"` и `xlink:href="#X"` → с суффиксом. Экспорт глифов пишет один
  `id` дважды (rect внутри `clipPath` и снаружи — у 118 глифов): повтор
  внутри копии получает ещё `-2`, `-3`…, ссылка ведёт на первый элемент — как
  у одиночной копии. Глиф без `id` не меняется (та же строка).
- **`dsIcons.svg(имя)`** — SVG глифа строкой, копия с уникальными `id`; нет
  глифа — пустая строка. Публичный API: `window.dsIcons = { apply, svg }`.
- **`apply()`** вставляет через `svg(имя)`; остальное как было (перекраска в
  `currentColor`, `data-icon-done`, предупреждение о неизвестном имени).
- **`DS_ICONS` после `ds-icons.js` отдаёт копии.** При загрузке рантайм
  заменяет `window.DS_ICONS` объектом с теми же ключами, где чтение
  `DS_ICONS[имя]` возвращает копию с уникальными `id`. Рантаймы, которые
  читают `DS_ICONS` напрямую, получают уникальные копии без правок — на
  экране их грузит `ds.js` после `ds-icons.js`, и запомненная при загрузке
  ссылка уже указывает на новый объект. Если `ds-icons.js` оказался раньше
  `icons-data.js`, замена делается при первом обращении.

**Вне задачи:** страницы документации ДС без `ds-icons.js` (п. 1) по-прежнему
вставляют исходные строки — это витрина ДС, а не экраны продукта.

## 3. Проверка

**Исполняемая** — `node design-system/scripts/ds-icon.mjs --selftest`
(исполняет `icons-data.js` и `ds-icons.js` в `vm` на заглушках DOM):

1. по всем 247 глифам: две копии `svg(имя)` не пересекаются по `id`, внутри
   копии `id` не повторяются; каждая ссылка `url(#…)` и `href="#…"` копии
   ведёт в `id` той же копии; снятие суффикса возвращает исходную строку байт
   в байт; глиф без `id` не меняется;
2. `apply()`: две `<i data-icon="message-text">` получают разные `id`;
   повторный `apply()` не вставляет заново; неизвестное имя — предупреждение
   без вставки;
3. `DS_ICONS` после `ds-icons.js`: те же 247 ключей, два чтения одного глифа —
   разные `id`; при обратном порядке загрузки замена случается при первом
   `apply()`;
4. порядок в `ds.js`: `ds-icons.js` сразу за `icons-data.js`, раньше каждого
   рантайма из списка, который читает `DS_ICONS`.

Селфтест — шаг гейта харнеса (правка `ds-icons.js`, `icons-data.js`,
`ds.js`, `ds-icon.mjs`) и шаг `ds-check.mjs --all` (ДС проверяет себя без
харнеса). **Откат:** на `ds-icons.js` до правки селфтест падает.

**В браузере:** страница прототипа с иконками и панелью — повторов `id` в
SVG-иконках документа нет, иконки видны; тост и снекбар с иконкой видны.

**Уточнено по ходу.**

- Первый замер кто вставляет глифы был неполным (только `ds-icons.js` и
  `ds-notify.js`): напрямую `DS_ICONS` читают ещё четыре рантайма экрана и
  страницы документации. Решение сменили на замену `DS_ICONS` внутри
  `ds-icons.js` — без правок в потребителях (§1–2).
- Проверка в браузере нашла повторы `id` внутри одной копии (экспорт пишет
  один `id` дважды) — первый вариант селфтеста сравнивал только копии между
  собой. Добавлены обработка повторов и кейс, доказанный откатом.
