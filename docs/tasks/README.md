# Задачи

Задача — документ, по которому идёт работа: человек ставит, агент уточняет и ведёт
по этапам, следующая сессия продолжает по нему и по handoff.

## Новая задача

1. Скопируй [0000-task-template.md](0000-task-template.md) в `<ID>-<slug>.md`.
   - `ID` — префикс автора и следующий номер после последнего своего: `RE0022`, `MS0017`.
     Префикс — это автор (RE — Roes, MS — mikhail), а не тип задачи.
   - Доработка той же задачи — буква к номеру: `MS0014a`, `MS0014b`.
   - `slug` — латиницей через дефис: `deal-navigator`.
2. Заполни обязательное: шапка, «Коротко», «Этапы», «Критерии приёмки», «Открытые
   вопросы» (таблица «№ · Вопрос · Ответ»: ответ вписывает человек, пусто — не отвечено).
   Необязательные разделы — только когда есть что написать.
3. Отметь старт: `node .agents/tools/task-cost.mjs start <ID>`.

## Файлы задачи

Все лежат здесь, рядом с задачей, и начинаются с её `ID`:

| Файл | Что | Кто пишет |
|---|---|---|
| `<ID>-<slug>.md` | сама задача | человек и агент |
| `<ID>-<slug>.handoff.md` | состояние для следующей сессии (`/handoff`, `/resume`) | агент, на границе этапа |
| `<ID>-<slug>.review.md` | отдельное ревью по [шаблону](0000-review-template.md); повторное — `.review-2.md` | ревьюер |
| `<ID>-<slug>.*.json` | доказательства: сводки снимков, отчёты сверки | инструмент |

Handoff, написанные до RE0021, остались в `apps/` — `/resume` находит и их.

## Статусы

`draft` — пишется · `open` — готова, не начата · `in-progress` — в работе ·
`review` — сделана, ждёт приёмки человеком · `done` — закрыта · `backlog` —
отложена · `superseded` — заменена другой задачей (ссылка в «Коротко»).

## Когда ревью — отдельным файлом

- **Вердикт в «Итоге» задачи** — обычная приёмка по роли `screen-reviewer` в том же
  заходе: строка `ВЕРДИКТ:` и что проверено.
- **Отдельный `.review.md`** — когда ревью делает другой человек или отдельная сессия,
  когда находок больше нескольких и их надо разбирать по номерам, или когда ревью
  порождает задачу-доработку. NEEDS-WORK → новая задача с буквой, находки — по номерам ревью.

## Необязательные разделы по типу задачи

| `type` | Обычно нужны |
|---|---|
| `screen` | Решения человека, Как сейчас (источник), Решение (экраны, данные, компоненты ДС), Решения агента |
| `ds` | Как сейчас, Решение (API, токены, документы ДС), Риски |
| `harness` | Как сейчас (замер), Решение (файлы, проверки), Вне задачи, Риски |
| `docs`, `fix` | часто хватает ядра |
| `research` | Решение (вопросы, источники, выводы), Вне задачи |

## Затраты

После каждого закрытого этапа: `node .agents/tools/task-cost.mjs mark <ID> Э<N>`.
Скрипт читает локальные журналы сессий агента (без сети), считает токены и активное
время с прошлой отметки и дописывает строку в раздел «Затраты» задачи, пересчитывая
«Итого». Под строкой — откуда взяты числа и сколько было запросов к модели и вызовов
inструментов (в таблицу не пишутся). Активное время — от сообщения человека до конца ответа агента; паузы между
ходами и ожидание ответа на вопрос агента не входят. Ожидание подтверждения прав
внутри хода от работы инструмента не отличить — оно входит.

Колонки токенов:

| Колонка | Что это |
|---|---|
| Вход | новое на входе, ещё не бывшее в кэше (плюс запись в кэш) |
| Кэш | контекст, повторно прочитанный из кэша |
| Выход | что написала модель (с рассуждениями) |
| Всего | Вход + Кэш + Выход по всем запросам этапа — объём работы, для стоимости и сравнения этапов и CLI |
| Пик окна | самый большой один запрос этапа — сколько модель держала в окне разом; в «Итого» — максимум, а не сумма |

«Всего» и окно модели не сравниваются: на каждом шаге агент заново отправляет весь
разговор, поэтому сумма по запросам в десятки раз больше окна (этап из 50 запросов
по 100 тыс. — это 5 млн «Всего» при пике 100 тыс.). Влезет ли этап в окно, говорит
«Пик окна». Без кэша (если CLI его не умеет) те же токены уходят во «Вход» — «Всего»
от этого не меняется.

В счёт идут только сессии, где ID задачи написал человек или агент (вывод
инструментов не в счёт): называйте задачу в разговоре — `/resume RE0021`,
«продолжаем RE0021». Параллельные сессии о другом не попадают. `--all-sessions` —
все сессии проекта за окно.

Читает журналы JSONL (две формы строки — список форм в шапке `task-cost.mjs`) и базу
opencode; для прочих CLI — общий читатель. Другой CLI — `node .agents/tools/task-cost.mjs probe`
покажет, где лежат его журналы и какие в них поля (без значений); по выводу
дописывается читатель. Пока его нет — ручной ввод:
`mark <ID> Э<N> --manual --tokens <N> --minutes <M> [--peak <N>]`.

- Субагент, чья сессия задачу не упоминает, в счёт не идёт: `mark` и `report`
  предупреждают строкой, `--all-sessions` его включает.
- Журналы с другой машины копируются каталогом той же формы
  (`<дом>/.<CLI>/projects/<папка проекта>/`) с сохранением времени — `cp -p`;
  затем `--home <дом копии>`. Имя `<папка проекта>` — путь к проекту **на той
  машине, где запускается `task-cost`**, в котором всё, кроме латинских букв и
  цифр, заменено на `-`: копия под именем с другой машины не найдётся. Нужное
  имя печатает `probe` (строка «ожидаемая папка журналов»).
- Отказ без чисел называет причину: журналов нет, журналы старше окна, форма не
  узнана, в окне нет записей, задача не упомянута.
- Служебные метки блока «Затраты» в тексте задачи не цитировать: метка, встреченная
  не один раз или не строкой целиком, — отказ `mark` без записи.

Факт этапов сборки — замер для калибровки сметы окна:
`ctx-budget.mjs --calibrate --stage <этап> --fact <пик окна>`. Смета считает
занятость окна, поэтому факт — «Пик окна», а не «Всего». Этап с субагентами —
пик сессий той роли, которую описывает этап (`review` — приёмщиков, `build-*` —
сборщика), а не ведущей сессии (RE0024).

**Итог по числам отчёта — командой, а не в уме.** Сумму колонки, разность меток,
долю считает команда (`node -e "…"`, `task-cost report`), в отчёт идёт её
вывод вместе с выражением. Выражение, записанное верно, не страхует от неверного
результата: в RE0022 при верной записи слагаемых итог 267,5 мин стоял как 318,4
и ушёл в выводы двух задач (Л236).
