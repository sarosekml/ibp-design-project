# Шаблон спецификации на разработку

## Коротко

- **Что.** Повторяемый шаблон передачи сценария в разработку: папка `<Spec>/` с двумя
  файлами — `<Spec>.md` (текст спецификации) и `<Spec>.html` (тот же текст плюс снимки
  экранов и компонентов, открывается сам по себе, без проекта и без сети).
- **Снимки — не растр.** Снимок — замороженный DOM состояния прототипа: разметка и
  стили ДС на момент съёмки, без скриптов. Текст выделяется, в DevTools видны классы
  ДС и размеры в px. Растровых скриншотов нет.
- **Где смотреть.** Концепт Post «Спецификации на разработку»
  (`apps/postrade/drafts/dev-specs/`): список спек, выбранная спека ровно в том виде,
  в каком уйдёт разработчикам, кнопки выгрузки.
- **Проба.** Сценарий «Корректировки процентов РСБУ» модуля `deals-app` (RE0013):
  страница `RsbuInterestAdjustments`, тайл `RsbuInterestAdjustmentsTile`, окно
  `RsbuAdjustmentModal`.

Решения человека 12.10.2026:

| Вопрос | Решение |
|---|---|
| Порядок | сначала план шаблона, затем реализация, проба на РСБУ, показ на странице концепта, выгрузку делает человек |
| Где страница | один концепт на все спеки: `apps/postrade/drafts/dev-specs/`, каждая следующая спека — туда же |
| Ширина снимков | 1920 × 1080, как макеты Post; ширина — параметр спеки |
| Объём текста | коротко, без текста ради текста; достаточно, чтобы спроектировать и сверстать |

## Objective

Дизайнер (или агент по скиллу `dev-spec`) пишет одну спеку-исходник по шаблону, запускает
генератор, открывает показанный им адрес — страница съёмки проходит по объявленным
состояниям прототипа и снимает их. Генератор собирает `<Spec>.md` и `<Spec>.html` и кладёт их
в концепт. Человек смотрит спеку на странице концепта и выгружает папку zip-архивом.

## 1. Шаблон

Исходник — `apps/postrade/drafts/dev-specs/refs/<Spec>/<Spec>.dev-spec.md`. Шаблон —
`.agents/skills/dev-spec/references/template.md`, процедура — `.agents/skills/dev-spec/SKILL.md`,
команда — `/dev-spec`.

Front matter: `spec`, `title`, `module`, `version`, `date`, `designer`, `sources`,
`viewport` (`1920x1080`), `base` — путь до `pages/` модуля от файла спеки, `snaps` —
снимки `{ id, title, page, do?, target?, note? }`. `do` — словарь действий `flows.yaml`
панели прототипа (`click`, `fill`, `press`, `hover`, `focus`, `scroll`, `waitFor`, `wait`);
`target` — селектор кадра, без него — экран целиком.

Разделы:

| № | Раздел | Что в нём |
|---|---|---|
| 1 | Коротко | что, зачем, роли и права, где в продукте — 3–6 строк |
| 2 | Сценарий | шаги «действие → результат» со снимками; ветки: ошибка, отмена, удаление |
| 3 | Экраны | по экрану: назначение, вход и параметры адреса, раскладка, компоненты ДС, снимок |
| 4 | Новые локальные компоненты | назначение, где стоит, размер (колонки сетки + px со снимка), состав из ДС, состояния (таблица + галерея снимков), поля, поведение, проверки, контракт |
| 5 | Данные и API | DTO, что нужно от бэкенда |
| 6 | Тексты | тосты, ошибки, подтверждения |
| 7 | Открытые вопросы | из спек и паспортов, с источником; не закрываются догадкой |

Маркеры в тексте: `<!-- snap: id -->` — снимок; `<!-- snaps: id1 id2 id3 -->` — галерея
состояний в ряд. В `<Spec>.md` маркер становится строкой «Снимок N — <название>
(<Spec>.html#snap-<id>)», в `<Spec>.html` — сам снимок с подписью и размером кадра.

## 2. Генератор `.agents/tools/dev-spec.mjs`

```bash
node .agents/tools/dev-spec.mjs <spec.dev-spec.md> --check   # разбор и проверки, без браузера
node .agents/tools/dev-spec.mjs <spec.dev-spec.md>           # сервер съёмки → сборка генерата
node .agents/tools/dev-spec.mjs --selftest
```

1. **Проверки.** Front matter и действия — ядром панели (`loadCore`, `schemaReader`);
   страницы снимков существуют, селекторы `target` и `do` есть в странице (`selectorMisses`,
   как у карты экранов); каждый маркер ссылается на объявленный снимок, каждый снимок
   использован.
2. **Съёмка.** Локальный HTTP-сервер по образцу `page-snapshot.mjs` (заморозка даты и
   `Math.random` — `injectFreeze`). Человек открывает напечатанный адрес в любом браузере:
   служебная страница открывает каждое состояние в iframe размера `viewport`, проигрывает
   `do`, сериализует DOM (значения полей — в атрибуты; без скриптов и без панели
   прототипа), режет кадр по `target` (цепочка предков без соседей + поддерево цели с
   шириной, снятой со страницы) и отдаёт серверу. CSS — только правила, которые находят
   что-то на снимках; шрифты — data-URI. **Браузер скриптом не запускается** (правила
   процесса §9: headless в контуре не согласуется).
3. **Сборка.** md → html своим маленьким конвертером; стиль страницы — на значениях
   токенов ДС, зашитых в файл. Генерат `apps/postrade/drafts/dev-specs/data/<Spec>.dev-spec.js`
   — `window.DEV_SPECS.push({ id, title, …, md, html })`, руками не правится.
4. Шага в гейте нет (как у карты экранов): проверка — в генераторе, `--check` зовётся
   вручную.

## 3. Концепт `apps/postrade/drafts/dev-specs/`

- `app.json`: `id: dev-specs`, `track: rnd`, «Post — Спецификации на разработку».
- `pages/index.html` (+ `index.screen.md`): список спек слева, справа выбранная спека в
  iframe — ровно тот `html`, что уйдёт разработчикам. Кнопки «Скачать папку (.zip)»,
  «.md», «.html». Работает по `file://`.
- `refs/<Spec>/` — исходники спек; `data/*.dev-spec.js` — генераты.

## Acceptance Criteria

- На хабе в колонке «Концепты» — «Post — Спецификации на разработку»; страница показывает
  спеку РСБУ со снимками: место тайла, три вида тайла, страница пустая и с данными, окно
  новой корректировки, окно с ошибкой, правка, подтверждение удаления.
- «Скачать папку (.zip)» отдаёт архив с папкой `RsbuInterestAdjustments/` и двумя файлами;
  `.html` открывается отдельно без сети и без проекта, снимки совпадают с живыми
  страницами; `.md` читается сам по себе.
- В снимках нет растровых картинок; классы ДС и размеры видны в DevTools.
- `dev-spec.mjs --selftest` и `--check` на спеке РСБУ — `ВЕРДИКТ: OK`;
  `lessons-cli.mjs gate` — `ВЕРДИКТ: OK`; `vendor-scan.mjs` — OK.

## Риски

| Риск | Что делаем |
|---|---|
| Снимок устаревает после правки прототипа | пересъёмка одной командой; дата съёмки в шапке спеки |
| Кадр компонента без соседей верстается иначе | ширина цели фиксируется размером со страницы; размер кадра — в подписи |
| Генерат тяжёлый (шрифты, CSS) | CSS — только используемые правила, шрифты — только используемые начертания |
| Браузер в контуре скриптом не запускается | съёмку запускает человек: открывает адрес, который печатает генератор |

## Открытые вопросы

1. Нужен ли шаг в гейте, сверяющий генерат с исходником. Пока нет — как у карты экранов.
2. Тема снимков — IBP Legacy (тема страниц без выбора). Нужны ли снимки в других темах —
   не решено.
