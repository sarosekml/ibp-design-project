# Контрольный заход в рабочем контуре (RE0022)

## Коротко

- **Зачем.** RE0018 (Э7) и калибровке сметы (перенесена туда из RE0020) нужны цифры с рабочего
  устройства: доходит ли гейт до `ВЕРДИКТ:` на свежей распаковке, ставится ли и работает ли
  `page-run`, сколько длится сборка экрана масштаба RE0017 и сколько окна съедает каждый этап.
- **Кто делает.** Агент в рабочем контуре — сам, по этому документу. Человек только распаковывает
  архив, запускает сессии одной фразой и в конце отправляет **этот файл** наружу.
- **Результат.** Заполненный раздел «Отчёт» ниже. Наружу уходит только этот md-файл; по нему вне
  контура записываются замеры в RE0018 и калибровка сметы.

## Как запускать (человеку)

1. Распаковать свежий архив репозитория **в новую пустую папку**. Ничего в ней не править.
2. Открыть в этой папке CLI-агент контура и написать:
   `Прочитай docs/tasks/RE0022-contour-run.md и выполни следующий этап.`
3. В конце каждой сессии агент пишет, нужна ли следующая. Если нужна — новая сессия, та же фраза.
4. Когда агент напишет «отчёт готов», отправить наружу файл `docs/tasks/RE0022-contour-run.md`.

Разрешения на команды подтверждать как обычно. Ожидание подтверждения попадает во время этапа,
это допустимо.

## Правила для агента

- **Следующий этап** — первый в «Этапах» без отметки `[x]`. Одна сессия — один этап. Закончил
  этап — отметь `[x]` с датой, заполни свою часть «Отчёта», напиши человеку, нужна ли следующая
  сессия, и остановись.
- **Время.** В начале и в конце этапа выполни `date -u +%Y-%m-%dT%H:%M:%SZ` и впиши результат.
  Длительность команд — через `/usr/bin/time -p <команда>` (строка `real`, секунды). Ничего не
  засекай «на глаз» и не оценивай: нет числа — пиши `—` и почему.
- **Что можно писать в отчёт.** Числа, вердикты, коды проверок (`ЖВ1`, `Б12`…), пути **внутри
  репозитория**, имена полей журнала. **Нельзя:** имена хостов, адреса реестров и серверов, имена
  пользователей, абсолютные пути (домашний каталог заменяй на `~`), содержимое журналов и
  внутренних файлов, данные из сессии. Файл уходит за пределы контура.
- **Ничего не чини** в оснастке, ДС и правилах, даже если упало: запиши, что упало (команда,
  строка `ВЕРДИКТ:`, первые строки `FAIL`/`ОШИБКА`), и иди дальше. Цель — замер, а не починка.
- Этот файл правишь только в разделах «Этапы» и «Отчёт».

### Э1. Механика — строго в этом порядке

Шаг 1 — **первым действием сессии**, до любых других команд и правок: от него зависит замер
«свежая копия из архива».

```bash
date -u +%Y-%m-%dT%H:%M:%SZ
/usr/bin/time -p node .agents/tools/lessons-cli.mjs gate            # 1. первый гейт
/usr/bin/time -p node .agents/tools/lessons-cli.mjs gate --full     # 2. полный гейт
uname -sm; sysctl -n hw.ncpu hw.memsize 2>/dev/null; node -v; npm -v  # 3. окружение
/usr/bin/time -p npm i --prefix tmp/page-run linkedom@0.18.13       # 4. зависимость прогона
node .agents/tools/page-run.mjs --selftest                           # 5.
/usr/bin/time -p node .agents/tools/page-run.mjs --all --flows       # 6. все страницы
node .agents/tools/task-cost.mjs probe                               # 7. журналы CLI
node .agents/tools/task-cost.mjs start RE0022                        # 8.
node .agents/tools/task-cost.mjs report RE0022 --from <начало Э1>     # 9. читаются ли журналы
date -u +%Y-%m-%dT%H:%M:%SZ
```

Упал шаг 4 (нет доступа к пакету) — шаги 5–6 дадут `ОШИБКА: linkedom не найден`; так и запиши,
текст ошибки npm — без адресов реестра. Шаг 9 — проба на этой же сессии: строки «источники» и
«запросов к модели» — в О3. Заполни разделы отчёта О1–О3.

- **В начале этапа:** `date -u …` → «начало». **В конце этапа:**
  1. `date -u …` → «конец»;
  2. смета этого этапа — та же команда `ctx-budget.mjs`, что в плане, с `--stage <этап>`;

  4. `node .agents/tools/task-cost.mjs report RE0022 --from <начало> --at <конец>` — в О4

     инструментов»; источник — из строки «источники» (`JSONL`, `общий: <форма>`). Ответ
     «журналов не найдено» — в этих графах `—`.

## Риски

| Риск | Что делаем |
|---|---|
| CLI-агент контура пишет журналы в форме, которую не узнаёт ни один читатель `task-cost` (включая общий) | видно уже в Э1 по пробе `report` (О3); графы токенов и вызовов — `—`; вывод `probe` — основа читателя; по меткам времени из О4 числа досчитываются следующим архивом, пока журналы лежат на машине |
| Общий читатель узнал форму, но понял её неверно (например, счётчик — нарастающий итог за сессию) | форма печатается в «источниках» и попадает в О4; вне контура её сверяют с выводом `probe` до записи калибровки |
| Первой командой сессии оказался не гейт — замер «свежей копии» испорчен | в О1 так и написать; повтор — новая распаковка |
| В отчёт попали внутренние данные | правила выше; `vendor-scan` ловит абсолютные пути; остальное — внимательность агента и взгляд человека перед отправкой |
