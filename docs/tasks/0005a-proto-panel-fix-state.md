# 0005a. Панель прототипа: Fix State, номера состояний, английский интерфейс

Подзадача `docs/tasks/0005-proto-panel.md`. Исходная точка — панель в том
виде, в каком она сделана по 0005: рантайм `.agents/proto-panel/`, оснастка
`.agents/tools/proto-panel.mjs`, описание `.agents/proto-panel/README.md`
(владелец форматов), скилл `.agents/skills/proto-panel/SKILL.md`, команда
`/panel`, пилот `apps/ib/drafts/ai-bankster-prototype-v02/proto-panel/`.

## Коротко

- **Fix State.** Дизайнер работает с прототипом как обычно: кликает,
  вводит, пробует. Дошёл до состояния, которое хочет запомнить, — открыл
  панель (`Alt+Shift+P`) и нажал **Fix State** в шапке шторки (или сразу
  `Alt+Shift+S`, не открывая панель). Панель превращает клики и ввод,
  сделанные на странице с момента её открытия, в шаг сценария и дописывает
  его в `flows.yaml`. Схема собирается по ходу работы и тестов, без промпта
  агенту.
- **Номера State NN.** Каждое состояние получает постоянный номер, сквозной
  по прототипу: State 01, State 02, … Номер не меняется при переименовании и
  переносе в другой сценарий и не выдаётся повторно после удаления. По нему к
  состоянию обращаются человек («что не так в State 07»), агент, комментарии,
  адрес шага. Шаги, которые написал агент, нумерует сборка — у пилота это
  State 01–11.
- **Название** генерируется само: подпись последнего нажатого элемента или
  заголовок страницы. Переименовать можно сразу в панели (после фиксации
  поле названия открыто) или позже агентом: `/panel <app> states`,
  «переименуй State 07 в …».
- **Весь интерфейс панели — на английском.** Форматы файлов и сообщения
  оснастки для агента остаются русскими.
- **Под капотом:** пассивная запись действий на странице (`recorder.js`),
  подбор устойчивых селекторов, запись `flows.yaml` из браузера тем же путём
  «прочитать → слить → записать», что у комментариев, каноническая форма
  файла и нумерация — в ядре и в сборке.

## Objective

Схема сценария собирается двумя путями, и оба ведут в один файл: агент
описывает сценарии по ТЗ (как в 0005), а дизайнер фиксирует состояния прямо
в работе с прототипом. У каждого состояния есть номер, по которому к нему
однозначно обращаются в разговоре, в комментариях и в оснастке. Интерфейс
панели — английский.

## 1. Исходная точка и что меняется

| Что | После 0005 | В 0005a |
|---|---|---|
| `flows.yaml` | пишет агент, браузер только читает; у шага `id`, `title`, `page`, `note`, `do` | браузер дописывает зафиксированные состояния; у шагов номера `state`; у файла каноническая форма; пустой сценарий допустим |
| Проигрыватель (`runner.js`) | точки входа и приращения, `pending`, страж, «изменено вручную» | цель по тексту (`text`), события для записи, адрес шага по номеру, свои элементы панели не попадают в поиск цели |
| Запись на диск (`store.js`) | `save` — только `comments.md` | `saveFlows` — `flows.yaml` тем же путём; журнал черновых операций; «Download flows.yaml» |
| Запись действий | нет | `recorder.js` — пассивно, с открытия страницы |
| Интерфейс | по-русски, ~220 строк в шести файлах | по-английски, все строки — модуль `strings.js`; сторож ПН10 не пускает кириллицу в строках кода |
| Ссылка комментария на шаг | `- Шаг: <сценарий>/<шаг>` | `- Шаг: State 07`; старая форма читается, сборка переводит |
| Горячие клавиши | `Alt+Shift+P`, `Alt+Shift+→ / ←` | плюс `Alt+Shift+S` — Fix State |
| Оснастка | сборка, `--check` ПН1–ПН10, `--list`, `--resolve` | сборка нумерует и приводит к канонической форме; ПН11–ПН12; `--states`, `--state`; новые кейсы селфтеста |

## 2. Решения

### 2.1 Что значит «зафиксировать состояние»

Состояние страницы прототипа — это адрес страницы плюс всё, что с ней
сделали после открытия. Внутреннее состояние её скрипта сохранить нельзя,
поэтому восстановить состояние можно только проигрыванием — так уже устроен
проигрыватель 0005. Значит, Fix State записывает рецепт:

- **страница**, с которой началась текущая загрузка (файл в `pages/` с
  параметрами адреса, без `#`);
- **действия** после её открытия — на языке сценариев 0005 (`click`, `fill`,
  `press`), с устойчивыми селекторами.

Действия пишет `recorder.js` — **всегда, без кнопки «начать запись»**: он
тихо ведёт журнал текущей загрузки страницы в памяти вкладки. Журнал живёт
до перезагрузки или перехода на другую страницу, на диск сам не попадает.
Fix State берёт из журнала нужный кусок и превращает его в шаг (§5.4):

- **приращение** — если текущее состояние продолжает последний шаг
  выбранного сценария: в шаг идут только новые действия;
- **точка входа** — во всех остальных случаях: `page` + все действия с
  открытия страницы, включая проигранные панелью. Такой шаг самодостаточен и
  воспроизводится всегда.

В журнал попадают только настоящие действия человека (`isTrusted`).
Действия, которые проиграла сама панель, рекордер получает от проигрывателя
напрямую, в готовом виде.

### 2.2 Номера состояний

- У каждого шага поле `state: N` — целое, уникальное **в пределах
  приложения** (через все сценарии), постоянное. В корне файла —
  `lastState: N`, наибольший когда-либо выданный номер: после удаления номер
  не переиспользуется.
- Подпись — `State ` и номер минимум из двух цифр: State 01, State 12,
  State 105.
- Кто выдаёт номер: браузер — в момент записи, по свежему файлу
  (`lastState + 1`); сборка — шагам без номера (их пишет агент), по порядку
  в файле. Агент номера руками не пишет и не меняет.
- `id` зафиксированного шага — `state-12`. Агент может дать осмысленный
  `id` — номер остаётся тем же.
- По номеру ссылаются: интерфейс, плеер, комментарии (`- Шаг: State 07`),
  адрес шага (`#pp=07`), оснастка (аргумент `07`, `7`, `State 07` или
  `state-07`).
- Шаги сценария в YAML по-прежнему лежат в `steps` — формат не ломается; в
  интерфейсе шаг называется **state**.

### 2.3 Куда пишется

- В тот же `flows.yaml`: схема одна. Браузер пишет его так же, как
  `comments.md`: через подключённую папку проекта, «прочитать свежий файл →
  применить операцию → каноническая запись → зеркало». Параллельная правка
  агентом не теряется: операции применяются к свежему файлу.
- **Каноническая форма** (§4.3): её пишут и браузер, и сборка, поэтому
  запись из панели не даёт «шумного» диффа. Комментарии YAML допустимы
  **только шапкой файла**: браузер и сборка переписывают файл целиком, и
  комментарий внутри потерялся бы. Файл с комментарием внутри ни сборка, ни
  панель не переписывают — это дефект ПН11, пояснение переносится в `note`
  шага или в шапку.
- Без подключённой папки операции копятся **журналом черновиков** в
  браузере и видны на схеме с пометкой «Unsaved»; после подключения
  записываются одной операцией слияния. Запасной путь — «Download
  flows.yaml».

### 2.4 Английский интерфейс

- Все тексты интерфейса — в одном модуле `strings.js` (`t(key, vars)`),
  остальные файлы берут строки только оттуда. Сторож ПН10 (§10.3) не
  пропускает кириллицу в строковых литералах рантайма, кроме `core.js` и
  `strings.js`. Комментарии в коде остаются русскими (process.md).
- **Не переводятся:**
  - форматы файлов: ключи и статусы `comments.md` (`Когда`, `открыт` …),
    заголовки `## К-3 · …`;
  - содержимое: названия сценариев и состояний, заметки, тексты
    комментариев. Автоназвания берутся из подписей прототипа и остаются на
    его языке;
  - диагностика ядра — сообщения ПН1–ПН3 о разборе `flows.yaml` и
    `comments.md`: тот же текст видит гейт и агент. В панели он стоит под
    английским заголовком.
- Стиль: sentence case («Play from start», «Connect project folder»);
  собственные имена — как в постановке: **Fix State**,
  **State 07**. Номер комментария `К-3` выглядит латиницей и не меняется.

### 2.5 Чего в 0005a нет

- Перетаскивание (drag and drop), наведение, ввод внутри фреймов, выбор
  файла — не записываются. Шаг получает пометку (§5.6), панель
  предупреждает.
- Правка действий шага в интерфейсе, перестановка шагов перетаскиванием,
  ветвления, картинки шагов, выгрузка в PlantUML.
- Автоматическая проверка записанного шага повторным проигрыванием: клик
  по узлу и есть проверка, делает её человек.

## 3. Как это выглядит у дизайнера

1. Открыл страницу прототипа и работает: кликнул «Конструктор», ввёл
   «Северный», выбрал группу.
2. `Alt+Shift+P` — в шапке шторки кнопка **Fix State**. В табе «Сценарии»
   дизайнер нажал **New flow** — появился пустой сценарий «Flow 03». Под
   выбором сценария — строка рекордера: «Since RequestThread.html opened: 3
   actions · Fix State adds them as State 12 (new entry point)».
3. **Fix State** — в сценарии появляется State 12, поле названия открыто, в
   нём выделено автоназвание «ГК «Северный агрохолдинг»». `Enter` —
   сохранить своё название, `Esc` — оставить автоназвание. Без New flow
   состояние легло бы в конец выбранного сценария.
4. Шторка закрыта кликом мимо, работа продолжается: «Отправить». Снова Fix
   State — State 13, «continues State 12»: в шаг попал только клик
   «Отправить».
5. `Alt+Shift+S` — фиксация без шторки: снекбар «State 14 fixed» с кнопкой
   «Rename».
6. Клик по узлу State 12 на схеме — страница открывается заново и приходит в
   это состояние: запись проверена.
7. Позже — агенту: `/panel <app> states` (привести названия и селекторы в
   порядок) или «переименуй State 13 в „Запрос отправлен“».

## 4. `flows.yaml`: что добавляется

### 4.1 Поля

| Где | Поле | Что | Кто пишет |
|---|---|---|---|
| корень | `lastState` | наибольший выданный номер состояния; не уменьшается | браузер, сборка |
| шаг | `state` | номер состояния, целое > 0, уникальное в файле | браузер при фиксации, сборка — шагам без номера |
| шаг | `recorded` | когда зафиксирован: `ДД.ММ.ГГГГ ЧЧ:ММ`; признак «записан из панели» | браузер |
| шаг | `issues` | список пометок записи: `fragile`, `frame`, `drag`, `file`, `truncated` (§5.6) | браузер; агент снимает, когда разобрал |
| действие | `text` | цель по тексту: из совпавших с `target` берутся элементы, у которых `aria-label` или видимый текст (пробелы схлопнуты, края обрезаны) равен `text`; `index` считается уже среди них. У `click`, `hover`, `focus`, `scroll`, `waitFor` | браузер (рекордер), агент |
| сценарий | `steps` | может быть пустым (`steps:` без значения) — сценарий, созданный кнопкой «New flow», до первой фиксации | браузер |

Порядок полей шага: `state`, `id`, `title`, `page`, `note`, `recorded`,
`issues`, `do`. У первого шага сценария `page` по-прежнему обязателен —
первый зафиксированный шаг пустого сценария всегда точка входа (§5.4).

### 4.2 Пример: пилот после сборки и зафиксированные состояния

Сценарии агента получили номера 01–11; дизайнер нажал «New flow» и
зафиксировал в новом сценарии три состояния — по истории из §3.

```yaml

# Формат — .agents/proto-panel/README.md, раздел «flows.yaml».
# После правки: node .agents/tools/proto-panel.mjs (пересобрать зеркало).
version: 1

  - id: report-from-builder
    title: Отчёт из конструктора
    desc: Новый чат → конструктор → подготовка → готовый отчёт → просмотр в split view → выгрузка
    steps:
      - state: 1
        id: home
        title: Главная
        page: index.html
        note: Точка входа — плитка «AI Pitcher» в группе Origination.
      - state: 2
        id: new-chat
        title: Новый чат
        page: RequestThread.html
        note: Пустая нить — точка входа в раздел. Слева недавние запросы, по центру поле запроса.
      - state: 3
        id: builder-open
        title: Открыть конструктор
        note: Конструктор выезжает внутри поля запроса и не уводит со страницы.
        do:
          - click: '#btnBuilder'
          - waitFor: '#cmpDrawer.is-open'
      # … State 4–8 — остальные шаги сценария

  - id: report-from-history
    title: Готовый отчёт из истории
    desc: Запрос с готовым материалом → просмотр → просмотр на всю ширину
    steps:
      # … State 9–11

  - id: flow-03
    title: Flow 03
    steps:
      - state: 12
        id: state-12
        title: ГК «Северный агрохолдинг»
        page: RequestThread.html
        recorded: 24.09.2026 18:40
        do:
          - click: '#btnBuilder'
          - fill:
              target: '#bldFind'
              value: Северный
          - click: '[data-obj="sah"]'
      - state: 13
        id: state-13
        title: Отправить
        recorded: 24.09.2026 18:41
        do:
          - click: '#btnSend'
      - state: 14
        id: state-14
        title: State 14
        recorded: 24.09.2026 18:42
        issues:
          - fragile
        do:
          - click:
              target: '[data-act="finish"]'

          - click:
              target: '#thrMsgs > div:nth-of-type(4) button'
              index: -1
```

- State 12 — точка входа (`page`): страница открыта заново, в шаге все
  действия с её открытия.
- State 13 — приращение к State 12: только клик «Отправить».
- State 14 — приращение к State 13: человек ждал индикатор подготовки 6 с —
  у клика по нему `timeout: 7500` (§5.4); у второго клика нашёлся только
  структурный селектор — пометка `fragile` (§5.3, §5.6); у кнопки без
  подписи нет и автоназвания — «State 14» (§5.5).

Цель по тексту выглядит так:

```yaml
          - click:
              target: '.menu__item'
              text: Краткий — PDF
```

(Комментарии `# …` в примере — для читателя постановки; в настоящем файле
комментарии внутри запрещены, §2.3.)

### 4.3 Каноническая форма

Её строит `core.serializeFlows(doc)`; `serializeFlows(readFlows(x))`
идемпотентна, а для канонического `x` возвращает `x` байт в байт (селфтест).

- Шапка — подряд идущие строки-комментарии в начале файла, как есть (без
  хвостовых пробелов). Нет шапки — стандартная из трёх строк (как у
  заготовки `--enable`).
- Корень: `version`, `lastState`, `flows`. Между сценариями — одна пустая
  строка, перед первым — нет. Отступ — два пробела, списки — `- ` под
  ключом с тем же отступом, что в 0005.
- Поля — в фиксированном порядке (§4.1; сценарий: `id`, `title`, `desc`,
  `steps`). Пустое значение не пишется.
- Действие — **минимальная форма**: короткая (`click: '<селектор>'`,
  `press: Enter`, `wait: 300`), если, кроме цели или клавиши, все параметры
  по умолчанию (`index: 0`, `timeout: 4000`, `state: visible`, `block:
  center`, модификаторы выключены). Иначе полная, параметры в порядке
  `target`, `text`, `value`, `key`, `index`, `state`, `block`, `timeout`,
  `alt`, `shift`, `ctrl`, `meta`; значения по умолчанию не пишутся.
- Скаляры:
  - селектор (`target`) — всегда в одинарных кавычках, `'` внутри удваивается;
  - остальные строки — простым скаляром, если это безопасно: одна строка,
    без пробелов по краям, не начинается с `[ ] { } & * ! | > ' " % @ #`,
    обратной кавычки, `- `, `? `, `: `, не содержит `: ` и ` #`, не похожа
    на число, `true`, `false`, `null`, `~`, не пустая; иначе — в одинарных
    кавычках;
  - многострочная `note` — блоком `|`;
  - числа — цифрами, логические — `true` / `false`.
- Файл заканчивается одним переводом строки, LF.

Пилот при первой сборке меняет только форму: двойные кавычки селекторов
станут одинарными, у шагов появятся номера. Смысл сценариев тот же — это
проверяет селфтест (нормализованные модели до и после равны).

### 4.4 Проверки схемы (дополняют ПН2)

- `lastState` — целое ≥ 0; `state` — целое > 0; `recorded` — `ДД.ММ.ГГГГ
  ЧЧ:ММ`; `issues` — список известных кодов; `text` — непустая строка в
  одну строку, только у глаголов с целью, кроме `fill`.
- Неизвестные поля — как в 0005: ошибка с подсказкой.
- Нумерация и форма — отдельные коды ПН11–ПН12 (§10.3).

## 5. Запись действий — `recorder.js`

Новый файл рантайма, подключается после `runner.js`. Всё, что не требует
DOM (из чего складывается шаг, номера, форма файла), — в `core.js`, чтобы
это проверял селфтест.

### 5.1 Что записывается

Слушатели — на `document`, фаза захвата. Учитываются только события
`isTrusted`, не из своих элементов панели (`.pp-root`, `#pp-drawer`,
`.pp-modal`, `.pp-hl`, слои снекбаров и тостов) и не во время проигрывания
(`runner.busy()`).

| Что сделал человек | Как ловится | Что попадает в журнал |
|---|---|---|
| клик по элементу, который реагирует на клик (§5.2) | `pointerdown` запоминает цель и координаты до того, как обработчики страницы поменяют DOM; `click` подтверждает | `click` |
| клик мимо, пока на странице открыт плавающий слой ДС (меню `.menu.is-open`, выпадающий список, поповер) | тот же `click` по элементу, который не реагирует на клик | `click: 'body'` — закрытие слоя кликом мимо |
| прочий клик мимо | — | ничего |
| ввод в текстовое поле (`input` кроме кнопок, чекбоксов, радио, файла, `range`, `color`; `textarea`; `contenteditable`) | `input` копит **отложенный ввод** по полю | `fill` со значением поля, когда: началось другое действие, поле потеряло фокус, нажат Fix State |
| выбор в `<select>` | `change` | `fill` |
| `Enter` в текстовом поле (без `Shift`) | `keydown` | сначала отложенный `fill`, затем `press: { key: Enter, target: <поле> }` |
| `Escape` | `keydown` | `press: Escape` (цель — поле, если фокус в поле страницы) |
| `Enter` и пробел на кнопке | браузер сам делает `click` | `click` (отдельного `press` нет) |
| перетаскивание: сдвиг больше 6 px между `pointerdown` и `pointerup` | pointer-события | ничего; пометка `drag` |
| клик по `input[type=file]` | `click` | ничего; пометка `file` |
| фокус ушёл во фрейм (превью в `#pv`) | `window` `blur`, `document.activeElement` — `IFRAME` | ничего; пометка `frame` |
| прокрутка, наведение, `Tab`, стрелки | — | не пишется |

Поле пароля (`type=password`) не записывается. В README панели —
предупреждение: введённые значения попадают в `flows.yaml` и в репозиторий,
настоящие данные в прототип не вводить.

### 5.2 На что кликнули

Цель клика — ближайший предок, который реагирует на клик:

1. `a[href]`, `button`, `input`, `select`, `textarea`, `label`, `summary`,
   `[role=button|link|tab|option|menuitem|menuitemcheckbox|menuitemradio|checkbox|radio|switch|treeitem]`,
   `[tabindex]:not([tabindex="-1"])`, `[onclick]`;
2. если такого нет — элемент с `cursor: pointer`: курсор наследуется, поэтому
   берётся **внешний** элемент, который его объявил (у его родителя курсор
   уже другой). В прототипах так помечены строки и карточки с обработчиком
   на делегировании.

Не нашлось ни того, ни другого — клик считается «мимо» (§5.1).

### 5.3 Селектор цели

`describe(el)` → `{ target, text?, index, fragile }`. Стратегии — по порядку,
первая, которая даёт **единственное совпадение** среди элементов страницы
(свои элементы панели в счёт не идут):

1. `#id` — если `id` — латиница, цифры, `_`, `-`; не начинается с `pp-`; не
   похож на сгенерированный (нет четырёх и больше цифр подряд, нет
   hex-хвоста из восьми и больше символов, нет `:`).
2. Атрибут `data-*`: `[data-act="open"]`. Сначала «говорящие» —
   `data-act`, `data-id`, `data-obj`, `data-focus`, `data-thread`,
   `data-menu`, `data-modal`, `data-drawer`, `data-tab`, `data-value`,
   `data-key`, `data-col`, `data-sort`, `data-flow`; затем прочие, кроме
   служебных и изменчивых: `data-icon`, `data-illu`, `data-tooltip*`,
   `data-pp*`, `data-menu-*` (кроме `data-menu`), `data-popover-*`,
   `data-modal-*`, `data-drawer-*`, `data-tabs-*`, `data-state`,
   `data-selected`, `data-open`, `data-active`. Затем пара атрибутов.
3. `name` у полей: `input[name="…"]`; `aria-label`: `button[aria-label="Закрыть просмотр"]`.
4. С областью: ближайший предок с устойчивым `id` или атрибутом из п. 2 —
   `#pv [data-menu="doc-menu"]`, `#pv button[aria-label="…"]`.
5. По тексту: `target` — тег и первый класс компонента (не `is-*`, без
   `--`), `text` — подпись элемента (`aria-label` или видимый текст до 60
   символов): `{ target: '.menu__item', text: 'Краткий — PDF' }`.
6. Класс с областью: `#hist .entity`.
7. Структурный путь от ближайшего предка с `id` (или от `body`):
   `#hist > div:nth-of-type(3) > button` — **хрупкий** (`fragile: true`).

Если селектор совпал с несколькими элементами, `index` — место цели среди
них; цель последняя — `index: -1` (списки в прототипах растут с конца).
Значения атрибутов в селекторе — в двойных кавычках, спецсимволы экранируются
(`CSS.escape`). Хрупкий селектор даёт шагу пометку `fragile`.

### 5.4 Журнал и из чего складывается шаг

Журнал загрузки страницы (в памяти, `PP._recorder`):

```
trail = {
  page:    'RequestThread.html?id=1',   // путь от pages/ + параметры; без #
  log:     [{ action, replayed, at, label, fragile }],   // action — нормализованное действие ядра
  mark:    0,                          // место в log после последнего Fix State на этой загрузке
  lastFix: null | { flow, state },     // что зафиксировано последним на этой загрузке
  base:    null | { flow, step, at },  // проигрыватель довёл страницу до этого шага; at — длина log в этот момент
  flags:   [{ code, at }]              // пометки §5.6 с местом в log
}
```

- Проигрыватель сообщает о себе событиями (§8): в начале прогона без
  перезагрузки — `lastFix = null`; каждое выполненное действие — в `log` с
  `replayed: true`; в конце — `base = { flow, step, at: log.length }`. После
  перезагрузки журнал новый.
- Действие человека — в `log` с `replayed: false`; отложенный ввод
  дописывается при следующем действии, потере фокуса или Fix State.
- Предел — 300 действий на загрузку; дальше запись останавливается,
  пометка `truncated`.

Шаг складывает **`core.composeState(input)`** — чистая функция, её
проверяет селфтест:

```
composeState({ trail, flow, n, when, title }):
  last = последний шаг flow или null
  user(i) = действия log с места i, кроме replayed
  если last и trail.lastFix = { flow.id, last.state }:          // продолжаем свою же фиксацию
      acts = user(trail.mark); mode = 'increment'
  иначе если last и trail.base = { flow.id, last.id }:          // панель довела до last, дальше руками
      acts = user(trail.base.at); mode = 'increment'
  иначе:                                                        // всё остальное — самодостаточная точка входа
      acts = все действия log (и проигранные, и свои); mode = 'entry'
  если mode = 'increment' и acts пуст → { error: 'nothing-changed' }
  шаг = { state: n, id: 'state-' + pad2(n), title, recorded: when,
          page: mode = 'entry' ? trail.page : нет,
          issues: коды flags и fragile в пределах acts, если есть,
          do: acts с поправкой timeout (ниже) }
  → { step, mode }
```

- **Пустой сценарий** — всегда точка входа (у `last` нет).
- **Ожидания.** Каждое действие проигрывателя само ждёт свою цель до
  `timeout`, поэтому явные `waitFor` рекордеру не нужны. Если человек ждал
  результата дольше 3,5 с (пауза между действиями), у следующего действия
  `timeout = min(пауза + 1500, 15000)` с округлением вверх до 500 мс.
- **После фиксации:** `lastFix = { flow, state: n }`, `mark = log.length`,
  проигрыватель ставит состояние сессии на новый шаг (`dirty: false`) —
  плеер показывает «N / N · State 12».
- **Ничего не изменилось** (приращение без действий) — шаг не создаётся,
  тост «Nothing changed since State 12».

### 5.5 Автоназвание

Считается в браузере, подпись запоминается **в момент действия**: к моменту
фиксации элемента может уже не быть.

- Подпись элемента: `aria-label` → `title` → видимый текст (пробелы
  схлопнуты, первая строка) → у поля: текст `<label for>` или
  `placeholder`, затем `name`. Обрезка до 40 символов с многоточием.
- Название шага — подпись цели **последнего действия человека** в шаге:
  `click` и `press` — подпись элемента (у `press` без подписи — имя
  клавиши); `fill` — «подпись поля: значение». Точка входа без действий —
  заголовок страницы до первого « — », « | » или « - »
  («Новый отчёт — AI Pitcher — IBP» → «Новый отчёт»). Ничего не нашлось —
  «State 12».

### 5.6 Пометки записи (`issues`)

| Код | Когда | Что видит человек (EN) | Что делает агент |
|---|---|---|---|
| `fragile` | у действия структурный селектор (§5.3, п. 7) | Selector may break | даёт элементу `id` или `data-*` в прототипе, меняет селектор |
| `frame` | человек работал во фрейме превью | Actions in the preview frame were not recorded | параметр адреса в прототипе или другой путь к состоянию |
| `drag` | было перетаскивание | A drag gesture was not recorded | то же |
| `file` | открывался выбор файла | A file chooser was not recorded | то же (в пилоте файлы «прикладываются» кнопкой без диалога) |
| `truncated` | журнал упёрся в 300 действий | Recording stopped after 300 actions | перезаписать короче или разбить |

Пометки — подсказка, а не дефект: гейт их печатает заметками (§10.3),
вердикт не краснеет. Агент снимает `issues`, когда разобрал
(`--state … --clear-issues` или правкой файла).

## 6. Запись `flows.yaml` из браузера

### 6.1 Операции

Все правки схемы из браузера — операции над документом, одна функция ядра
**`core.applyFlowOps(doc, ops)`**. Её же зовёт превью черновиков (§6.3) —
логика одна.

| Операция | Что делает | Ограничения |
|---|---|---|
| `addFlow { ref, title? }` | новый сценарий: `id` — первый свободный `flow-NN`, `title` — «Flow NN»; `steps` пуст | — |
| `renameFlow { flow, title }` | название сценария | `title` непустой |
| `addState { ref, flow, step }` | номер `lastState + 1` по свежему файлу, `id` `state-NN` (занят — с суффиксом `-2`), шаг в конец сценария; `lastState` растёт | в пустой сценарий — только шаг с `page` |
| `renameState { state, title }` | название шага | `title` непустой |
| `deleteState { state }` | удалить шаг; номер не возвращается | только если от шага ничего не зависит: он последний в сценарии или следующий шаг — точка входа (`page`) |

`ref` — временная метка операции: по ней UI сопоставляет черновой номер с
выданным. `flow` и `state` в операциях могут ссылаться на `ref` ещё не
записанных операций из того же журнала.

### 6.2 Запись

`store.saveFlows(ops)` — тот же путь, что `save` у комментариев:

```
ensureAccess (подключено / разрешение по жесту / отказ)
src = прочитать flows.yaml                       // свежий файл, не память
r = core.readFlows(src)
ошибки разбора или комментарии внутри → FormatError('flows.yaml') — ничего не писать
doc = r.doc; core.numberStates(doc)              // файл мог прийти без номеров от агента
res = core.applyFlowOps(doc, ops)
text = core.serializeFlows(doc)
записать flows.yaml → прочитать comments.md → записать panel-data.js (core.mirrorText)
обновить данные, bus 'saved-flows' { added: { ref → n }, created: { ref → id } }
```

- Номер назначается **по свежему файлу**: если агент или вторая вкладка
  успели выдать State 12, фиксация получит State 13. Панель сообщает, если
  выданный номер не совпал с показанным черновым: «Saved as State 13».
- Ошибка записи — операции остаются в журнале черновиков, Alert с причиной
  и кнопкой «Retry».

### 6.3 Черновики без подключённой папки

- Журнал операций — `localStorage`, `pp.flowOps:<app>`.
- **Превью:** данные сценариев для интерфейса и проигрывателя = зеркало +
  `core.applyFlowOps(копия, журнал)`. Черновые номера — от `lastState`
  зеркала; черновой шаг помечен «Unsaved» и **проигрывается** так же, как
  записанный.
- После подключения папки журнал пишется одной операцией `saveFlows` —
  вслед за черновиками комментариев; тост «Saved: 2 states».
- «Download flows.yaml» — канонический текст превью (шапка и `lastState`
  берутся из зеркала: в данные зеркала добавляются `flowsHeader` и
  `lastState`, §10.1). Файл кладут в папку прототипа или отдают агенту.

## 7. Интерфейс

Всё на компонентах ДС, свои блоки — только на токенах (правила 0005 и
ПН10 действуют).

### 7.1 Кнопка Fix State

- В шапке шторки, в `.drawer__acts` перед кебабом: Button outline S, глиф
  `bookmark-add`, подпись **Fix State**. Тултип: «Save the current prototype
  state to “{flow}” · Alt+Shift+S».
- Неактивна, тултип объясняет почему:
  - идёт переход к шагу — «Wait until the flow finishes»;
  - в `flows.yaml` ошибки или комментарии внутри — «flows.yaml has errors —
    ask the agent: /panel {app} flows»;
  - нет данных панели — «No panel data — rebuild: node .agents/tools/proto-panel.mjs».
- Нажата — фиксация в **выбранный** сценарий таба «Сценарии» (сценариев нет —
  сначала создаётся «Flow 01»). Шторка переключается на «Сценарии»,
  прокручивает к новому узлу и открывает поле названия (§7.2).
- `Alt+Shift+S` — то же без шторки: снекбар ДС «State 12 fixed» (текст —
  название и сценарий), кнопка «Rename» открывает шторку с полем названия.
  Без подключённой папки — «State 12 saved in this browser only» и кнопка
  «Connect folder».

### 7.2 Таб «Сценарии»

- **Шапка таба:** выбор сценария (DropdownList, подпись «Flow»); рядом
  IconButton S `edit` «Rename flow» — название сценария правится в поле
  ввода на месте; Button transparent S `add` **New flow** — создаёт сценарий
  «Flow NN» и выбирает его. Ниже — «Play from start» (accent S) и «Stop flow».
- **Строка рекордера** (своя, `--type-body-s`, `--text-secondary`, глиф
  `circle-filled-small` тоном `--error` — «идёт запись»): что сделает Fix
  State прямо сейчас — результат `composeState` без записи:
  - «Since {page} opened: 3 actions · Fix State adds them as State 12 (new
    entry point)»;
  - «2 actions since State 12 · Fix State adds State 13 (continues State 12)»;
  - «No actions since State 12»;
  - кнопка transparent XS «Show» раскрывает список действий: «Click
    “Конструктор”», «Type “Северный” in “Найти объект”», «Press Enter»; у
    хрупких — глиф `alert-triangle`.
- **Узел** (правки к узлу 0005):
  - Avatar — номер состояния («12»), над названием — надстрочная подпись
    `--type-body-xs`, `--text-secondary`: **STATE 12**, рядом Chip XS:
    «Recorded» (есть `recorded`), «Unsaved» (черновик), «current» /
    «current · changed»;
  - мета — «RequestThread.html · 3 actions» у точки входа, «3 actions» у
    приращения;
  - пометки `issues` — строки с глифом `alert-triangle` тоном `--warning`
    (тексты §5.6);
  - меню узла: «Go to state», «Copy state link», «Comment on state»,
    «Rename», «Delete state». «Delete state» неактивен, если от шага зависят
    следующие (§6.1), тултип «Later states depend on this one — ask the
    agent to restructure the flow»;
  - **Rename** — название заменяется полем InputText M с кнопками «Save»
    (accent S) и «Cancel» (transparent S); `Enter` — сохранить, `Esc` —
    отмена. После Fix State поле открыто само, автоназвание выделено;
  - удаление — вложенный диалог подтверждения ДС: «Delete State 12?» / «It
    will be removed from flows.yaml; the previous version stays in git
    history. The number 12 will not be reused.» / «Delete».
- **Пустой сценарий** — EmptyState M «No states yet» / «Work with the
  prototype and press Fix State (Alt+Shift+S) to save the current state
  here.»
- **Нет сценариев** — EmptyState M «No flows yet» / «Press Fix State to
  start one, or ask the agent: /panel {app} flows».

## 8. Проигрыватель: что меняется

- **Цель по тексту.** `find` фильтрует совпадения `target` по `text`
  (подпись: `aria-label`, иначе `innerText`; пробелы схлопнуты, края
  обрезаны), `index` считается среди них. В сообщении — `click
  '.menu__item' “Краткий — PDF”` (`core.describeAction`).
- **Свои элементы не цель:** из совпадений убираются элементы панели
  (`#pp-drawer`, `.pp-root`, `.pp-modal`) — скрытая шторка лежит в DOM и
  могла бы сбить `index`.
- **События для рекордера** (шина `PP._bus`): `replay-start { flow, from,
  to, reload }`, `replay-action { flow, step, action }` после каждого
  выполненного действия; в конце — уже существующее `step`.
- **Номер в состоянии и адресе:** `current()` отдаёт `state`; адрес шага —
  `#pp=07` (старый `#pp=<сценарий>/<шаг>` понимается по-прежнему);
  `setAt(flowId, stepId)` — поставить состояние сессии после фиксации.
- **Сообщения** — английские, из `strings.js` (§7.6); `console.warn` с
  префиксом `[proto panel]`.

## 9. Комментарии: ссылка на State NN

- Каноническая строка метаданных: `- Шаг: State 07`. Ключ остаётся `Шаг`
  (формат файла русский, §2.4).
- `parseComments` читает три формы: `State 07`, `state-07` и прежнюю
  `<сценарий>/<шаг>`. Модель: `step: { state: 7 }` или прежнее
  `{ flow, step }`.
- **Сборка переводит** прежние ссылки на номер, если шаг находится
  (`core.migrateCommentRefs(model, flows)`); не находится — ссылка остаётся
  как есть, у открытого комментария это ПН6.
- ПН6: у открытого комментария нет состояния с таким номером.
- `--list` печатает `State 07` вместо пары `сценарий/шаг`.

### 10.4 Селфтест — новые кейсы

1. Нумерация: сборка раздаёт номера по порядку в файле, пишет `lastState`;
   повторная сборка ничего не меняет.
2. Повтор номера → ПН12; сборка даёт второму новый номер, отчёт называет его.
3. `lastState` меньше максимума → ПН12; после сборки — чисто.
4. Форма: файл пилота с двойными кавычками → ПН11; после сборки — чисто;
   нормализованные модели до и после равны.
5. `serializeFlows(readFlows(x)) === x` на каноническом файле со всеми
   глаголами и параметрами (`text`, `index: -1`, `timeout`, модификаторы,
   `state`, `block`, `wait`, `note` блоком, `issues`, пустой `steps`).
6. Комментарий внутри `flows.yaml` → ПН11 со строкой; сборка файл не
   переписывает.
7. `composeState`: точка входа при свежей загрузке; приращение после своей
   фиксации; приращение после проигрывания до последнего шага; точка
   входа, если проигран не последний шаг (в `do` — проигранные и свои
   действия); `nothing-changed`; пауза 6 с → `timeout: 7500`; пометки
   попадают только из своего диапазона; пустой сценарий → точка входа.
8. `applyFlowOps`: номер по свежему `lastState`; `id` `state-NN` при занятом
   — с суффиксом; `deleteState` с зависимым шагом → `dependents`; удалённый
   номер не выдаётся снова; `addState` без `page` в пустой сценарий →
   `entry-required`; `ref` черновых операций сопоставляются.
9. Комментарии: `Шаг: report-from-builder/waiting` → после сборки
   `Шаг: State 05`; ссылка на отсутствующий номер у открытого → ПН6.
10. `--state 07 --title …` и `--clear-issues` — запись и зеркало; `--states` —
    строки по формату §10.2.
11. ПН10: кириллица в строке `ui.js` → дефект; в `core.js`, `strings.js` и в
    комментарии `ui.js` — не дефект.
12. Включатель в `vm`: во фрейме приложения с панелью пересылается и `KeyS`.

## Acceptance Criteria

- В шапке шторки есть **Fix State**, у него есть `Alt+Shift+S` на любой
  странице прототипа (и из фрейма превью). Фиксация дописывает шаг в
  выбранный сценарий `flows.yaml`: приращение, если состояние продолжает
  последний шаг, иначе точка входа. Клик по узлу воспроизводит состояние.
- Каждое состояние — **State NN**: номер уникален в прототипе, постоянен и
  не выдаётся повторно; шаги агента нумерует сборка (у пилота State 01–11).
  Номер виден на узле, в плеере, в комментариях, в адресе шага и в
  `--states`.
- Автоназвание ставится само; переименование работает в панели и через
  `--state <app> <NN> --title`.
- Запись из браузера — каноническая, со слиянием по свежему файлу; после
  неё `--check` чистый. Без папки — черновики, которые проигрываются, и
  «Download flows.yaml».
- Записанные действия опираются на `id`, `data-*`, `aria-label` или текст;
  структурный селектор, фрейм, перетаскивание, выбор файла — пометка на шаге
  и в `--check` (заметкой).
- Весь интерфейс панели — английский; кириллицы в строках рантайма вне
  `core.js` и `strings.js` нет (ПН10).
- Комментарии ссылаются на `State NN`; прежние ссылки переведены сборкой.
- `proto-panel.mjs --selftest` — все кейсы 0005 и §10.4; `lessons-cli gate` —
  `ВЕРДИКТ: OK`.

## 13. Риски

| Риск | Что делаем |
|---|---|
| Клик по элементу без признаков «кликабельности» (обработчик на предке без `cursor: pointer`) не записан — состояние не воспроизводится | состояние видно сразу: клик по узлу; зафиксировать заново или отдать агенту (`/panel states`); правило §5.2 в README |
| Селекторы записи хрупкие | порядок стратегий §5.3, пометка `fragile`, заметка в `--check`, агент даёт элементам `id` и `data-*` |
| Каноническая форма меняет файл, написанный агентом | однократный дифф формы; комментарии внутри запрещены — сборка такой файл не трогает (ПН11) |
| Номер у черновика не совпал с выданным | номер выдаётся по свежему файлу, панель сообщает «Saved as State 13» |
| Введённые в прототип значения попадают в репозиторий | предупреждение в README; пароли не пишутся |
| Состояние зависит от времени или случайности | как в 0005: параметр адреса в прототипе, агент по пометке |
| Английский интерфейс и русские сообщения ядра рядом в Alert | решение §2.4: заголовок английский, детали — те, что видит гейт |
