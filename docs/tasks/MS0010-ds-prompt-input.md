# PromptInput: поле ввода промпта

## Коротко

- **Откуда.** Прототип `apps/ib/drafts/ai-bankster-prototype-v02`, экран
  `RequestThread.html`, композер внизу нити (`.cmp`, строки ~238–353 стилей,
  разметка ~650–716, скрипт ~1305–1870). Это карточка: над полем — чипы
  файлов и фрагментов материала, раскрытая цитата фрагмента, само поле
  (растёт по тексту, подсвечивает вставленные конструктором фрагменты), ряд
  кнопок (скрепка, «Конструктор», очистить, отправить), под карточкой —
  подсказка с клавишами. Внутри карточки выезжает вниз панель конструктора.
  Всё это собрано локальным CSS экрана, мимо ДС.
- **Задача.** Завести в ДС новый организм **PromptInput** — поле ввода
  промпта для AI-сценариев — и перевести на него композер прототипа v02.
  Компонент собирается **только из элементов ДС**; то, чего в ДС нет,
  заводится раньше отдельными задачами (§2).
- **Порядок — снизу вверх.** Сначала атомы, потом молекулы, потом этот
  организм. PromptInput — второй шаг после MS0009 по смыслу, но
  выполняется **последним** в группе MS0010: все его подзадачи
  `MS0010a`–`MS0010h` идут до него (§2.2).
- **Это правка ДС.** Делается только после согласования плана и ответов на
  вопросы §7 (правка ДС — только после детального согласования).

## Objective

В ДС есть организм PromptInput: карточка-поле с вложениями, контекстом,
многострочным полем с авторостом и подсветкой фрагментов, рядом действий,
подсказкой клавиш и слотом выезжающей панели. Рантайм `PromptInput.js`
закрывает авторост, подсветку, очистку, Enter/Shift+Enter и раскрытие
панели. Прототип v02 собирает композер из PromptInput без локального CSS
`.cmp*` и `.cmp-quote*`; сценарии экрана работают как раньше.

### 1.3. Почему не InputText `--multiline`

InputText — поле формы: метка, рамка поля, хелпер, высота от `rows`,
действия справа в одну колонку. Композер — другое:

- рамка у **всей карточки**, а не у поля; в карточке живут чипы, цитата,
  ряд кнопок и выезжающая панель — у InputText для них нет слотов;
- поле подсвечивает вставленные фрагменты — нужен слой-зеркало под
  `textarea`, у InputText его нет;
- действия — ряд под полем слева и справа, а не колонка справа;
- метки и хелпера нет; вместо хелпера — подсказка клавиш под карточкой;
- авторост: у InputText он заявлен только в псевдокоде спеки
  (`InputText.md`, «Поведение»), рантайм `Inputs.js` его не делает (греп
  `scrollHeight` 05.10.2026 — только страница документации).

Расширение InputText ради композера задвоило бы его оси и нарушило
инвариант «одно поле — одна рамка». PromptInput **использует** чипы,
кнопки, полосу прокрутки и цвета поля ДС, но не является вариантом
InputText. Состояния рамки (hover / focus / disabled) берутся у InputText
дословно — см. §3.2.

## 2. Порядок работ

### 2.1. Уровни

```
атомы       Chip (MS0009) ─┬─ Chip expanded (MS0010c)
                           │
            Keyboard (MS0010a) │   Buttons toggle (MS0010b)   StepMarker (MS0010d)   Note (MS0010e)
                           │
атомы       Chip expandable (MS0010f) — заменила Chip expanded (MS0010c) и Quote
```

перевод композера в этой задаче сводится к самой карточке.

## 3. Компонент PromptInput

Категория — `components/organisms/PromptInput/` (новый компонент, версия
`1.000`). Имя — вопрос 7.1.

### 3.1. Анатомия

```
.prompt                                   корень: колонка, зазор --space-8
├─ .prompt__box                           карточка: фон, рамка, радиус, тень
│  ├─ .prompt__main                       колонка, зазор --space-8, поля 12/12/12/16
│  │  ├─ .chiplist.prompt__attachments    чипы файлов (Chip edit S + file-basic + remove)    — пустой скрыт
│  │  ├─ .chiplist.prompt__context        чипы фрагментов (Chip edit S + message-text|bar-chart + remove;
│  │  │                                   текстовый — aria-expanded, MS0010c)                  — пустой скрыт
│  │  ├─ .prompt__field.ds-scroll         грид из одной ячейки, max-height, прокрутка
│  │  │  ├─ .prompt__mirror               зеркало текста, aria-hidden; фрагменты — mark.prompt__mark
│  │  │  └─ textarea.prompt__control      само поле
│  │  └─ .prompt__bar                     ряд действий
│  │     ├─ .prompt__lead                 IconButton «Приложить» · Button-toggle (MS0010b) · свои кнопки экрана
│  │     └─ .prompt__trail                IconButton «Очистить» (hidden) · Button Accent S icon-only «Отправить»
│  └─ .prompt__drawer                     слот выезжающей панели (grid 0fr → 1fr), inert пока закрыт
│     └─ .prompt__drawer-in               обёртка с overflow:hidden и верхней границей
│        └─ [контент экрана]              в прототипе — StepForm (MS0010h)
└─ .prompt__hint                          подсказка под карточкой: Keyboard (MS0010a) + текст body-xs
```

Правила анатомии:

- **Слоты необязательны**, кроме поля и кнопки «Отправить». Нет файлов —
  нет `.prompt__attachments`; нет конструктора — нет кнопки-переключателя
  и `.prompt__drawer`; нет подсказки — нет `.prompt__hint`.
- **Пустой chiplist скрыт** правилом компонента (`:empty`) — экран не пишет
  `display: none` сам (сейчас пишет: `.cmp__files:empty`, `.cmp__ctx:empty`).
- **Чипы в карточке — размер S**: шкала поля body-m, правило ДС «чип на
  размер меньше поля» (InputAutocomplete). XS и M не допускаются (линтер — §5.3).
- **В ряду действий — не больше одной Accent-кнопки** (инвариант Buttons);
  это «Отправить». Остальные — IconButton neutral M и Button Outline S.
- **Содержимое панели — экрана.** Компонент даёт слот, раскрытие, анимацию
  и `inert`; что внутри (StepForm, фильтры, настройки), решает экран.

### 3.4. Поведение — рантайм `PromptInput.js`

Хук — `data-prompt` на корне. Рантайм грузит `ds.js`; без разметки молчит.

| Что | Как | Откуда в прототипе |
|---|---|---|
| Авторост | грид из одной ячейки: зеркало задаёт высоту, `textarea` растягивается; рантайм копирует текст в зеркало на `input` + символ нулевой ширины в конце (держит пустую последнюю строку) | `.cmp__field`, `paint()` |
| Подсветка фрагментов | `DSPrompt.highlight(root, fragments, {fresh})` — массив строк; рантайм находит их в тексте, оборачивает в `mark.prompt__mark`, новый — `.is-new`, и прокручивает поле к нему | `paint()`, `setFrag()` (часть про скролл) |
| Порядок вставки фрагментов в текст | **остаётся на экране** — это логика конструктора, а не поля | `setFrag()`, `ORDER`, `tidy()` |
| Очистить | показ по значению; клик — очистить, фокус в поле, событие `ds-prompt:clear` на корне | `paint()` (`btnClear.hidden`) |
| Отправка | Enter — событие `ds-prompt:submit` (detail: текст); Shift+Enter — новая строка; клик «Отправить» — то же событие | обработчики экрана |
| Панель | клик по переключателю с `aria-controls` → `.is-open`, `aria-expanded`, снятие/постановка `inert`, при закрытии фокус из панели возвращается в поле; Esc внутри карточки закрывает панель; событие `ds-prompt:drawer` (detail: open) | `setBuilder()`, обработчик Esc |
| Значение кодом | `DSPrompt.setValue(root, text)` — ставит текст и пересинхронизирует зеркало и крестик (`.value =` событий не шлёт — та же ловушка, что у `DSInput.sync`) | `field.value = …; paint()` |
| Перерисовка | `DSPrompt.bindAll(scope)` | — |

Чего рантайм **не** делает: не рисует чипы файлов и фрагментов (это Chip),
не раскрывает фрагменты (это Chip expandable, MS0010f), не знает, что в панели.

### 3.5. Доступность

- `textarea` — `aria-label` (видимой метки нет) и `aria-describedby` на
  `.prompt__hint`.
- Переключатель панели — `aria-expanded` + `aria-controls` (MS0010b);
  закрытая панель — `inert`, Tab в неё не заходит.
- Группы чипов — `role="group"` + `aria-label` («Файлы, приложенные к
  сообщению», «Фрагменты материала в запросе»).
- «Отправить», «Приложить», «Очистить» — `aria-label`.
- `prefers-reduced-motion`: панель, вспышки и градиент — без анимации.
- Подсветка видна только глазами: `mark` в зеркале с `aria-hidden`.
  Скринридер читает поле как обычный текст — это ожидаемо (вопрос 7.6).

### 3.6. Что из прототипа в ДС не переносится

- `--cmp-ring`, `--cmp-shadow`, `--cmp-ease` и все `color-mix(…)` — не токены.
- Внешнее кольцо фокуса 4 px — у полей ДС фокус внутри рамки.
- Анимации `cmpPop` (появление крестика), `ctxPulse`, `bldIn`, `bldPop`,
  `cubic-bezier(.22,1,.36,1)` — в ДС нет токенов движения. Переносится
  только раскрытие панели (`grid-template-rows`) и вспышка фрагмента —
  длительности по вопросу 7.5.
- Подсветка выбранного переключателя (`.cmp__tgl[aria-expanded]`) — берётся

## 7. Вопросы к человеку (до начала работ)

1. **Имя.** `PromptInput` (класс `.prompt`) — рекомендую: описывает, что
   это, и не путается с Input-полями формы. Альтернативы: `Composer`
   (`.composer`), `ChatInput`.
2. **AI-режим — бегущий градиент по рамке** при открытом конструкторе
   (`is-building`, цвета `--primary` → `--info-light` → `--primary-light`).
   Варианты: (а) перенести как `.prompt--ai` — заметный приём «AI работает»,
   пригодится и другим AI-сценариям; (б) не переносить, открытая панель
   отмечается только кнопкой-переключателем. Рекомендую (а), но с
   отдельным пунктом в бэклоге ДС про токены движения.
3. **Тень карточки.** `--elevation-2` (как у меню и тултипов — «плавающий
   слой») — рекомендую: композер прижат к низу нити и лежит над прокруткой;
   `--elevation-3` сейчас резерв без компонента; или без тени, только рамка.
4. **Максимальная высота поля.** 240 px в прототипе — не токен. Варианты:
   (а) 10 строк body-m (`10 × line-height`) — рекомендую, не зависит от
   пикселей; (б) завести токен; (в) взять ближайший `--space-*`.
5. **Анимации.** В ДС нет токенов длительности и кривой. Переносить
   раскрытие панели и вспышку фрагмента с литералами длительности в CSS
   компонента (как у Chip, Tooltip сегодня) или сначала завести токены
   движения отдельной задачей? Рекомендую первое, с пометкой в бэклоге;
   пульс рамки (`ctxPulse`) — не переносить.
6. **Подсветка для скринридера.** Озвучивать ли, что фрагмент вставлен
   конструктором? Рекомендую нет: текст в поле тот же, подсветка
   вспомогательная.
7. **Правило линтера** «чип в карточке промпта — только S» — заводить или
   оставить на приёмке? Рекомендую завести (дешёвое, ловит частую ошибку).
8. **Замороженные копии** (`ai-bankster-prototype-mvp`, `pipelineScanner-v07`)
   — не трогать (рекомендую), как в MS0009.
