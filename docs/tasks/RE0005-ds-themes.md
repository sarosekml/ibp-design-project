# Темы ДС

## Коротко

- **Что не так.** Палитра ДС выросла без правил: растяжки неровные (светлота скачет
  внутри рампы), есть дубли и лишние стили, нейтральные — болотно-зелёные. Тёмной темы
  нет. В CSS компонентов есть hex, `rgba` и прямые ссылки на рампы, а один семантический
  цвет местами обозначает разные состояния.
- **Главное условие.** Пока продукт полностью не переехал на новую палитру, в ДС всё как
  прежде: значения текущей палитры, имена токенов, CSS компонентов, их спеки, версии и
  страницы не меняются. Разработке переносить нечего.
- **Решение — наложение.** Текущая тема `legacy` — это ДС как есть, страница без атрибута.
  Новые темы `ibp-light` и `ibp-dark` лежат в отдельных файлах и действуют только под
  атрибутом `data-theme`: они дают **старым именам** (`--text-primary`, `--bg-tile`…) новые
  значения. Компоненты о темах не знают — они, как и раньше, ссылаются на старые имена.
- **Карта «старое → новое».** Новая тема собрана из словаря ролей `--color-*`, и каждому
  старому имени в ней соответствует роль. Несколько старых имён → одна роль: общий цвет.
  Одно старое имя в разных ролях (например, `--tertiary` — и линия Divider, и наведение в
  меню) → точечное правило темы для конкретного места компонента; CSS компонента не
  трогается. Из карты генерируются темы и таблица для разработки.
- **Переключение** — плавающая кнопка сервисного окна на всех страницах проекта; выбор
  запоминается. **Заодно** — сервисная тема для протопанели и самого окна, чтобы служебное
  не путали с продуктом.
- **Переезд — отдельная задача**, когда разработка готова: компоненты переходят на роли
  `--color-*`, точечные правила становятся CSS компонентов, `legacy` выводится. Карта и
  список точечных правил — готовая инструкция переезда.
- **Заложено на будущее.** Тема — данные и генератор, а не ручной CSS: кастомный акцент «в
  моменте» с подстройкой всей темы, несколько акцентов, затем размеры, скругления,
  типографика, тени — наложение переопределяет те же токены; на этой основе — другой
  продукт на тех же компонентах.

Решения человека 02.10.2026:

| Вопрос | Решение |
|---|---|
| Откуда значения новой палитры | генератор строит рампы по правилам (ровный шаг светлоты в OKLCH, сине-серые нейтральные, проверка контраста), дизайнер правит семена на странице-стенде и утверждает |
| Где кнопка сервисного окна | везде: хаб, приложения, витрина локальных компонентов, страницы ДС; выбор темы запоминается и действует на всех страницах |
| Имена токенов | новые имена по ролям (`--color-*`) — словарь новых тем; до переезда они живут только в файлах тем, компоненты и экраны остаются на старых именах |
| Акцент новой темы | изумрудный остаётся; меняются нейтральные и растяжки, акцент выравнивается по шагам |
| Legacy до переезда | всё как прежде: палитра, имена токенов, CSS, спеки, версии и страницы компонентов не меняются; новые темы — наложение; перевод компонентов — отдельная задача «Переезд», когда разработка готова |

## Objective

В ДС есть механизм тем: `legacy` (текущая, без единой правки) и наложенные на неё
`ibp-light`, `ibp-dark`, `service`. Тема переключается из сервисного окна на любой странице
проекта и сохраняется. Всё, что видит и переносит разработка, — значения и имена токенов,
CSS, спеки, версии компонентов — до переезда не меняется. Карта «старое → новое» полна и
опубликована. Архитектура позволяет без переделки добавить кастомный акцент и темы не только
цвета.

## 2. Архитектура

```
legacy — ДС как есть (страница без атрибута):
  рампы Colors.css ──► старые имена Palette.css ──► CSS компонентов ──► экраны и виджеты apps/
                               ▲
новая тема — наложение, действует только под data-theme:
  семена ──► генератор ──► рампы --ramp-* ──► роли --color-* ──► старым именам — новые значения
                                                   └──► точечные правила: место компонента → роль
```

**Тема** — блок `[data-theme="<имя>"]` в генерате `foundations/Themes/Themes.css`: рампы
`--ramp-*`, роли `--color-*`, значения **всех 119 старых имён** (через роли), тени
`--elevation-*`, `color-scheme`. Отдельно — точечные правила для мест, где старого имени не
хватает. Без атрибута не действует ни одно правило файла — `legacy` та же, что сейчас.

- Старое имя, которому новая тема не дала значения, возьмёт значение `legacy` — поэтому
  тема обязана задать все 119 (проверка генератора).
- Переменная, вычисленная выше по дереву, наследуется готовым значением — блок темы задаёт
  всё целиком, поэтому темы вкладываются: протопанель в `service` поверх страницы в любой
  теме, на стенде — светлая и тёмная рядом.
- Селектор темы сильнее `:root` (`:root[data-theme]`) — порядок подключения не важен.
- `legacy` внутри новой темы (для стенда) — блок со старыми значениями; точечные правила
  внутри него не действуют.

**Карта «старое → новое»:**

1. **Старое имя → роль.** Каждое из 119 имён получает роль. Токены без применения (6 по
   замеру Э1, §1) — полноценные роли словаря, а не «при переезде убрать» (решение человека
   02.10.2026).
2. **N → 1.** Несколько старых имён с одной ролью — в новой теме один цвет; ничего не правится.
3. **1 → N.** Старое имя в разных ролях: его значение в новой теме — основная роль, остальные
   места — точечные правила темы (файл, селектор, свойство → роль). CSS компонента не меняется.
4. **Места без токена** — hex, `rgba` и рампы в CSS компонентов и хроме документации — тоже
   точечные правила. Инлайн-цвета в демо страниц ДС селектором не перебить — решение Э2:
   правила по значению атрибута `style` и по селектору блока `<style>`, только страницы ДС;
   образцы Colors, код на тёмном, редкое — «не перекрашивается».
5. Точечное правило задаёт «место → роль» одинаково для всех новых тем (значения ролей у
   каждой темы свои): кастомная тема и тема другого продукта получают их без доработки.
6. Генератор проверяет, что селектор и свойство каждого точечного правила ещё есть в файле
   компонента: правка компонента не сломает тему молча.

**Источник — данные.** `foundations/Themes/Themes.tokens.js`: роли, их значения в каждой
теме, семена рамп, карта старых имён, точечные правила. Формат — JS-файл: его читают и Node,
и страница по `file://` без fetch (`window.DS_THEMES`, как `window.DS_ICONS` у
`icons-data.js`; Node — через `vm`). v1 (Э2) лежит в `docs/misc/RE0005-themes/Themes.tokens.js`
и переезжает в ДС на Э3 вместе с основой: до неё папка `foundations/Themes/` с одним `.js`
сочтётся рантаймом (`ds-paths.mjs` определяет вид по расширению).

**Точечное правило** — `file` (от корня ДС), `selector` и `prop` как в файле, `from` —
исходное значение (генератор сверяет его с файлом: правка компонента не пройдёт молча),
`value` — значение в новых темах на ролях. Токен компонента (`--btn-pale`,
`--menu-item-hover`) получает правило в месте определения, места применения — только если
расходятся по ролям. Правила страниц ДС (`pages`) — отдельно: `style` — по значению
атрибута, `block` — по селектору блока `<style>`. Генератор `design-system/tools/theme-build.mjs` пишет
`Themes.css` (генерат, руками не править) и умеет `--check`: генерат совпадает с источником;
каждое правило файла — под атрибутом `data-theme`; у каждой темы все роли и все 119 старых
имён; селекторы точечных правил на месте; циклов нет; контраст пар «текст/фон» — AA. Алгоритм
рамп — один модуль для Node и браузера: на нём потом работает кастомный акцент (§6).

**Словарь ролей** (утверждён на Э2, 02.10.2026) — 158 ролей; полностью, с картой 119 имён
и всеми правилами — `docs/misc/RE0005-themes/map.md` (генерат `role-map.mjs`). Имя —
`--color-<группа>-<назначение>[-<состояние>]`, класс словом: `fg` (текст и иконка),

**Как старое имя получает роль** (решения пользователя 02.10.2026). Основная роль — по смыслу
имени; её получают все места без правила, в том числе `apps/`. Другая роль — по группе
класса места: fg, граница, заливка и фокус различаются; статусы — только по уровню. Граница
парная: рядом с заливкой того же имени — роль заливки, рядом с текстом — роль текста; глифы
из границ и фонов (дуги спиннера, шевроны, точки) остаются в роли своего имени.

Рампы новых тем — `--ramp-<тон>-<шаг>`, шаги 50, 100…900, 950: префикс не пересекается со
старыми `--blue-500`, A-шаги не переносятся. Тона (19): `accent` — из изумрудного семени
(имя роли, а не тона: кастомный акцент Ф2 меняет семя); `neutral` (сине-серая) и `grey`
(чисто серая, C = 0) вместо swamp, cgrey, mgrey; остальные — все тона legacy по их именам:
amber, blue, brown, cyan, deep-orange, deep-purple, green, indigo, light-blue, light-green,
lime, orange, pink, purple, red, yellow (решения пользователя на Э1 и Э2, 02.10.2026).

Решением человека 02.10.2026 **генератор считает только новые тона** (`accent`, `neutral`,
`grey`); базовые тона тема **переносит из `Colors.css` как есть** и не меняет — их значения
и особенности (немонотонные шаги, контраст статусов) остаются прежними. Поэтому «рампы
монотонны» и обязательный AA относятся к генерируемым рампам; на базовых — INFO и пометка
`legacy` на стенде.

## 3. Подключение и сервисное окно

**Подключение — через существующие точки; без выбранной темы ничего не меняется:**

эталон `.agents/skills/docs-split/references/skeleton.md` и в `MAINTAINING.md`. Тема по
умолчанию — `legacy`. Рантаймы ДС не меняются: при общей теме на `<html>` слои, вынесенные в
`body`, её наследуют; если такой слой открывает сервисная панель, тему ему ставит код панели (Э6).

**Сервисное окно:**

- круглая кнопка в левом нижнем углу (справа внизу — кнопка и плеер протопанели);
  `Alt+Shift+T` — открыть окно (у протопанели P, S и стрелки);
- окно «Темы»: список тем (Текущая · Новая светлая · Новая тёмная), ссылка на страницу
  «Темы» ДС, «Скрыть кнопку» (вернуть — той же клавишей);
- на кнопке метка, когда включена не `legacy`: снимок экрана для разработки не уйдёт в
  новой теме незаметно;
- собрано из компонентов ДС, глиф — из `foundations/Icons/Icons.md`; окно — в теме
  `service` (до Э6 — в текущей). На страницах ДС CSS компонентов подключён поштучно — окно
  само подключает CSS своих компонентов, если его нет (как `ensureCss()` в `ds-nav.js`);
- API `DSTheme.get()/set()/list()`, событие `ds:themechange`; разделы окна расширяемые —
  дальше акцент (Ф2) и не-цветовые настройки (Ф4).

## Acceptance Criteria

1. Тема переключается из сервисного окна на хабе, в приложениях, на витрине и на страницах
   ДС; выбор сохраняется между страницами и после перезагрузки; чужая тема не вспыхивает.
2. **Legacy как прежде.** Сверка `git diff` с базой (`main` на старте задачи): без изменений
   `foundations/Colors/`, остальные основы, CSS, JS и спеки компонентов и паттернов, их
   версии и блоки чит-шита, `utils/`, `apps/` (кроме генерата `apps/ds-config.js` и правки
   Э1 по решению человека: виджет `DealFinancialMetricsModal` — CSS, паспорт, журнал — и его
   страница и `kit-data.js` в витрине); в
   страницах ДС единственная правка — строка служебного тега. `theme-build.mjs --check`:
   каждое правило `Themes.css` — под атрибутом `data-theme`. Без выбранной темы страницы
   выглядят как до задачи (отличие — кнопка окна).
3. Каждая новая тема задаёт все роли и все 119 старых имён; селектор и свойство каждого
   точечного правила есть в файле компонента; циклов нет.
4. `ibp-dark`, `service`: пары текст/фон — AA (4,5:1 текст, 3:1 элементы управления и
   границы полей); рампы монотонны по светлоте. Критерий относится к генерируемым рампам

   04.10.2026): она повторяет текущую палитру, где AA на ссылке, кнопке, границе и
   вторичном тексте не держится; эти пары помечены `exempt: ["ibp-light"]` и печатаются
