# Дерево продуктов сделки: ProductRow в ДС, тайл и окна выбора

## Коротко

- **Что есть.** Тайл «Продукты сделки» (`apps/postrade/deals-app/widgets/tiles/DealProductTreeTile/`)
  на странице сделки — заглушка: шапка и строка «Данные ещё не заведены». Демо-дерево
  `apps/postrade/deals-app/data/mock-deal-trees.js` на странице не подключено, typedef у него нет.
- **Что пришло.** Макеты дизайнера 29.09.2026: компонент строки дерева ProductRow (пять типов
  строк и их состояния), тайл в четырёх стадиях заполнения в режимах правки и просмотра,
  правило отступов вложенности, окна «Продукты ДИД» и «Продукты», подтверждение удаления,
  каталог продуктов ДИД и обязательный состав каждого из них.
- **Чего не хватает.** Строки дерева в ДС нет. По правилам локальных компонентов
  (`design-system/pages/patterns/LocalComponents.html`) недостающий элемент сначала заводится
  компонентом ДС, потом используется в тайле.
- **Решение.** Два слоя. ДС получает `ProductRow` — форму строки, состояния, контейнер дерева
  с отступами и сворачиванием, без знания предметной области. Модуль сделок получает
  предметные правила: типы узлов, нумерацию, кнопки и меню по типу, основной продукт,
  обязательные продукты, окна выбора.

## Objective

На странице сделки, таб «Финансовые данные», тайл «Продукты сделки» показывает дерево продуктов
сделки из демо-данных во всех состояниях данных и прав, собран на компоненте ДС `ProductRow`;
продукты ДИД и продукты добавляются и удаляются через окна по макетам.

## 1. Как сейчас (29.09.2026)

- Тайл-заглушка: `DealProductTreeTile.html/.css/.md`, паспорт `0.004`, всё «не решено».
- `mock-deal-trees.js`: `productsDid[] → products[] → instruments[] → tranches[]`, поля
  `name`, `isMain`, `currency`, `balance`, `isPE`; названия узлов не совпадают с каталогом
  продуктов с макетов. Из дерева при генерации заморожены плоские поля записи сделки в
  `mock-deals.js` (`mainProductDid`, `productsDidNames`, `productsNames`, `balances`,
  `currencies`, `isPE`) — их читает реестр портфеля.
- Имена фронтенда (README модуля, `docs/misc/project-tree.md`): `DealProductTreeTile`,
  `DidProductsModal`, `ProductsModal`, `InstrumentsModal`, `RepaymentModal`,
  `InstrumentTransferModal`, `TransferringInstrumentsToFIModal`, строка — `AccordionProductRow`.
- Модуль в треке `product`: правки модуля — с подтверждения человека (дано 29.09.2026 вместе с
  этой задачей).

## 2. Решение

### Р1. Решения человека (29.09.2026)

- Имя компонента в ДС — `ProductRow`, класс `.prow`, страница `pages/organisms/ProductRow.html`.
  Варианты называются по форме строки, слов ДИД/ФИ/транш в ДС нет.
- Окна — только те, на которые есть макеты: `DidProductsModal`, `ProductsModal`, подтверждение
  удаления. «Погасить», «Перенести», ⇄ и «Добавить транш» стоят в тайле, окна за ними — «не решено».
- Тайл собирается сразу в модуле `deals-app`, без концепта в `drafts/`.

### Р2. Что на макетах

| Тип узла | Номер | Вид строки | Кнопки | Меню |
|---|---|---|---|---|
| Продукт ДИД | `1.` | корневая: без рамки (рамка при наведении), жирный заголовок, шеврон свернуть, звезда «основной» (контур / залитая, одна на сделку) | ⊕ «Добавить продукт» | Удалить → подтверждение |
| Продукт | `1.1.` | вложенная, ширина как у продукта ДИД | ⊕ «Добавить инструмент» | Удалить (недоступно, если продукт обязательный и единственный в продукте ДИД) |
| Инструмент | `1.1.1.` | вложенная, на 24px уже родителя; вторая строка у акций и опционов (дата подписания + сумма), у «НКЛ с баланса ПАО» (дата входа + дата выхода ДИД) | ⇄, если прикрепляется к ФИ; ⊕ «Добавить транш» только у «Договор займа (НКЛ)» | Погасить / Перенести / … — по типу |
| Транш | `1.1.1.1.` | вложенная, на 24px уже родителя; вторая строка (дата подписания + сумма лимита) | ⇄ | Погасить, Удалить; перенести нельзя |
| Строка в окне | — | та же строка | ⓘ (тултип с описанием), ⇄ «Переместить» | — |

- Состояния строки: обычное, с заливкой `--tertiary-bg-light` (прикреплена к ФИ), наведение
  (рамка), наведение с заливкой, выключенное.
- У инструмента со своей страницей заголовок на наведении — цвета primary, клик — переход.
- Погашенный инструмент или транш: строка статуса «✓ Дата фактического погашения ДД.ММ.ГГГГ»,
  «Погасить» меняется на «Отменить погашение». Пустое значение во второй строке — «–».
- Тайл: пусто — в правке кнопка «Добавить продукт ДИД», в просмотре «Не заполнено»; с данными —
  «+ Продукт ДИД» в шапке и «+ Добавить продукт ДИД» во всю ширину внизу; в просмотре нет
  ⊕ / ⋮ / ⇄ и кнопок добавления.
- Окна выбора: две колонки «Доступные продукты» / «Выбрано», перенос кнопкой ⇄ или двойным
  кликом, подсказка в пустом «Выбрано»: «Для выбора актива кликните по нему дважды или нажмите
  на кнопку со стрелкой», «Сохранить». В окне продуктов обязательный продукт выбран заранее и
  выключен, пока он единственный. Удаление продукта ДИД — «Подтвердите действие» / «Удаление
  продукта ДИД со всеми продуктами и инструментами» / «Отменить», «Подтвердить».
- Замеры (сверить с макетом): строка в одну линию ≈48px, в две ≈72px, зазор ≈8–10px, отступ
  вложенности 24px.

Человек ответил на вопросы 1–30 (ответ записан у каждого вопроса) и дал макеты «Перенос из
дерева в ФИ», «Погашение», «Перенос инструмента». Окна за «Погасить», «Перенести» и ⇄

вопросам агента в той же сессии:

- Окна выбора — три виджета, как во фронтенде: `DidProductsModal`, `ProductsModal` и новый
  `InstrumentsModal` на общем слое `PostProductPicker`.
- Окно связи с ФИ — `LinkChangeModal` (у фронтенда подчасть `FICards` — карточки ФИ, у нас в
  разметке окна). Перенос инструмента — `InstrumentTransferModal` (`AccordionProductRow`,
  `ConfirmTransferGrid` у фронтенда — подчасти), погашение — `RepaymentModal`.
- Правки дерева сохраняются между перезагрузками: в прототипе — через адаптер `PostApi`, как
  состав КНР (localStorage или сервер данных); реестр портфеля видит их после перезагрузки.
- В окне связи с ФИ можно выбрать любые две доступные карточки; тип отчётности не важен.
