# Палитра ДС

## Коротко

- **Что не так.** В RE0005 механизм тем заработал, но палитру человек не принял.
  `ibp-light` — копия текущей legacy: нейтраль `swamp`/`cgrey`/`mgrey` зелёно-бирюзовая
  (тон 193–204°), фон `#F5F7F7`, текст `#324844`, границы `#B8CCCC` — «болотно-зелёная»
  гамма. `ibp-dark` — та же гамма в тёмной версии. Статусы — старый Material
  (`#4CAF50`, `#EF5350`, `#FFA000`, `#03A9F4`) — пёстро и устарело. Ссылка `#00AA9B`
  на белом — 2.91:1 (ниже AA, зафиксировано в аудите RE0005).
- **Эталон.** Человек выбрал **Untitled UI** (`untitledui.com`) — семантические семейства
  ролей (text/border/bg/fg), белые поверхности, чистая нейтраль, мягкие многослойные тени.
  Референсы исследования: Untitled UI, Radix Colors, Tailwind v4 (OKLCH), GitHub Primer.
- **Наша настройка эталона.** Нейтраль — **полный Radix `slate`** (сине-серый), акцент —
  **ровно текущий `#00AA9B`** (сохраняем идентичность), статусы и графики — чистые
  Tailwind-шкалы, всё для светлой и тёмной темы.
- **`service`.** Приводим к виду новой тёмной темы, отличается **только акцентной рампой** —
  пурпур Untitled UI `#7F56D9`.
- **Механика RE0005 не меняется.** Темы — наложение; без атрибута `data-theme` `legacy`
  нетронута; компоненты, их CSS, спеки и экраны (`apps/`) не правим — только
  `foundations/Themes/Themes.tokens.js`, `Ramp.tokens.js` и генератор.
- **Отдельный итог** — инструкция для разработки, как продукт переходит с текущей темы на
  новую (сам переезд — не в этой задаче, остаётся будущим шагом).

## Objective

Дизайн-система получает принятую человеком палитру: светлая тема `ibp-light` и тёмная
`ibp-dark` построены по эталону Untitled UI на нейтрали `slate` с акцентом `#00AA9B`;
статусы, графики и тени пересобраны для обеих тем; `service` — тёмная версия с пурпурным
акцентом `#7F56D9`. Все темы задают все роли и все 119 старых имён, проходят AA и
монотонность там, где это требуется. Legacy без атрибута `data-theme` не меняется.
Дополнительно опубликована инструкция для разработки: как продукт переходит с текущей темы
на новую, по шагам, с проверками и откатом.

## Направление: эталон Untitled UI (исследование 04.10.2026)

Источники прочитаны напрямую (websearch в контуре не отвечал): `untitledui.com/react/docs`,
репозиторий `untitleduico/react` (`styles/theme.css`), `radix-ui.com/colors`,
`tailwindcss.com/docs/colors`, `primer.style`.

**Что взято у Untitled UI:**

- **Семантические семейства ролей**, а не «цвета по имени»: `text-*`, `border-*`, `bg-*`,
  `fg-*`; у каждого 3–4 уровня (`primary/secondary/tertiary/quaternary`), статусы — пара
  «текст 600/`solid` 600/подложка 50», тёмная тема переопределяет те же имена.
- **Слои поверхностей:** `bg-primary` (главная) → `bg-secondary` → `bg-tertiary` →
  `bg-quaternary`; в тёмной теме поверхности **светлеют с подъёмом**, а не темнят.
- **Мягкие многослойные тени** (`shadow-xs…3xl`): `0 1px 3px rgba(0,0,0,.1), 0 1px 2px -1px …`.
- **Акцент — отдельная шкала `brand-50…950`**, где сплошная заливка — `brand-600` под белый
  текст, а `brand-50/100` — тонированные подложки.

**Что взято из Radix/Tailwind:**

- **Radix `slate`** — нейтральная шкала с синевой; отдельные значения для light и dark (не
  инверсия). Шаги и роль каждого — по «Understanding the scale».
- **Tailwind v4 (OKLCH)** — статусные шкалы `red/green/amber/blue/violet` (600 для заливки,
  600/400 для текста, 50/950 для подложек) и палитра графиков.
- **Primer** — модельный пример функциональных ролей (`fgColor-*`, `bgColor-*`,
  `borderColor-*`), спокойный холодный нейтрал.

### Акцент — `#00AA9B`

Сохраняем оттенок ровно. Вокруг него строится шкала `--ramp-accent-*` (как `brand-*`
Untitled UI):

- опорная ступень = `#00AA9B` (идентичность, крупные заливки);
- `--color-accent-fill` (кнопка + белый текст) — ступень темнее опорной (как `brand-600`);
  снимает конфликт AA 2.91:1;
- `--color-accent-fill-hover/-pressed` — ещё темнее;
- `--color-link` / `--color-accent-fg` — тёмная ступень для светлого фона, светлая — для
  тёмного (AA 4,5:1);
- `--color-accent-bg*` — тонированные подложки (8/4 % как сейчас).

Точные хексы шкалы считает генератор (Э2), `#00AA9B` закрепляется в одной ступени.

## Архитектура (из RE0005, не меняется)

- `legacy` — страница без атрибута, ДС как есть.
- `ibp-light`, `ibp-dark`, `service` — блоки `[data-theme]` в генерате `Themes.css`: рампы
  `--ramp-*`, роли `--color-*`, значения всех 119 старых имён, тени, `color-scheme`.
- Источник — `foundations/Themes/Themes.tokens.js` (`seeds`, `values`, `themeValues`, `map`,
  `contrast`, `rules`); генерат — `design-system/tools/theme-build.mjs` (`--check`,
  `--selftest`); алгоритм рамп — `Ramp.tokens.js` (OKLCH → hex, WCAG).
- Стенд — `foundations/Themes/Themes.html` (сцены, конструктор семян, отчёт контраста).
- **Меняются только** `Themes.tokens.js`, `Ramp.tokens.js` и результат генератора
  (`Themes.css`); при необходимости — `Themes.html`/`Themes.md` (описание палитры и
  инструкция переезда). Компоненты, их CSS, спеки и `apps/` не правятся.

## Инструкция переезда для разработки (итог задачи)

Документ для человека-разработчика без агента (спека `Themes.md` + раздел страницы «Темы»).
Содержание:

1. **Что меняется.** Сейчас компоненты пишут старые имена; новая тема даёт им новые значения
   под `[data-theme]`. Переезд нужен, чтобы разработка получила роли `--color-*` напрямую,
   а `legacy` ушёл.
2. **Шаги:**
   - **Шаг 0.** Продукт включают на `ibp-light` по умолчанию — визуально он уже новый, код
     не тронут.
   - **Шаг 1.** Компоненты ДС: старое имя → основная роль `--color-*` по карте (механическая
     замена).
   - **Шаг 2.** Исключения — точечные правила становятся CSS компонентов: «одно имя в другой
     роли» (224), токены компонентов (26), места мимо токена — hex/rgba/рампы (83); тени на
     `--elevation-*`.
   - **Шаг 3.** `Palette.css`: старые имена → псевдонимы `var(--color-*)`; переводятся и
     экраны `apps/` (≈930 ссылок).
   - **Шаг 4.** Вывод `legacy`: `ibp-light` — тема по умолчанию, старые имена и блок `legacy`
     удаляются.
3. **Карта «старое → новое»** и список точечных правил по компонентам — как рабочая таблица
   переезда (публикуется на странице «Темы» и в `Themes.md`).
4. **Порядок и границы:** пофайлово/покомпонентно; что первым, что можно параллельно.
5. **Проверки на каждом шаге** и **откат** (пока `legacy` жив, возврат возможен на любом шаге).
6. **Ускорение:** скрипт механической замены + правило линтера, ловящее старое имя после
   переезда.

  акцентом (`accent-600`), а `.sw__input:checked ~ .sw__control` берёт

  бледный). Роль исправлена на видимый трек (`accent-200`, hover `accent-300`);
  правка — в `values` (общая), `--secondary-light` используется только свитчем.
  Скрипт — `docs/misc/RE0006-palette/fix-light.mjs`.
- **Починен гейт точечных правил (баг RE0005, урок Л170):** генератор ставил
  `:where([data-theme]…)` на **весь список селекторов целиком** — у правил с
  запятой гейт доставался только первому, а хвосты (`…, .sw--hover.sw--on …`,

  наведении пропадал фон (OFF не задет). Теперь гейт на каждый селектор;
  `checkGated` проверяет каждый селектор списка; кейс `--selftest` с правилом
  `.a .b, .c .d`. Восстановлен инвариант «без атрибута ни одно правило файла
  тем не действует».
- Стенд: редактор семян не падает на явных ступенях (показывает «эталонная
  шкала»); `Themes.md` описывает новую светлую.
- Проверки: `theme-build --check` — OK (4 INFO — пары на legacy-тонах
  warning/success/info до Э4); `--selftest` — OK (20 кейсов); `ds-check --all` —
  OK; `ds-check Themes.html` — OK.
- Не сделано (следующие этапы): тёмная ещё бирюзовая (`seeds["ibp-dark"].neutral`
  h 187), статусы и графики светлой — legacy. Это Э3–Э4.

### Пост-приёмка (04.10.2026, по замечанию человека)

На стенде сцена «legacy» портилась, когда на `<html>` выбрана тема (тёмная заливка
бейджа «Черновик», сбой свитча на наведении) — нарушался инвариант «legacy как есть».
Причина: точечные правила гейтятся по предку `:where([data-theme]:not([data-theme="legacy"]))`,
а он матчит и `<html>` с выбранной темой → вложенная сцена `data-theme="legacy"` получала
правила чужой темы; второй канал — токены компонентов, заданные темой на `:root[data-theme]`,
наследуются в легаси-поддерево. Исправлено в `theme-build.mjs`:
- цель каждого точечного правила исключена из поддерева legacy —
  `:where(:not([data-theme="legacy"] *))` (нулевая специфичность, состояния сильнее);
- в блоке `legacy` компонентные токены возвращаются к исходному значению компонента
  (поле `from` правила).

Кейсы `--selftest`: «точечное правило исключает вложенную legacy», «legacy возвращает
токены компонентов». Урок **Л173**. Проверки: `theme-build --check`/`--selftest` — OK,
`ds-check --all` — OK. Замечание закрыто.

## Риски

| Риск | Что делаем |
|---|---|
| Случайная правка legacy-файла | сверка `git diff` в конце каждого этапа (критерий 2) |
| Тема задаёт не все роли/имена | генератор требует все 119 имён в каждой теме |
| `#00AA9B` + белый не проходит AA | заливка на ступень темнее или `exempt` (решение на стенде) |
| Тёмная тема как инверсия выглядит мутно | собственные значения `slate`-dark, поверхности светлеют с подъёмом |
| Семена не совпадают с целевой таблицей slate | генератор настраивается на таблицу; сверка на стенде |
| Правка компонента ломает точечное правило (тени) | генератор проверяет селектор и свойство каждого правила |
| Инструкция переезда расходится с картой | карта и правила — единый источник в `Themes.tokens.js`, документ строится из них |
