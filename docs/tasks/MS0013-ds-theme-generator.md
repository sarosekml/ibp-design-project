# Темы из файлов и конструктор темы

## Коротко

- **Главное — ничего не сломать.** Изменения не должны задеть:
  - текущие прототипы и экраны `apps/` (107 страниц: драфты, модули, хаб,
    витрина локальных компонентов);
  - концепты и паттерны;
  - саму ДС.

  Ветка должна нормально влиться в main: без конфликтов и регрессий. Проверка и
  доработка — этап Э6 (§3.8, §6). Снимок исходного состояния делается до Э0.
- **Откуда.** Запрос человека 05.10.2026 (во время MS0010): тема настраивается
  вручную, токен за токеном. Нужно задавать только **brand 500** и **neutral 500**,
  а растяжки и все токены пусть строятся сами. Плюс страница, где видны все цвета
  и любой правится колор-пикером. План уточнён ответами 06–07.10.2026 (§1) и
  образцом coolors.co/tailwind.
- **Модель.** Тема — JSON-файл в папке токенов цветов ДС. Базовых файлов три:

  | Файл | Что это | Кто правит |
  |---|---|---|
  | `ibp-legacy` | текущая ДС без изменений, только светлая; в конструкторе выглядит «собранной руками» — её отступления от алгоритма видны как ручные правки | никто |
  | `ibp-neo` | тема по алгоритму: светлая — по растяжке «Colors / Core», тёмная — генератором | только агент |
  | `custom` | сиреневая: тёмная — как сейчас, светлую нужно сгенерировать | человек в конструкторе |

  Человек пересохраняет `custom` или создаёт новую тему.
- **Что уходит.** «Новая светлая» и «Новая тёмная» (`ibp-light`, `ibp-dark`) —
  их заменяет `ibp-neo`. Плавающее окно тем ДС тоже уходит.
- **Страница «Темы»** переделывается и встаёт первой в «Основах»:
  - «Конструктор» — выбор темы и сам конструктор по образцу coolors;
  - «Документация» — как устроены темы;
  - «Код» — экспорт.
- **Выбор темы** — в двух местах: конструктор и панель прототипа. В панели рядом с
  названием каждой темы — рубильник «светлая / тёмная»; у `ibp-legacy` его нет.
- **Новые компоненты ДС:** ползунок Slider, колор-пикер ColorPicker, вариант
  Switch с подписями по обе стороны («Светлая ◯ Тёмная», как у coolors).
- **Замер.** Прототип алгоритма в черновике сессии (в ДС не входит):
  - повторяет нынешние рампы из одной ступени с отклонением не больше 0,010 ΔE;
  - на цветах примера все обязательные пары контраста проходят (§3.6).
- **Это правка ДС.** Начинается после утверждения плана.

## Objective

Темы ДС задаются файлами. Человек открывает «Темы» и выбирает тему. Дальше два пути:

- смотреть с ней всю ДС;
- доработать тему: brand 500, neutral 500, ползунки, ручная правка любого цвета.
  Результат сохраняется поверх `custom` или в новый файл.

Генератор строит растяжки brand и neutral по эталону, остальные тона берёт из
фиксированных базовых растяжек. `ibp-legacy` при этом остаётся ровно текущей ДС.

При этом не меняются ни текущие прототипы и экраны, ни сама ДС в `legacy`.
Ветка вливается в main без конфликтов и регрессий — это проверяет и
дорабатывает Э6.

## 3. Решение

### 3.1. Темы и файлы

| Тема | Светлая | Тёмная | В `data-theme` |
|---|---|---|---|
| `ibp-legacy` | текущая ДС, как есть | нет | без атрибута (как `legacy` сейчас) |
| `ibp-neo` | генератор: эталон «Colors / Core», входы `#18A59E` + `#617179` | генератор | `ibp-neo-light`, `ibp-neo-dark` |
| `custom` | генератор из сиреневой палитры: brand 500 `#7F56D9`, neutral 500 — как у нынешней | нынешняя сиреневая, ступени как есть | `custom-light`, `custom-dark` |
| своя | конструктор | конструктор | `<имя>-light`, `<имя>-dark` |
| `service` | — | служебная, хром панели прототипа | `service`, не меняется |

- Старые адреса и сохранённый выбор (`?theme=ibp-light`, `ibp-dark`) ведут на `ibp-neo`.
- Правила ролей светлого и тёмного профиля — нынешние правила `ibp-light` и
  `ibp-dark` (RE0006–RE0011): сами темы уходят, их правила остаются общими для
  всех светлых и всех тёмных тем.

**Папка `design-system/foundations/Themes/tokens/`.** Она внутри
`foundations/Themes/`: имена тем (`--ramp-*`, `--color-*`) живут только там
(правило B16).

| Файл | Что | Запись |
|---|---|---|
| `base-light.json` | светлая базовая растяжка: 16 тонов + серый, 11 ступеней — из `Colors.css` (950 = 900) | фиксирована; `--check` сверяет с `Colors.css` |
| `base-dark.json` | тёмная базовая растяжка — нынешние ступени `ibp-dark`, закреплённые явными значениями | фиксирована |
| `ibp-legacy.json` | brand 500 `#00AA9B` и neutral 500 legacy + правки ролей, при которых результат равен текущей ДС | закрыт: `--check` сверяет все 119 имён с legacy |
| `ibp-neo.json` | входы и правки `ibp-neo`, светлая и тёмная | закрыт, правит только агент |
| `custom.json` | `custom`, светлая и тёмная | конструктор: «Сохранить» |
| `<имя>.json` | свои темы | конструктор: «Сохранить как…» |
| `tokens.data.js` | зеркало всех JSON — для загрузки по `file://` | страница при сохранении и `theme-build`; руками не правится |

Набросок файла темы:

```json
{
  "name": "custom", "label": "Custom", "locked": false,
  "light": { "brand": "#7F56D9", "neutral": "#87919C", "adjust": { "hue": 0, "saturation": 0, "temperature": 0 },
             "overrides": { "--color-…": "#…" }, "onFill": "white" },
  "dark":  { "brand": "#7F56D9", "neutral": "#87919C", "overrides": { "--ramp-accent-…": "#…" } }
}
```

### 3.2. Как тема попадает на страницы

- **Открытие.** Страница читает зеркало `tokens.data.js` тегом `<script>` — это
  работает по `file://` в любом браузере. Список тем = файлы папки.
- **Базовые темы** `ibp-neo` и `custom` — статический CSS в `Themes.css`. Его
  собирает `theme-build`, `--check` стережёт свежесть и контраст.
- **Свои темы** собираются на лету. При выборе темы страница строит её CSS из
  зеркала тем же модулем `Ramp.tokens.js`, что и `theme-build`. Точечные правила
  общие для всех тем — работают и для своих. Новая тема видна на всех страницах
  ДС сразу после сохранения, без сборки.
- **Сохранение** — по образцу панели прототипа (MS0005): File System Access API.
  - Chromium (Chrome, Edge, Яндекс Браузер): папку подключают один раз, в новой
    сессии браузер может переспросить разрешение.
  - Firefox и Safari в папку писать не умеют. Там есть «Скачать JSON»; файл кладут
    в папку руками, зеркало пересобирает `theme-build`.
- **Несохранённое** живёт до перезагрузки. Перед уходом со страницы, где есть
  несохранённое, браузер переспрашивает «Покинуть страницу?».
- **Защита базы.** У `ibp-legacy` и `ibp-neo` «Сохранить» выключено, и запись
  этих файлов страница не выполняет — только «Сохранить как…».

### 3.3. Выбор темы: два места

1. **Страница «Темы».**
   - Список тем.
   - Свитчер «Светлая ◯ Тёмная», как у coolors. У `ibp-legacy` он выключен.
   - Выбор действует на всю ДС и запоминается в браузере, как сейчас.
2. **Панель прототипа.** Вкладка тем остаётся как сейчас: у каждой темы название
   и рядом рубильник «светлая / тёмная» (Switch ДС). У `ibp-legacy` рубильника нет.

Плавающее окно тем ДС (кнопка слева внизу, `Alt+Shift+T`) убираем. API
`DSTheme` остаётся: им пользуются панель и конструктор, в нём появляется режим
«светлая / тёмная».

### 3.4. Алгоритм (дополнение `Ramp.tokens.js`)

1. **hex → OKLCH** — обратное преобразование к уже существующему `lch()`.
2. **Эталон светлой — «Colors / Core».** Светлота, доля хромы и сдвиг тона по
   ступеням снимаются с примера: у brand тёмные ступени уходят в синеву на 19°.
   - Шкала ДС: ступени 50…900 — как в примере, 950 — продолжение кривой.
   - Ступень 25 из примера не используется.
3. **Эталон тёмной — генератор.** Тёмная кривая снята с нынешних рамп `ibp-dark` —
   это единственная тёмная растяжка с проверенным контрастом.
4. **Brand.**
   - Светлая: 500 — ровно вход, соседние ступени сдвигаются вслед за ним с
     затуханием к краям шкалы.
   - Тёмная: заливка (600) — от входа.
5. **Neutral.**
   - Светлая: 500 — ровно вход; хрома ограничена (≈ 0,04), чтобы нейтраль не
     стала цветной.
   - Тёмная: тон и насыщенность — от входа, светлота — по тёмной кривой, чтобы
     поверхности 50–300 не слиплись.
6. **Ползунки** тона, насыщенности и температуры сдвигают оба входа, как
   «Adjust» у coolors.
7. **Генерация** (пробел) даёт случайный brand. Метод задаёт, как neutral связан
   с brand: авто, монохромный, аналоговый, комплементарный, сплит-комплементарный,
   триадный, тетрадный, квадрат.
8. **Гамма sRGB.** Хрома, которая не помещается в sRGB, уменьшается с
   сохранением тона.
9. **Контраст.** Обязательные пары генератор держит сам, сдвигая ступень. Текст
   на заливке — переключатель «белый / тёмный»; провал виден на странице.
10. **Роли** — по правилам профиля (§3.1). Отличие одно: `--color-status-accent-*`
    идут за brand, а не за старым `--emerald-*`.
11. **Не меняются:** базовые растяжки, статусы, графики.

### 3.5. Страница «Темы» (docs-split, первая в «Основах»)

**Вкладка «Конструктор»** — по образцу coolors.co/tailwind.

| Блок | Что на нём |
|---|---|
| Шапка | список тем (файлы, у базовых — замок); свитчер «Светлая ◯ Тёмная»; «Сохранить», «Сохранить как…», «Подключить папку»; метка «Не сохранено» |
| Палитры | две строки — Brand и Neutral, ступени 50…950. На плашке шаг, hex и контраст, как в «Colors / Core»; точка на 500. Клик — правка ступени: ColorPicker, «Копировать», «Сбросить» |
| Нижняя закреплённая панель | полосы Brand 500 и Neutral 500 (ColorPicker); «Настроить» — ползунки тона, насыщенности и температуры; отмена и повтор (⌘Z / ⇧⌘Z); «Сгенерировать» (пробел) и метод; «Код» |
| Примеры | живые компоненты ДС в теме: шапка страницы, тайл с таблицей, кнопки всех видов и состояний, поля, чипы, табы, алерты, бейджи, меню, DocCard, Entity; сцены нынешнего стенда переезжают сюда |
| Все цвета | роли (160) по группам; старые имена (119) с ролью; базовые растяжки, светлая и тёмная (просмотр, правка с пометкой); контраст (17 пар), провал красным |

- У `ibp-legacy` плашки и роли показывают, где тема отступает от алгоритма:
  такие цвета помечены как ручная правка.
- **Вкладка «Документация»** — как устроены темы: файлы, роли, точечные правила,
  проверка. Берётся из нынешней страницы и `Themes.md`.
- **Вкладка «Код»** — экспорт, как у coolors: JSON темы и CSS-переменные,
  hex / OKLCH, «Копировать».
- Нынешний конструктор семян `h`/`c` уходит — его заменяет новый конструктор.

### 3.6. Замер прототипа (06.10.2026)

Прототип лежит в черновике сессии, в ДС не входит. Кривые в нём сняты с нынешних
ручных рамп. ΔE — расстояние в OKLab, около 0,02 — порог «на глаз разницы нет».

| Что проверено | Итог |
|---|---|
| Повтор нынешних рамп из одной ступени (`#00AA9B`, `#858F9A`) | max ΔE: brand 0,010 / 0,007, neutral 0,002 — генератор держит растяжку |
| Обязательные пары на цветах примера (`#18A59E` + `#617179` или `#61796F`) | все проходят. Светлая: вторичный текст 8,61 / 8,03, текст brand 6,70. Тёмная: 8,52 · 8,40 |
| Пробные brand (`#2563EB`, `#E5484D`, `#FFD60A` и др.) | проходят все, кроме жёлтого (текст 3,75): генератор затемнит ступень текста, на заливке нужен тёмный текст |
| Растяжка ДС против «Colors / Core» | у примера середина нейтрали темнее (ступень 400: L 0,60 против 0,69), brand 400 и 600 светлее, тёмные ступени brand синее; max ΔE 0,066 / 0,103. Поэтому `ibp-neo` берёт эталоном пример, а не нынешние рампы |

### 3.7. Новые компоненты ДС (Э0)

| Компонент | Что |
|---|---|
| **Slider** (атом) | ползунок значения: трек, бегунок, подпись, значение, клавиатура; трек может быть градиентом (тон, насыщенность, температура) |
| **ColorPicker** (молекула) | поле цвета (насыщенность × яркость), ползунок тона (Slider), hex (InputText), пипетка (EyeDropper API, Chromium), «Копировать»; открывается в Popover |

### 3.8. Сохранность: что может задеть прототипы и ДС

Замер 07.10.2026:

- Ни один прототип не задаёт тему в разметке. Тему ставит только загрузчик
  `apps/ds-config.js`: из `?theme=` или из сохранённого выбора `ds.theme`.
- Без выбора все экраны — в `legacy`, то есть ровно в текущей ДС.
- Значит, `legacy` должна остаться нетронутой до пикселя, а всё остальное —
  включаться только под атрибутом `data-theme`.

| Что меняем | Чем может задеть | Как стережём |
|---|---|---|
| Загрузчик приложений (`ds-config.js`, `ds-body.js` — генераты `boot-build.mjs`) | его грузит каждый экран: ошибка ломает все 107 страниц | без темы загрузчик ведёт себя как сейчас; `boot-build --check` и `--selftest`; консоль без ошибок на всех экранах |
| `Themes.js` (в списке рантаймов `ds.js`) | убираем плавающее окно, добавляем темы на лету | API `DSTheme` совместим (`get`, `set`, `list`); при `legacy` рантайм ничего не меняет на странице |
| `Themes.css` | уходят блоки `ibp-light`/`ibp-dark`, приходят `ibp-neo`/`custom` | всё — под `[data-theme]`; точечные правила остаются под `:where([data-theme]:not([data-theme="legacy"]))` |
| `ds.css` — подключение новых компонентов | CSS Slider, ColorPicker и варианта Switch попадает на каждый экран | только свои новые классы, без глобальных селекторов; имена классов сверяются с классами экранов и локальных компонентов — пересечений нет |
| Switch — новый вариант | существующие свитчи на экранах | вариант — отдельным классом; без него Switch рисуется как сейчас |
| Панель прототипа (`.agents/proto-panel/`) | стоит на всех прототипах: сценарии, комментарии, Fix State | меняется только вкладка тем; сценарии и комментарии проверяются на прототипе с папкой `proto-panel/` |
| Сохранённый выбор `ds.theme = ibp-light / ibp-dark` у людей | тема пропала — экран без цветов | старые id ведут на `ibp-neo` |
| Меню ДС и главная | порядок «Основ», новые страницы | `ds-home`, `hub-build`, `kit-build` — `--check` |
| Генераты при слиянии (`Themes.css`, `hub.js`, `docs/index.md`, загрузчики) | конфликты слияния с main | конфликты в генератах не правятся руками — пересборка после слияния и `--check` |

**Ветка.** Сейчас в рабочей копии ветки `feat/ai-pitcher-components` 87
незакоммиченных правок. Это работа прошлых заходов и, возможно, параллельных
сессий. Порядок такой:

1. Эти правки коммитятся и вливаются в main — по команде человека.
2. MS0013 идёт отдельной веткой от свежего main.

Так изменения тем не смешаются с другой работой, и слияние останется чистым.
