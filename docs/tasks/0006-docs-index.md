# Единый каталог документации (docs/index.md)

## Objective

Документация проекта разложена по ~220 md-файлам в шести кластерах (корень,
`design-system/`, `.agents/`, `apps/`, `docs/`, `.agent-state/`) и не имеет
единой точки входа: чтобы найти нужный документ, надо знать структуру
репозитория. Человек (Obsidian) и агент работают вслепую.

Задача — **единый сборный каталог всей документации** `docs/index.md`:

- открывается в Obsidian (корень репозитория = vault) и на GitHub;
- каждая строка — ссылка на документ с короткой аннотацией, сгруппирована по
  кластерам репозитория; сверху — рукописные «маршруты чтения» (с чего начать
  дизайнеру / агенту / разработчику), чтобы по каталогу можно было пройтись;
- **пересобирается автоматически и не может протухнуть**: каталог — генерат
  `.agents/tools/docs-index.mjs`, любое добавление, удаление или перемещение
  md-файла без пересборки краснит гейт (шаг `docs-index`). Обновляемость
  обеспечивается сторожем, а не памяткой — «запрет без замены не работает»
  (Л68), прецеденты — `hub.js` (шаг `hub`) и деревья в README модулей (шаг
  `readme`).

Каталог — точка входа для **человека**. Агенты его целиком не читают
(экономия контекста, process.md §13): в сводных таблицах указателей
(README, AGENTS.md) он поименован как адрес для человека.

## Решения постановки

### Р1. Где хранить — `docs/index.md`

Каталог — сам документация, его место в `docs/` (в project.json это
`"docs": "docs"`; «планы и задачи» по README). Корень не рассматривается:
он уже перегружен входами (`README.md`, `AGENTS.md`, `index.html`, `hub.js`,
`project.json`), а файл уровня корня дублировал бы роль README.

Отклонённые альтернативы:

- **`docs/INDEX.md` / корневой `Docs.md`** — то же самое без преимуществ;
  имя `index.md` — привычная точка входа в папке.
- **Хранить каталог вне репозитория (только локальный vault Obsidian)** —
  теряется гейт и каталог расходится между машинами.
- **Wikilinks-«хаб» Obsidian (`[[…]]`)** — не работает на GitHub и в
  редакторах без Obsidian; проект живёт в git, ссылки только markdown.

В Obsidian пользователь открывает корень репозитория как vault и закрепляет
`docs/index.md` (инструкция — в рукописной шапке каталога, Р5).

### Р2. Что входит — все md репозитория минус явный игнор-лист

Источник — обход диска от корня (как у остальных сторожей; git-специфичные
приёмы не используем). Игнор-лист живёт в шапке генератора, а не в задаче:

- `node_modules`, `.git`, `.opencode/node_modules` — зависимости;
- `.agents/tools/fixtures/**` — фикстуры тестов линтера, это данные, не
  документация;
- локальный вход ассистента другого CLI — файл исключён из git
  (`.git/info/exclude`), ссылка на него в коммитуемом каталоге была бы битой
  на других машинах. Имя файла **ни в этой задаче, ни в генераторе не
  пишется литералом**: его ловит vendor-scan (стоп-слово «имя ассистента»),
  в игнор-листе тулзы оно записывается склейкой строк — по образцу шапки
  самого `vendor-scan.mjs`;
- `tmp/`, `.zcodeignore`, `.obsidian/` — локальные пути и конфиги
  (project.json → `vendorScan.ignore`, `.gitignore`);
- `docs/index.md` сам себя не перечисляет.

`docs/misc/*` (scratch-заметки) и `*.handoff.md` **входят** — это тоже
документация, но секции помечаются как «архив/черновики» и «снимки задач».
Спеки ДС `design-system/specs/*` входят полностью — каталог претендует на
полноту, а не на кураторство.

### Р3. Обновление — генератор + шаг гейта

По образцу `hub-build.mjs` / `module-readme.mjs`:

- **генератор** `.agents/tools/docs-index.mjs`: без аргументов — собирает
  `docs/index.md`; `--check` — сверяет файл на диске с генератом (для
  гейта); `--selftest` — откат на временном дереве (создать/переместить/
  удалить md → каталог меняется; рассинхрон → `--check` красный);
  шапка файла — решения инструмента, по конвенции остальных тулзов;
- **шаг гейта** `docs-index` (и `docs-index-selftest` на правку самого
  генератора) в `gateStep()` + строка матрицы `gateStepsFor`: любое
  создание/удаление/переименование `.md` вне игнор-листа поднимает шаг.
  Состав матрицы прозой не пересказывается (Л43): печатает
  `node .agents/tools/lessons-cli.mjs gate --dry --changed <путь>`;
- рукная правка сгенерированной зоны = красный гейт, как у `hub.js`.

Даты генерации в файле **нет**: бессодержательная строка, которая шумит в
диффах и делает `--check` вечно красным. Счётчики по секциям — можно, они
меняются только при реальных изменениях.

### Р4. Ссылки — относительные markdown, совместно с Obsidian и GitHub

- путь — от `docs/`: `../README.md`, `../apps/postrade/deals-app/pages/Deal.screen.md`,
  `misc/mvp.md`;
- пробелы в путях — `%20` (обязательно для GitHub, Obsidian понимает оба
  варианта); кириллицу не кодируем (обе стороны понимают raw) — проверяется
  на `apps/postrade/deals-app/refs/Текущий портфель.md`;
- никаких `[[wikilinks]]`, никаких якорей-к-разделам (хрупкие), никаких
  абсолютных путей (vendor-scan).

### Р5. Структура каталога — рукописная шапка + генерируемое тело

- **Рукописная зона** (не трогается генератором): заголовок «Карта
  документации», как открыть в Obsidian (vault = корень репозитория),
  «Маршруты чтения» — 3–4 коротких списка по ролям (новичок-дизайер,
  агент-сборщик, фронтенд-разработчик, ревьюер) со ссылками на 5–7 главных
  документов;
- **генерируемая зона** между маркерами `<!-- @docs-index -->` …
  `<!-- /@docs-index -->` (по образцу `@tree` в README модулей): первый
  маркер снабжён подписью «генерирует docs-index.mjs, руками не править»;
- секции в порядке: Корень → Дизайн-система → Агентная система →
  Приложения (по разделам и модулям) → Задачи и заметки (`docs/`) →
  Служебное (`.agent-state`); внутри секции — стабильная сортировка по
  пути, чтобы диффы не шумели;
- строка файла: ссылка + аннотация. Аннотация = `title` из frontmatter,
  иначе первый `# заголовок`, иначе длинное тире;
- `docs/index.md` в UTF-8, как весь репозиторий (process.md §8).

## Acceptance Criteria

- `docs/index.md` существует, открывается в Obsidian из vault-корня, все
  проверенные ссылки живые (Obsidian + GitHub), включая кириллицу и пробелы
- Каталог полон: любой md-файл git-репозитория вне игнор-листа Р2 представлен
  строкой в своей секции; проверка — сличение с обходом диска
- `node .agents/tools/docs-index.mjs --check` — зелёный; `--selftest` —
  зелёный и непустой по составу проверок
- Добавление/удаление/перемещение md-файла без пересборки каталога даёт
  `ВЕРДИКТ: FAIL` гейта (шаг `docs-index`), после `node
  .agents/tools/docs-index.mjs` — `ВЕРДИКТ: OK`
- Указатели из блока «Tasks → 3» на месте; в каталоге нет абсолютных путей
- Заход закрыт: `node .agents/tools/lessons-cli.mjs gate` — `ВЕРДИКТ: OK`

## Открытые вопросы

Не блокируют исполнение, решения выше — рабочие:

- Глубина аннотирования спек ДС (65 файлов одной секцией или подгруппами
  «основы / компоненты / служебные») — на усмотрение исполнителя, устойчиво
  к любому выбору благодаря сортировке по пути.
- Включать ли `.handoff.md`-снимки задач, которые устаревают: включаем с
  пометкой секции; если окажется шумно — Exclude-правило в игнор-листе
  генератора (одна строка, без правки правил).
