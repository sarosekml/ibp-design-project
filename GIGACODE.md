# IBP ai-Designer — правила для GigaCode

Этот файл читает GigaCode из корня воркспейса `aiDesigner`. Он описывает
структуру проекта и то, как с ним работать, чтобы выполнять главную задачу —
**генерацию HTML-экранов на компонентах дизайн-системы IBP**.

Язык общения и комментариев — **русский**. Контент репозитория —
UTF-8.

## Что это за проект

Дизайн-система продукта **IBP (Investment Banking Platform)** — внутренней
платформы инвестиционного банкинга. **Ванильный HTML/CSS, без React и без
сборщика.** Экран — это один самодостаточный `.html`, который открывается
в браузере двойным кликом. Интерфейс — плотный, деловой, на русском;
акцентный цвет — изумрудно-зелёный.

Главная задача агента — **генерация экранов из компонентов дизайн-системы**:
взять ТЗ/скриншот/описание, прочитать нужные спеки ДС, собрать экран как
HTML + markdown-спеку экрана, проверить и сдать.

## Три части проекта

В проекте три смысловые части, и они **не взаимозаменяемы**:

### 1. `.agents/` — рабочая среда агента ai-designer

Папка, где лежит всё для работы агента `ai-designer`: правила его работы,
агенты, скиллы, команды, оснастка (`.agents/tools/`) и весь процесс генерации
HTML-прототипов. Это инструментарий, а не продукт и не дизайн-решения. Рядом —
тонкий адаптер `.opencode/`: конфиг opencode и указатели на роли и команды
харнеса; содержания в нём нет, правится `.agents/`.

Ключевые файлы:

| Файл | Что содержит |
|---|---|
| `.opencode/opencode.json` | Конфиг: подключение `process.md` и `design-system/AGENTS.md`, права на инструменты |
| `.agents/rules/process.md` | **Правила процесса агента** — читать всегда, целиком |
| `design-system/AGENTS.md` | **Знание о ДС**: карта, чтение, запреты, каркас экрана, каталог — читать всегда, целиком |
| `.agents/agents/ai-designer.md` | Ведущий агент: маршруты, распределение по субагентам, границы |
| `.agents/agents/screen-builder.md` | Сборка экрана `<Имя>.html` + `<Имя>.screen.md` |
| `.agents/agents/screen-reviewer.md` | Приёмка экрана по чек-листу (PASS / NEEDS-WORK) |
| `.agents/agents/ux-researcher.md` | Исследование по базе знаний продукта — выключено, пока база не подключена (`KB` в `knowledge-lookup`) |
| `.agents/commands/*.md` | `/screen`, `/concepts`, `/handoff`, `/resume`, `/screen-check` |
| `.agents/skills/screen-assembly/SKILL.md` | Пошаговая сборка экрана на ДС |
| `.agents/skills/ds-lookup/SKILL.md` | Как найти компонент в ДС и достать разметку, не читая большие файлы |
| `.agents/skills/screen-review/SKILL.md` | Полная приёмка экрана |
| `design-system/templates/screen/Screen.html` | **Каркас экрана** — стартовая копия при сборке |
| `.agents/skills/screen-assembly/references/patterns.md` | Готовые рецепты разметки (крошки, шапка, таблица, модалка) |
| `design-system/specs/_runtime-hooks.md` | Таблица «что работает само / что требует атрибута» |

### 2. `design-system/` — дизайн-система и компоненты

Источник истины: токены, классы компонентов и документация. **Файлы этой
папки агент не меняет** (исключение — явное поручение человека). Точки
входа ДС — `ds.css` (все стили) и `scripts/ds.js` (все рантаймы). Экран
проекта их не называет: ДС подключает загрузчик `boot/` двумя тегами
(`boot/ds-head.js` в `<head>`, `boot/ds-body.js` вместо `ds.js`), путь до ДС
записан только в `project.json`.

Ключевые файлы:

| Файл | Что содержит |
|---|---|
| `design-system/ds.css` | Единая точка подключения стилей (@import всех `styles/*`) |
| `design-system/scripts/ds.js` | Единая точка подключения рантаймов (сам догружает иконки, табы, модалки, таблицы) |
| `design-system/specs/_index.md` | Манифест: компонент → спека → CSS → версия |
| `design-system/specs/_cheatsheet.md` | Чит-шит: по блоку на каждый компонент. **Большой — читать только точечно** |
| `design-system/specs/<Имя>.md` | Полная спека компонента |
| `design-system/specs/Icons.md` | Все имена глифов (вставляются как `<i data-icon="имя">`) |
| `design-system/styles/colors.css` (базовые цветовые рампы), `palette.css` (семантика цвета), `typography.css`, `spacing.css`, `radius.css`, `shadow.css` | Токены фундамента |
| `design-system/templates/screen/Screen.html` | Стартовый шаблон экрана |
| `design-system/pages/` | Документация компонентов (не читать целиком) |

### 3. `apps/` — приложения: проекты и концепты

Каждое приложение — каталог `apps/<id>/` одной формы: `app.json` с треком,
экраны и их спеки в `pages/` (все на одной глубине), фрагменты модульных
экранов в `components/`, демо-данные в `data/`, входящие материалы в `refs/`.
Трек — свойство приложения, а не место на диске:

- **`product`** — **актуальные версии продуктовых экранов**, строго на
  компонентах ДС и по текущему состоянию кода. Туда переносит человек; агент
  правит такое приложение только с подтверждением.
- **`rnd`** — **концепты и новые разработки**, в том числе на новых
  компонентах: отсюда берут идеи для разработки и новые компоненты для ДС.
  **Сюда агент кладёт собранные экраны**: `apps/<Имя>/pages/<Имя>.html` +
  `<Имя>.screen.md`.

Дополнительно:

| Файл | Что содержит |
|---|---|
| `hub.js` (корень) | Реестр хаба: собирается `hub-build.mjs` из `app.json` приложений, руками не правится |
| `index.html` (корень) | Хаб проектов: меню и три колонки строятся из `hub.js`, сама страница не правится |
| `AGENTS.md` (корень) | Правила проекта для внешних агентных CLI (opencode и др.) |

## Как работать: главная задача — сборка экрана

Сборку ведёт агент `ai-designer` по маршрутам из
`.agents/agents/ai-designer.md`. Ключевые моменты:

### Порядок чтения перед задачей

Чтобы успешно выполнять генерацию экранов, **в начале задачи** подключи в
контекст:

1. `GIGACODE.md` (этот файл) — карта проекта. ✅
2. `.agents/rules/process.md` — правила процесса и `design-system/AGENTS.md` — знание о ДС, оба **целиком**.
3. `.agents/agents/ai-designer.md` — роли и маршруты (по своей роли).
4. По необходимости — скиллы: `screen-assembly` (сборка),
   `screen-review` (приёмка), `ds-lookup` (поиск компонента),
   `concept-design` (концепты), `session-plan` (смета захода).
5. Каркас экрана — `design-system/templates/screen/Screen.html`
   (копия при старте сборки) + `patterns.md` + `design-system/specs/_runtime-hooks.md`.

### Главное правило: ничего не выдумывать

Цвет, размер, отступ, радиус, шрифт, класс, имя иконки — **только из
дизайн-системы**. Нет нужного — **спросить, а не изобрести**. Доменный термин
из ТЗ, не описанный в базе знаний, — тоже вопрос пользователю.

### Экономия контекста

ДС читать **только точечно**: `grep -n "^## "` по оглавлению чит-шита,
`sed -n '/^## <Имя>$/,/^## /p'` по блоку компонента, `read` с `offset/limit`.
Запрещено читать целиком:

- `design-system/scripts/icons-data.js` (671 KB в одну строку);
- `design-system/specs/_cheatsheet.md` (~170 KB);
- страницы `design-system/pages/**/*.html`;
- собранный экран при правке — только по якорям секций (`#sec:head`,
  `#sec:content`, `#sec:modals`).

### Инварианты экрана

- Скроллится **только контент**, горизонтального скролла не бывает никогда.
- `body { margin: 0 }` обязателен (в шаблоне уже есть).
- Иконки — только `<i data-icon="имя">`, никакого инлайнового `<svg>`.
- Нет `#hex`/`rgb()`/`px` в цветах и типографике — только токены и классы ДС.
- Состояния компонентов (`--selected`/`--disabled`/`:hover`) задаёт только сам
  компонент; свой `<style>` — только раскладка (grid/flex/gap) на токенах.
- Собственный JavaScript вместо рантайма ДС не пишется. Хуки рантаймов —
  в `design-system/specs/_runtime-hooks.md`.
- Таблица-реестр занимает всю свободную высоту (`screen--app` + `dtable--fill`).
- После каждой сборки — приёмка `screen-reviewer`, без исключений.

### Куда класть результат

Результат сборки — приложение трека `rnd`: `apps/<Имя>/pages/<Имя>.html` +
`<Имя>.screen.md`, у нового приложения — `apps/<Имя>/app.json`
(`track: "rnd"`, название, описание, стартовая страница, иконка) и пересборка
реестра `node .agents/tools/hub-build.mjs`. Строка
пользователя меню ведёт на хаб `../../../index.html`. Файлы ДС агент не
трогает, приложения трека `product` — только с подтверждением.

### Проверка в конце захода

Одна команда `lessons-cli gate` — прогоняет сторожей изменившегося, строка
`ВЕРДИКТ:` идёт в отчёт. Контекст между сессиями — `/handoff` и
`/resume <Задача>` (файл `apps/<Задача>/<Задача>.handoff.md`).
