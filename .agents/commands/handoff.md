Задача: записать handoff — всё, что нужно новой сессии, чтобы продолжить
работу, не перечитывая историю разговора.

Имя задачи: $ARGUMENTS

Если имя не задано — возьми имя экрана или короткое имя задачи латиницей
в PascalCase (`DealRegistry`, `TabSizes`) и назови его в ответе.

Файл — рядом с задачей: `docs/tasks/<ID>-<slug>.handoff.md` (решение человека
14.10.2026, RE0021; правила папки — `docs/tasks/README.md`). Работа идёт без
файла задачи — сначала заведи короткую задачу по `docs/tasks/0000-task-template.md`
(ядро шаблона, без необязательных разделов), потом handoff рядом с ней.

Уже есть — перепиши целиком актуальным состоянием: файл — снимок, не журнал.
Handoff, написанные до RE0021 в корне приложения (`apps/…/<Задача>.handoff.md`),
не переносятся: `/resume` находит их там.

Этап закрыт — перед handoff отметь его затраты:
`node .agents/tools/task-cost.mjs mark <ID> Э<N>` (строка в «Затратах» задачи).

Формат — до 80 строк и ~5 тыс. символов, только факты, без пересказа разговора:

```markdown
# <Задача> — handoff

- **Дата:** ДД.ММ.ГГГГ
- **Статус:** в работе | закрыта | ждёт ответа пользователя

## Цель
Одна-две строки: что должно получиться и для кого.

## Этапы
Маршрут из `ctx-budget.mjs --stages`, статусы: ✓ сделан · → текущий · — впереди.

- ✓ plan
- → build-main
- — build-modals
- — review

## Смета
Строка `ВЕРДИКТ:` последнего `ctx-budget` и аргументы, которыми он считан
(этап, компоненты, ожидаемые строки) — чтобы следующая сессия пересчитала
то же самое, а не другое.

## Принятые решения
- решение — кто принял (пользователь / по правилу ДС / допущение агента)

## Что сделано
- путь к файлу или папке — что в нём, одной строкой

## Проверки
Строка `ВЕРДИКТ:` последнего `lessons-cli gate` и вердикт последней приёмки.

## Открытые вопросы
- вопрос — к кому

## Следующий шаг
Одно действие, с которого начнёт новая сессия.

## Читать первыми
- пути к файлам, без которых следующий шаг не сделать
```

Правила:

- Решение, которое пользователь дал в разговоре, записывается **дословно по
  смыслу** — это единственное место, где оно переживёт сессию.
- Для экрана не дублируй `<Имя>.screen.md`: сошлись на него в «Читать первыми».
- Догадку не записывай как решение: пометь «допущение агента».
- Раздел «Этапы» — чек-лист маршрута, а не пересказ сделанного: сделанное
  живёт в «Что сделано». Один этап в статусе `→`, не два.
- **Разделов по этапам нет** («Что сделано (Э3)», «Проверки (Э4)»): сделанное
  за все этапы — один список «Что сделано», проверки — только последние.
  Подробности этапа живут в файле задачи и в git, не в handoff.
- «Что сделано» — строка на файл или папку: путь и что в нём. Без пересказа
  правок, замеров и находок — они в файле задачи.
- Задача идёт коротким маршрутом (`plan → build → review → close`) — раздел
  «Этапы» всё равно нужен: по нему `/resume` понимает, что осталось.
- В ответе пользователю — путь к файлу одной строкой.
