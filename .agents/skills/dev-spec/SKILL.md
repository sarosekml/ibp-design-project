# Спецификация на разработку

Задача RE0016. Спека на разработку — не замена спекам экранов и паспортам: она
**собирает сценарий целиком** из того, что уже написано у модуля, и добавляет то,
чего там нет: последовательность шагов и снимки каждого состояния.

| Что | Где |
|---|---|
| Шаблон исходника | `.agents/skills/dev-spec/references/template.md` |
| Исходник спеки | `<концепт>/refs/<Spec>/<Spec>.dev-spec.md` — у Post концепт `apps/postrade/drafts/dev-specs/` |
| Генератор | `.agents/tools/dev-spec.mjs` (формат и коды СР — в его шапке) |
| Генерат | `<концепт>/data/<Spec>.dev-spec.js` и индекс `data/dev-specs.js` — руками не правятся |
| Где смотреть и выгружать | страница концепта `pages/index.html`: кнопки «Скачать папку (.zip)», «.md», «.html» |

## Кто читает

Разработчик фронтенда, который проектирует и верстает по спеке, — часто без
прототипа под рукой. Ему нужно: что делаем и зачем, шаги сценария, экраны и
новые компоненты (состояния, размеры, поля, проверки, контракт), данные, тексты,
открытые вопросы. **Коротко**: таблица лучше абзаца, текст ради текста не пишется;
что уже есть в паспорте дословно — выжимка в строку, не копия раздела.

## Порядок

1. **Источники.** Спеки экранов сценария (`<Экран>.screen.md`), паспорта новых
   виджетов (`<Имя>.md`), их `fixtures.json`, демо-данные `data/*.js` (typedef),
   сценарии панели (`proto-panel/flows.yaml`) и карта экранов
   (`apps/screen-map/<раздел>/map.yaml`) — там готовые адреса состояний. Читать
   точечно, по разделам. Пути — в `sources`.
2. **Снимки.** На каждое состояние, которое разработчик должен увидеть, — запись в
   `snaps`: собранная страница `<Экран>.preview.html` с параметрами адреса, `target`
   для кадра компонента, `do` — если состояние достигается только действиями
   (язык `flows.yaml`: `click`, `fill`, `press`, `waitFor`, `wait`…). Галерея
   состояний компонента — все его виды. Экран целиком — когда важно место
   компонента; длинная страница — `height: full`.
3. **Текст** по шаблону: семь разделов, номера и названия как в шаблоне (СР5);
   раздела нет по существу — «Нет.». Открытые вопросы — из источников, с
   номером, не закрываются догадкой (правила процесса §7).
4. **Проверка:** `node .agents/tools/dev-spec.mjs <исходник> --check` —
   `ВЕРДИКТ: OK`.
5. **Съёмка:** `node .agents/tools/dev-spec.mjs <исходник>` поднимает сервер и
   печатает адрес. **Адрес открывает человек** в своём браузере (агент браузер
   скриптом не запускает — правила процесса §9): страница снимает состояния сама и
   по строке «готово» генератор пишет генерат. Сообщи человеку адрес и жди.
6. **Правка текста без пересъёмки:** `--text`. Переснять часть: `--only id,id`.
7. **Показ:** хаб → «Концепты» → «Post — Спецификации на разработку». Человек
   смотрит и выгружает папку сам.

## Правила

- Снимок — DOM прототипа на момент съёмки: правка прототипа = пересъёмка.
  Тема — IBP Legacy, дата и `Math.random` заморожены.
- Размеры в px — со снимка, в ширине `viewport` (Post — 1920×1080); ширина в
  сетке — классами (`col-3 colw-6`), из паспорта.
- Имена компонентов — как в модуле (тип в конце: `…Tile`, `…Modal`); компоненты
  ДС — по каталогу ДС.
- Шага в гейте нет: генерат с исходником сверяет только сам генератор.
