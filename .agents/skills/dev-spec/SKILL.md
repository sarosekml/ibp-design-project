# Спецификация на разработку

Задача RE0016. Спека на разработку — не замена спекам экранов и паспортам: она
**собирает сценарий целиком** из того, что уже написано у модуля, и добавляет то,
чего там нет: последовательность шагов и снимки каждого состояния.

| Что | Где |
|---|---|
| Шаблон исходника | `.agents/skills/dev-spec/references/template.md` |
| Исходник спеки | `<концепт>/refs/<Spec>/<Spec>.dev-spec.md` — у Post концепт `apps/postrade/drafts/dev-specs/` |
| Генератор | `.agents/tools/dev-spec.mjs` (формат и коды СР — в его шапке) |
| Генерат | `<концепт>/data/<Spec>.dev-spec.js` и индекс `data/dev-specs.js` — руками не правятся |
| Где смотреть и выгружать | страница концепта `pages/index.html`: кнопки «Скачать папку (.zip)», «.md», «.html» |

## Кто читает

Разработчик фронтенда, который проектирует и верстает по спеке, — часто без
прототипа под рукой. Ему нужно: что делаем и зачем, шаги сценария, экраны и
новые компоненты (состояния, размеры, поля, проверки, контракт), данные, тексты,
открытые вопросы. **Коротко**: таблица лучше абзаца, текст ради текста не пишется;
что уже есть в паспорте дословно — выжимка в строку, не копия раздела.

## Порядок

1. **Источники.** Спеки экранов сценария (`<Экран>.screen.md`), паспорта новых
   виджетов (`<Имя>.md`), их `fixtures.json`, демо-данные `data/*.js` (typedef),
   сценарии панели (`proto-panel/flows.yaml`) и карта экранов
   (`apps/screen-map/<раздел>/map.yaml`) — там готовые адреса состояний. Читать
   точечно, по разделам. Пути — в `sources`.
2. **Снимки.** На каждое состояние, которое разработчик должен увидеть, — запись в
   `snaps`: собранная страница `<Экран>.preview.html` с параметрами адреса, `target`
   для кадра компонента, `do` — если состояние достигается только действиями
   (язык `flows.yaml`: `click`, `fill`, `press`, `waitFor`, `wait`…). Галерея
   состояний компонента — все его виды. Экран целиком — когда важно место
   компонента; длинная страница — `height: full`. Снимок окна — кадр `target` с
   `.modal`: спека покажет его на скриме.
3. **Текст** по шаблону: пять обязательных разделов — «Коротко», «Сценарий», «Экраны», «Новые
   локальные компоненты», «Тексты»; названия как в шаблоне, номера подряд (СР5); раздела нет по
   существу — «Нет.». «Данные и API» и «Открытые вопросы» — по желанию: API разработке не
   нужен, решения и ответы человека остаются в задаче; нерешённое, что влияет на реализацию,
   пишется в самом месте (ветка сценария «под вопросом»). В разделе компонентов связанные идут
   подряд: тайл — его окно, затем следующий тайл — его окно.
   Таблица и список под своим подзаголовком `#####` — читатель не должен угадывать, о чём они.
   Несколько снимков — `snaps` (сетка по ширине кадров: тайлы до трёх в ряд, средние по два,
   страницы по одному; `<!-- snaps: cols=2 a b c -->` — столбцы задаёт автор). Окна — по ширине в
   шагах ДС (`modal--wN`), в любом разделе: до `w4` — три в ряд, `w5`–`w9` — два, `w10`–`w12` — один) и
   `matrix` (все виды компонента одной сеткой «данные × права»: подписи строк и столбцов, пустая
   клетка — `_`; в сетку входят и вырожденные виды, например «условия не выполнены»). Пояснение
   к снимку («почему возникает ошибка») — `note` снимка. Образец чипа в таблице —
   `{chip:success Текст}`. Цветной блок в тексте — цитата `> [!warning] …` (warning, info, error,
   success), например для «под вопросом». В начале раздела «Сценарий» — схема блоком `scenario`.
   Сплошной абзац с перечислением («Условия: …. Данные: …») — маркированным списком; шаги
   сценария — нумерованным (страница рисует его путём); ветки — подзаголовками `####` под
   `### Ветки сценария`, у каждой первой фразой — к чему она относится; подраздел, на который
   ссылаются (ошибки окна), — своим `###` и ссылкой `[текст](#слаг)`.
4. **Проверка:** `node .agents/tools/dev-spec.mjs <исходник> --check` —
   `ВЕРДИКТ: OK`.
5. **Съёмка:** `node .agents/tools/dev-spec.mjs <исходник>` поднимает сервер и
   печатает адрес. **Адрес открывает человек** в своём браузере (агент браузер
   скриптом не запускает — правила процесса §9): страница снимает состояния сама и
   по строке «готово» генератор пишет генерат. Сообщи человеку адрес и жди.
6. **Правка текста без пересъёмки:** `--text`. Переснять часть: `--only id,id`.
7. **Показ:** хаб → «Концепты» → «Post — Спецификации на разработку». Человек
   смотрит и выгружает папку сам.

## Схема сценария

Блок ```scenario в начале раздела 2: узлы и связи, раскладка — слоями слева направо, снимок
узла — id из `snaps`, клик по узлу в html ведёт к нему, кнопка «К схеме сценария» возвращает.
Связи держи между соседними слоями; замыкающая цикл связь рисуется серым пунктиром. Цвет
связи — по тому, куда она ведёт: голубая — обычный переход, красная — в ошибку, зелёная — в
успешное состояние, оранжевая — в узел «под вопросом»; под схемой — легенда. Наведение на узел
подсвечивает его связи, кнопка «На весь экран» открывает схему как снимок. В md схема уходит
блоком mermaid.

```
id | Название | вид | снимок       вид: page · modal · state · error · ok · warn
a -> b | подпись                     связь, подпись — условие или действие
```

Форма узла и его тон — два признака. Форму (экран или окно) определяет снимок: кадр с `.modal` в
`target` — окно, остальное — экран; тон — вид `state` / `error` / `ok` / `warn` (цвет планки экрана
или строки заголовка окна). Поэтому состояние и ошибку окна помечай `state` / `error`, а не `page`:
форма возьмётся из снимка. `page` и `modal` — явная форма без тона; если она противоречит снимку,
СР5 не даст собрать спеку.

## Правила

- Снимок — DOM прототипа на момент съёмки: правка прототипа = пересъёмка.
  Тема — IBP Legacy, дата и `Math.random` заморожены.
- Размеры в px — со снимка, в ширине `viewport` (Post — 1920×1080); ширина в
  сетке — классами (`col-3 colw-6`), из паспорта.
- Имена компонентов — как в модуле (тип в конце: `…Tile`, `…Modal`); компоненты
  ДС — по каталогу ДС.
- Шага в гейте нет: генерат с исходником сверяет только сам генератор.
