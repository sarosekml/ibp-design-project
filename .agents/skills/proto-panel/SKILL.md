# Панель прототипа: включение, сценарии, комментарии

## 1. Что это

Служебная шторка поверх прототипа: на любой его странице `Alt+Shift+P`. В ней
сценарии показа — состояния блок-схемой, клик по узлу приводит прототип в
нужное состояние, — и комментарии к прототипу со статусами «открыт / сделан /
отклонён». Кнопки панели называй так, как на экране («Fix State», «Flows»,
«Connect project folder…»). Данные лежат рядом с
прототипом: `<приложение>/proto-panel/flows.yaml` (сценарии пишешь ты, а
человек дописывает состояния кнопкой **Fix State**), `comments.md`
(комментарии пишет панель, закрываешь ты), `panel-data.js` (зеркало —
генерат, руками не правится). У каждого состояния — постоянный номер
**State NN**: по нему к состоянию обращаются человек, комментарии и оснастка.

Форматы `flows.yaml` и `comments.md`, подмножество YAML, глаголы действий,
устройство, коды ПН и ограничения — **только** в
`.agents/proto-panel/README.md`; здесь они не пересказываются (урок Л43).
Читай нужный раздел оттуда, когда пишешь сценарий.

## 2. Включение

- Вопрос «**Панель прототипа: включить?** (сценарии показа и комментарии)» —
  в общем списке вопросов перед сборкой (маршрут «Собери экран», шаг 2).
  Рекомендация по умолчанию — «да» для нового прототипа из двух и более
  экранов.
- «Да» →

  ```bash
  node .agents/tools/proto-panel.mjs --enable <приложение>
  ```

  и строка в README приложения: «Панель прототипа: Alt+Shift+P на любой
  странице; сценарии — proto-panel/flows.yaml».
- В отчёте человеку — как открыть панель: кнопки на странице по умолчанию
  нет, без этой строки панель не найти.
- Сценарии (п. 3) описываешь после приёмки экранов — PASS, а не раньше: пока
  разметка меняется, селекторы расходятся с ней.

## 3. Сценарии

Источник — пользовательский путь из ТЗ, сценарий показа из README
приложения, просьба человека. Формат — README панели, раздел «flows.yaml».

- Шаг — **одно состояние интерфейса**, которое показывают.
- Без `state`: номер выдаст сборка (п. 4 и «Зафиксированные состояния»).
- Первый шаг и каждый переход на другую страницу — `page`.
- Приращение — только то, что пользователь делает на этом шаге.
- Селекторы — `id` и `data-*` разметки прототипа, **в одинарных кавычках**;
  классы ДС и `:nth-child` — нет. После асинхронного — `waitFor` по признаку
  в DOM (класс `is-open`, появившийся элемент), а не `wait`.
- Действие не уводит со страницы: переход — полем `page` следующего шага.
- `note` — тезисы для показа, одно-два предложения.
- Комментарии YAML — **только шапкой** файла: панель и сборка переписывают
  файл целиком, комментарий внутри — ПН11, и файл больше не пишется. Пояснение
  к шагу — в `note`.
- Состояние долго или ненадёжно достигается кликами (таймер в минуты,
  случайность) — добавь в экранный скрипт параметр адреса (как `?run=1`) и
  опиши его в спеке экрана: это часть прототипа.
- Прежде чем писать селектор, найди его в разметке и в экранном скрипте
  (`grep -n`): элемент может рисоваться скриптом после клика.

После правки — сборка и проверка: `node .agents/tools/proto-panel.mjs`
(пронумерует новые шаги и приведёт файл к канонической форме).

## 4. Проверка

- `node .agents/tools/proto-panel.mjs --check` — статическая: форматы,
  страницы шагов, селекторы по тексту страниц, форма и нумерация
  (ПН1–ПН12). Пометки записи (`issues`) она печатает заметками — не дефект,
  а работа для п. 5.
- Прогон в браузере — человек по чек-листу README панели (раздел «Проверка
  человеком»), или ты, если у тебя есть браузер. Headless-браузер не
  запускать (process.md §9).
- Заход закрывается гейтом: `node .agents/tools/lessons-cli.mjs gate`.

## 5. Зафиксированные состояния

Человек фиксирует состояния сам: работает с прототипом, жмёт **Fix State**
(`Alt+Shift+S`) — панель дописывает шаг в `flows.yaml` (`state`, `recorded`,
действия, иногда `issues`). Формат и то, как пишется шаг, — README панели,
разделы «Fix State» и «Номера состояний».

- **Номера не пишешь и не меняешь руками**: их выдают панель (по свежему
  файлу) и сборка (шагам без номера). Удалённый номер не возвращается —
  `lastState` не трогай.
- К состоянию обращайся **по номеру**: «State 07» в отчёте, в плане, в
  вопросе человеку; аргумент оснастки — `07`, `7`, `State 07` или `state-07`.
- Просьба «переименуй State 07 в „…“» →

  ```bash
  node .agents/tools/proto-panel.mjs --state <приложение> 07 --title "…"
  ```

  (`--note "…"` — заметка для показа). Каноническая запись и зеркало — сами.
- **Привести в порядок** — маршрут `/panel <приложение> states`:
  1. `node .agents/tools/proto-panel.mjs --states <приложение>` — список
     состояний с пометками, `--check` — заметки о них;
  2. план человеку одним списком: названия (автоназвания вроде «State 14»),
     `note` для показа, хрупкие селекторы (`fragile`), пометки `frame`,
     `drag`, `file`, `truncated` — что с каждой сделать;
  3. после «да» — правки: в прототипе элементу `id` или `data-*`, в
     `flows.yaml` — устойчивый селектор (п. 3); для `frame`, `drag`, `file` —
     параметр адреса в прототипе или другой путь к состоянию;
  4. пометки разобранного состояния снять: `--state <приложение> 07
     --clear-issues`;
  5. сборка `node .agents/tools/proto-panel.mjs`, затем гейт.
- **Записанные значения** — что человек ввёл в поля (`fill` → `value`) —
  не меняешь без него: это его сценарий показа.
- Проверка состояния — клик по узлу в панели; без браузера — человек по
  чек-листу README панели.

## 6. Комментарии в работу — маршрут «Правки по комментариям»

Триггер: «внеси правки из комментариев», `/panel <приложение> comments`.

1. Открытые комментарии коротко:

   ```bash
   node .agents/tools/proto-panel.mjs --list <приложение> --open
   ```

   Полный текст — в `proto-panel/comments.md` по номеру (`grep -n "## К-3"`).
2. План правок человеку **одним списком**: что понятно и будет сделано, что
   спорно (нужно решение), что непонятно (нужен вопрос). Непонятный
   комментарий не закрывается догадкой — спроси (process.md §7).
3. Правки экранов — обычным маршрутом: мелкое — сам, крупное — задание
   `screen-builder` и приёмка `screen-reviewer`.
4. По каждому комментарию:

   ```bash
   node .agents/tools/proto-panel.mjs --resolve <приложение> К-3 --status сделан --note "<что и где поменялось>"
   node .agents/tools/proto-panel.mjs --resolve <приложение> К-4 --status отклонён --note "<почему>"
   ```

   `отклонён` — только после ответа человека. Решение пишется в файл строкой
   «Решение», зеркало пересобирается само.
5. Гейт: `node .agents/tools/lessons-cli.mjs gate`.

## 7. Правка экрана при включённой панели

Переименовал или убрал `id` / `data-*`, на которые ссылается сценарий, —
поправь `flows.yaml` в том же заходе и пересобери зеркало. Гейт это ловит
(ПН5 — имя селектора не найдено в странице), но чинить после красного гейта
дороже, чем сразу.

## 8. Выключение

Только по просьбе человека. Есть комментарии — покажи их
(`--list <приложение>`) и получи явное «удалить».

```bash
node .agents/tools/proto-panel.mjs --disable <приложение>           # без комментариев
node .agents/tools/proto-panel.mjs --disable <приложение> --force   # только по прямому решению человека
```
