| З1 | Статусы оформлены компонентом Chip, а не текстом; счётчики — Badge |
| З2 | Сортировка активна максимум у одной колонки, `aria-sort` проставлен. | З8 | Тексты на русском, действия в инфинитиве («Добавить», не «Добавление») |
| З13 | **Выбор, который рантайм ДС ставит по клику, скрипт виджета читает макрозадачей.** В JS виджета нет `Promise.resolve().then` / `queueMicrotask` в обработчике `click`/`keydown`, который читает состояние, поставленное рантаймом ДС на том же событии (`aria-selected` у Tab, `aria-checked` у SegmentControl, `checked` у Checkbox и Switch). При настоящем клике браузер выполняет микрозадачи после каждого слушателя, и слушатель виджета, привязанный раньше рантайма, читает прежнее значение — панель или фильтр отстают на клик. Читать — `setTimeout(fn, 0)` или из цели события. Синтетический клик смоука этого не ловит: проверка — эмуляция настоящего клика или браузер (Л203) |

суждение: З1 З4 З8 · сторожа нет: З13

| К3 | **Скролл и якоря реально работают** — не «по разметке». Скролл-контейнер обязан быть ограничен по высоте (`flex:1; min-height:0; overflow-y:auto`); панель, растянутая на контент (`scrollHeight == clientHeight` у скролл-контейнера), — признак сломанной flex-цепочки |
| К4 | **«Файл ДС изменён» — не по одному mtime.** Дата файла может быть старше/новее сессии без правок (например, запись в навигацию добавлена до начала работ). Сверяй содержимое и контекст задания, прежде чем объявлять блокер «файл ДС тронут» |
| К5 | **Не объявлять «мёртвое» до чтения `*.page.js` страницы.** Кнопки-копирования (`data-copy-target`), контролы конструктора, редлайны часто оживляет page.js страницы (`initCopy`, `initPlayground`). Сначала найди обработчик в page.js — потом вердикт |
| К6 | **Порядок скриптов важен.** Рантаймы (`ds-*.js`) → `page.js` → общий слой (`docs-split.js`). Если общий/страничный скрипт подключён раньше рантайма и читает его состояние в момент события — читает устаревшее. Переключение панелей по `data-`-атрибуту кнопки — норм, по `aria-selected` в клике — подозрительно |
| К14 | **Дефект прошёл мимо сторожа, который обязан был его поймать — сначала проверь, ВИДИТ ли сторож нужные данные.** Правило может существовать, быть верным и не срабатывать, потому что его вход срезан: `ds-lint.js` вырезал `<script>` из разметки, и классы, которые страница рисует своим `*.page.js`, правилу A2 были не видны — так прожил урок Л41 (`.dvd` при неподключённом `Divider.css`). Это отдельный класс: не «правила нет» (К13/Л42) и не «копии разошлись» (Л43), а **«правило есть, вход усечён»** (Л48). Процедурное правило «проверять руками», написанное вместо починки входа, маскирует дефект инструмента и обрекает класс дефектов на повтор |
| К13 | **Заявленное спека-правило подтверждается реализацией в рантайме ДС, а не только наличием в документации/разметке.** Если спека/чит-шит обещают поведение «из коробки» (крестик очистки по значению, свёртка чипов «+N», тултип усечённой подписи, маска даты), а в рантайме ДС (`components/**/<Имя>.js`, `utils/ds-*.js`) реализации нет — это дефект «правило записано, кода нет» (Л42): компонент живёт дефолтным, демо может иллюстрировать несуществующее. Поиск реализации — `grep` по этим файлам на класс/механизм. Также: одно правило не должно иметь несколько владельцев-копий (Л43) — почти одинаковые реализации в двух рантаймах — NEEDS-WORK. Дефект общего механизма чинится в слое, а не точечно в компоненте (Л44) |
