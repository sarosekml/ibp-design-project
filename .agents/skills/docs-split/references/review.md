# Приёмка страниц документации (паттерн `docs-split`)

Читает `screen-reviewer` вместе с `screen-review` и `composition-review`, когда
проверяемая страница — страница документации ДС (`main.page.ds-split`). Пункты
чек-листа (ряд К, в том числе К8–К11) остаются в `screen-review/SKILL.md`;
здесь — как их применять к странице документации и композиция конструктора
(КК1–КК4, раздел ниже).

Ряд **К** (каскад раскатки) проверяет не сенсор, а линтер — правилами ряда `R`
(`ds-lint.js`). Причина в предмете: сенсор принимает экран, страницу
документации он отвергает на каркасных проверках Б1/Б5, и до К-правил дело не
доходит (урок Л71). Чем закрыт каждый пункт — печатает `lessons-cli coverage`,
здесь это не перечисляется.

Страницы документации ДС (организмы/молекулы/атомы), переведённые на паттерн
«сплиттер + табы», проверяются по `screen-review` с учётом особенностей:

- **Механику не перечитывать — прогони `node design-system/tools/ds-check.mjs <страница>`**
  (линтер + структурные проверки + headless-живость; для не-docs-split страниц —
  только линтер). Токены на механикy тратить не надо: она вся в команде.
  Глазами — только суждение (композиция, смысл, контент, отклонения);

- подключения: явные `Splitter.css`, `SegmentControl.css`, `Tab.css`,
  `docs-split.css`; рантаймы `Splitter.js`, `Tab.js`, `docs-split.js`;
  НЕ должно быть `ds-toc.js`, `ds-toc.css`, `pg-kit.js`;
- `main.page` обязан иметь класс `ds-split`; без него общий слой не активируется;
- три таба (Документация/Конструктор/Код) — на едином контейнере `.docs-layout`
  (одинаковая ширина и центрирование); `.constructor-panel`/`.code-panel-wrap`
  в разметке паттерна быть не должно;
- конструктор: бинарные параметры → свитчеры `pg-toggle`, остальные — селекты;
  SegmentControl в конструкторе — блокер (конвенция 29.08.2026);
  **у свитча не должно быть отдельного лейбла сверху** — подпись свитча
  самодостаточна («Показывать тулбар», не «Тулбар» + «Показывать»);
  правило компонента Switch (29.08.2026); ловит правило R9 линтера,
  в том числе в статичном конструкторе без `#pg-controls`;
  **у ButtonGroup тоже нет лейбла сверху** — каждая кнопка называет
  вариант целиком («2 чипа», не «2» под «Количество чипов»); правило
  компонента ButtonGroup (21.09.2026). Лейбл прячет `docs-split.js`,
  а самодостаточность текстов — суждение: читать варианты селектов
  на 2–3 пункта так, будто лейбла нет;
  **подпись свитча статична** — не меняется от положения (К8): свитч
  называет опцию действием в On-состоянии и не переименовывается при
  выключении; словарь `DS_SPLIT_SWITCH_LABELS` — строка или `{ label, on? }`;
  **подпись свитча не пуста, источник подписи — `.lbl`** (К9);
  **в `<style>` нет остатков `.pg__controls { flex-wrap/flex:1 1 … }`** (К10);
  **`.pg__grouphead` следует за своими контролами** (К11);
  **две колонки**: справа (`.toggles`) — свитчи/чекбоксы/радио/слайдеры,
  слева (`.ctl-col`) — селекты/инпуты; только один тип — в левой колонке;
  группы (`.ctl-group`) сохраняются, правила внутри каждой группы;
  слайдер — без `ctl--span` (не на всю ширину);
- вкладка «Код»: исходники статично в `<script type="text/plain" id="src-code-*">`,
  подсветка `tk-*` применена;
- **`src-code-css` сверен с файлом стилей диффом, а не «по наличию блока»** (урок
  Л24): после любой правки `<Имя>.css` компонента `src-code-css` обязан быть
  перегенерирован тулчейном `docs-split.mjs inject <page>` (`--css <путь от корня ДС>` — для страницы без спеки)
  и совпадать с файлом по содержимому (новые правила футера/состояний — в эталоне);
- документ страницы паттерна не прокручивается (`html:has(main.ds-split)
  { overflow: hidden }` в `docs-split.css`), место под скроллбар области
  под табами зарезервировано (`scrollbar-gutter: stable` на `.tabs-body`) —
  ширина не скачет при переключении табов. Своих `html { overflow }` /
  `scrollbar-gutter` на странице быть не должно (урок Л147).

## Композиция конструктора

Проверяется на страницах документации ДС с `main.page.ds-split` (вкладка
«Конструктор»). Механика — в `screen-review` (К8–К11); здесь — только
визуальная композиция колонок конструктора:

| # | Проверка |
|---|---|
| КК1 | **Левая колонка (`.ctl-col`) с равномерными отступами.** Поля не растянуты по высоте (признак остатков `.pg__controls .ctl { flex:1 1 … }` в `<style>`); зазор между полями ровный (gap из docs-split.css). Вертикально растянутые поля с большими промежутками — дефект |
| КК2 | **Свитчи в правой колонке с непустой, читаемой подписью.** Пустой текст у свитча (признак подписи не из `.lbl`) — дефект. Свитчи одной колонки выровнены по левому краю, подписи не переносятся в 2 строки |
| КК3 | **Группировка читается:** заголовок группы (`.pg__grouphead`) стоит над своими контролами, а не стопкой вверху без содержимого; разделитель группы не оторван от группы |
| КК4 | **Баланс колонок не вызывает вопросов.** Не-бинарные селекты и инпуты слева; если справа только один-два свитча, а слева восемь полей — допустимо (механизм раскладки), но зазор/выравнивание не должны выглядеть случайными |

Претензия — с именем страницы и описанием видимого симптома («поле X в
левой колонке растянуто на всю высоту, под ним пусто ~40px»). Номер строки —
по `<style>` или по хелперу page.js, где это задаётся.

Задокументированные отклонения (шард уроков `references/lessons.md` этого скилла:
Л7 — чекбоксы `.cb` и слайдеры в левой колонке, Л6 — нативные segctrl) — не
переоткрывать.
