# Харнес агента-дизайнера IBP — вход

Этот каталог — харнес: роли, команды, скиллы, правила процесса и оснастка
агента, который собирает экраны на дизайн-системе IBP. Он работает только
вместе с этой ДС и этим проектом (решение владельца Р8): где они лежат,
говорит манифест проекта `project.json` уровнем выше. Команды ниже
запускаются из корня проекта.

| Что | Где |
|---|---|
| Правила процесса — читать в начале задачи целиком | `rules/process.md` |
| Роли: ведущая `ai-designer`, `screen-builder`, `screen-reviewer`; `ux-researcher` выключен, пока нет базы знаний | `agents/` |
| Команды `/screen`, `/screen-check`, `/concepts`, `/handoff`, `/resume` | `commands/` |
| Скиллы — пошаговые инструкции, грузятся на своём шаге | `skills/<id>/SKILL.md` |
| Оснастка: сенсор, гейт и журнал уроков, сторожа, генераторы загрузчика ДС и реестра хаба, фикстуры | `tools/` |
| Обзор для человека: как запускать, права, модель | `README.md` |

## Порядок захода

1. Правила процесса `rules/process.md` и правила ДС (`AGENTS.md` дизайн-системы)
   — целиком, в начале задачи.
2. Своя роль из `agents/`; по команде — её сценарий из `commands/`.
3. Скилл — когда работа дошла до его шага; крупная задача начинается со
   сметы контекста (скилл `session-plan`).
4. Заход закрывается одной командой, строка `ВЕРДИКТ:` идёт в отчёт:
   `node .agents/tools/lessons-cli.mjs gate`.
5. Что-то сломалось и починилось — урок; процедура у скилла `lessons`, здесь
   она не пересказывается.

Если инструмент не подхватывает роли, команды и скиллы сам — они берутся
чтением файла отсюда. Адаптер под конкретный CLI лежит в проекте, не здесь:
у opencode это один файл `.opencode/opencode.json`: пути до харнеса, режимы
и права ролей, роль-исполнитель каждой команды.
